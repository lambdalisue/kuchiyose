# 文書の形

[指標](../glossary.md#指標)の定義には「地の文で」「日本語 1,000 字あたり」「1 段落に」
といった言葉が出てくる。この文書は、それらの言葉が何を指すかを 1 か所で決める。

ここで決めておかないと、指標の定義が読めない。指標ごとに決めると、同じ言葉が指標に
よって違うものを指してしまう。[戦略](010-strategy.md#どれも対象が揃っていることを前提にする)は
「測る対象が揃っていること」を求めている。この文書が決めるのは、その揃った先の形である。
集めた文章をこの形に落とす手順は[正規化](030-normalize.md)が決める。

この文書で定義する主な言葉は次のとおりである。

| 言葉 | 意味 | 定義 |
| --- | --- | --- |
| node | 段落・見出し・補足など、文書を組み立てる部品 | [文書は node でできている](#文書は-node-でできている) |
| 地の文 | 書き手が日本語の散文として書いた部分。記号を数える指標はここだけを見る | [地の文](#地の文) |
| 日本語の文字 | ひらがな・カタカナ・漢字。率の分母になる | [日本語の文字](#日本語の文字) |
| 文・文末・段落・節・項目 | 地の文や node をさらに区切った数える単位 | [数える単位](#数える単位) |
| 記法・表記 | 書式の選択と、地の文の中身の選択 | [消えるものと、残るもの](#消えるものと残るもの) |

## ここに無いものは測れない

この文書に挙げた node と単位にあるものだけが数えられる。ここに無いものは、どんな指標を
考えても数えられない。この文書が、測れることの上限を決めている。

そのため、node を 1 つ足すことは、指標を 1 つ足すことよりも重い。node を足すなら、
すべての[取り込み元](../glossary.md#取り込み元)（Markdown や HTML といった文書の書式）で
その node を[意味として認識できる](030-normalize.md#意味で認識する)ようにしなければ
ならない。ある取り込み元でその node を認識できないなら、その取り込み元の文書では、
その node の値は 0 ではなく「測れない」になる。

## 文書は node でできている

文書は node の並びである。node は文書を組み立てる部品で、次の種類がある。子を持つ
node は、中にさらに node を含む。

| node | 子を持つか |
| --- | --- |
| 段落 | 持つ |
| 見出し | 持つ |
| 箇条書き | 項目を持つ |
| 番号リスト | 項目を持つ |
| 引用 | 持つ |
| 補足 | 持つ |
| 警告 | 持つ |
| 折りたたみ | 持つ |
| 脚注 | 持つ |
| 表 | セルを持つ |
| セル | 持つ |
| コードブロック | 持たない |
| 区切り線 | 持たない |
| 画像 | 持たない |
| 強調 | 持つ |
| インラインコード | 持たない |
| リンク | 持つ |

node は記法ではなく意味で決める。書き手が「これは補足である」と示していれば、それを
どの記法で書いたかにかかわらず補足の node になる。たとえば GitHub の `> [!NOTE]` で
書いても、Zenn の `:::message` で書いても、HTML の `<aside>` で書いても同じ補足である。
記法の違いは取り込み元の事情であって、書き手の書きぶりではないからである。

構造について測れることは、この表に挙げたものがすべてである。

## 数える単位

### 地の文

地の文とは、書き手が日本語の散文として書いた部分である。記号を数える指標は、断りが
なければ地の文だけを見る。

地の文に含めるのは、次の node に含まれるテキストである。

- 段落、見出し
- 箇条書きの項目、番号リストの項目
- 引用、補足、警告、折りたたみ、脚注
- 表のセル

次のものは地の文に含めない。

- コードブロックの中身
- インラインコードの中身
- 画像の代替文字
- リンクの参照先（URL）
- 日本語の文字を 1 つも含まない表のセル

コードを外すのは、書き手が日本語で書いた部分ではないからである。外さなければ、コードの
多い記事ほど記号の率が上がる。そうなると、書きぶりではなく題材を測ることになる
（[題材を統制する](010-strategy.md#題材を統制する)）。

日本語を含まないセルを外すのも同じ理由である。比較表に並ぶ `o` `-` `✓` `〇` `×` は、
日本語の散文ではない。これを残すと、表を作る書き手ほど[文字種](metrics/文字種.md)の
記号と英字の割合が上がる。表を作るという選択は[表](metrics/表.md)の指標で測るべきもの
なのに、それが文字種の値に出てしまう。

セルが地の文かどうかは、次の規則で決める。

> セルがひらがな・カタカナ・漢字を 1 つも含まなければ、そのセルは地の文ではない。

この判定では `ー` と `々` を数に入れない。どちらも[日本語の文字](#日本語の文字)には
含まれるが、前の字に付く記号であり、単独では語にならない。さらに `ー` は、比較表で
「該当なし」を表すのに使われることがある。もし `ー` を数に入れると、「該当なし」を `-` で
書く書き手のセルは落ち、`ー` で書く書き手のセルは残る。その差が文字種のカタカナの割合に
出てしまい、外したかったものがそのまま戻ってくる。

この規則では、表記の手がかりを一部捨てることになる。たとえば `１２３` だけのセルは地の文
から落ちるので、[数字の字幅](metrics/数字の字幅.md)はそのセルを見ない。これは受け入れる。
記号だけのセルの字形は表の記法であって散文の書き方ではないし、表の記法と散文の書き方を
決定的に見分ける方法が無いからである。

#### 地の文は 1 本の文字列ではない

地の文は、node ごとに切れた文字列の並びとして扱う。並び順は文書に現れる順である。
すべてを 1 本の文字列に連結はしない。

連結すると、たとえば見出しの末尾と次の段落の先頭が隣り合う。この隣り合いは書き手が
書いたものではなく、文書の構造が作ったものである。これを文字の並びとして数えると、
構造の違いが書きぶりの違いに見えてしまう。

表も 1 本にはしない。セル 1 つが 1 本の文字列である。このために、セルも独立した
[node](#文書は-node-でできている) にしてある。表を 1 本にまとめると、あるセルの末尾と
次のセルの先頭が隣り合い、桁揃えのための空白まで地の文に入る。さらに、
[地の文から落としたセル](#地の文)の跡で、本来は離れていたセルどうしが隣り合ってしまう。

指標ごとの扱いは次のとおりである。

| | node を跨ぐか |
| --- | --- |
| 文字 bigram、品詞 bigram、文節パターン | 跨がない |
| 文の切り出し | 跨がない |
| 率の分母（日本語の文字） | 全部を合計する |

入れ子になった node の文字列は、1 度だけ数える。たとえば段落の中の強調やリンクの中身は、
その段落の文字列の一部として 1 度だけ現れる。強調の node の側で同じ文字列をもう 1 度
数えることはしない。

ただし、入れ子の node そのものは残す。数を数えるためである。記法を取り除くだけで node を
作らないと、[強調](metrics/強調.md)や[コードブロック](metrics/コードブロック.md)の数が
いつまでも 0 になる。エラーにはならないので、実際の文章に当てるまで気付けない。

| | 役割 |
| --- | --- |
| 段落の文字列 | 強調の中身を 1 度だけ含む |
| 強調の node | 数を数えるためにある。文字列は足さない |

親の文字列に子の文字列を足すかどうかは、実装の型で決めておく。親の文字列と子の並び順を
持たない形で子の文字列を後から足すと、文の途中にあった強調が、いつも文字列の末尾に
来てしまうからである。

### 日本語の文字

日本語の文字とは、ひらがな、カタカナ、漢字、および `ー` `々` である。範囲は下の表で
決める。

率の分母はこの文字の数である。「日本語 1,000 字あたり」とは、この文字 1,000 個あたり
いくつか、という意味である。

範囲をここで決めておくのは、書かなければ実装ごとに違う文字が漢字と見なされるからで
ある。そうなると、1,000 字あたりの分母、[除外の下限](100-metrics.md#除外の既定)、
[取り込むか断るかの判定](030-normalize.md#通らないものは断る)が、まとめてずれる。

| | 範囲 |
| --- | --- |
| ひらがな | U+3041〜U+3096、U+309D〜U+309F |
| カタカナ | U+30A1〜U+30FA、U+30FC〜U+30FF、半角カタカナ U+FF66〜U+FF9F、および `々` U+3005。半角カタカナは[表記を潰さない](030-normalize.md#表記を潰さない)ので、正規化のあとにも現れる |
| 漢字 | CJK 統合漢字とその拡張、互換漢字、康熙部首。範囲は下の表のとおり |

漢字は、割り当て済みの区画を 1 つずつ挙げて定める。「U+20000 以降」のような開いた
区間では書かない。開いた区間にすると、まだ文字が割り当てられていない符号位置まで漢字に
なる。すると Unicode が更新されてそこに別の文字が入った日に、分母が知らないうちに
変わってしまう。

| 区画 | 範囲 |
| --- | --- |
| CJK 統合漢字 | U+4E00〜U+9FFF |
| 拡張 A | U+3400〜U+4DBF |
| 拡張 B | U+20000〜U+2A6DF |
| 拡張 C | U+2A700〜U+2B73F |
| 拡張 D | U+2B740〜U+2B81F |
| 拡張 E | U+2B820〜U+2CEAF |
| 拡張 F | U+2CEB0〜U+2EBEF |
| 拡張 G | U+30000〜U+3134F |
| 拡張 H | U+31350〜U+323AF |
| 拡張 I | U+2EBF0〜U+2EE5F |
| 互換漢字 | U+F900〜U+FAFF |
| 互換漢字補助 | U+2F800〜U+2FA1F |
| 拡張 J | U+323B0〜U+3347F |
| 康熙部首 | U+2F00〜U+2FDF |

この表は Unicode 17.0 の区画である。版を明記しておかないと、実装が使う Unicode の版に
よって区画が増減し、同じ文書でも環境ごとに分母が変わる。

区画の中でまだ割り当てのない符号位置も、この表に従って漢字として数える。割り当ての
有無で分けると、Unicode の版が上がるたびに過去の値を測り直すことになるからである。

Unicode の版を上げるときは、この表も一緒に更新する。実装が新しい Unicode を使っていても、
どの区画を漢字とするかはこの表が決める。版は[指紋](200-extract.md#何で測ったかを指紋にする)
（何で測ったかの記録）に出す。版を上げると区画が増え、分母が変わるからである。

次のものは日本語の文字として数えない。

- 英数字
- 約物（`。` `、` `「` `（` など）
- 空白
- 記号

範囲を「Unicode のブロック」で指定してはいけない。かなのブロックの中にも約物が
混ざっているからである。

| 符号位置 | 何か | ブロック |
| --- | --- | --- |
| U+30FB `・` | 約物（[文字種](metrics/文字種.md#数え方)が約物に数えている） | Katakana |
| U+30A0 `゠` | 約物 | Katakana |
| U+3099〜U+309C | 濁点・半濁点。前の字に付く記号 | Hiragana |
| U+FF61〜U+FF65 `｡｢｣､･` | 半角の約物 | 半角カタカナの手前 |

たとえば Katakana ブロックをそのまま使うと `・` が日本語の文字になり、[中黒](metrics/中黒.md)が
分母に入る。すると中黒を多く使う書き手ほど分母が膨らみ、中黒の率が下がる。次の段落で
禁じていること（分母が測る対象と連動すること）が、範囲の指定の仕方だけで起きてしまう。

約物を分母から外すのは、分母が測る対象と連動してはいけないからである。約物を分母に
含めると、読点の多い書き手ほど分母が膨らみ、読点の率が下がる。

繰り返し記号と長音符（`ゝ` `ゞ` `ゟ` `ヽ` `ヾ` `ー` `々`）は日本語の文字として数える。
ただし、[表のセルが地の文かどうかの判定](#地の文)では数に入れない。

### 文

文は、地の文を `。` `！` `？` `!` `?` で区切ったものである。終端記号の直後に閉じ括弧
（`」` `』` `）` `"`）が続く場合は、その括弧までを同じ文に含める。

全角の `！` `？` だけでなく、半角の `!` `?` でも切る。字幅は書き手の選択であり、
[正規化で潰さない](030-normalize.md#表記を潰さない)からである。全角だけで切ると、半角を
使う書き手の文は区切られずに連結される。その結果、文を数えるものがすべて狂う。段落
あたりの文数、1 文だけの段落の割合、文末表現、文を単位にする語の指標がそうである。

次の場所では切らない。

- `…` では切らない。言いさしであって、文の終わりではないからである。
- 括弧の内側の `。` では切らない。引用の中の文を、外側の文として数えないためである。

node の末尾は、終端記号が無くても文の終わりとする。見出しや箇条書きの項目は `。` で
終わらないことが多い。それを 0 文として捨てると、見出しの多い文書ほど文が少ないことに
なり、構造の癖が文の癖に見えてしまう。

切り出した文は捨てない。日本語の文字を 1 つも含まない文も、1 文として数える。たとえば
地の文に混ざった `Rust is fast.` のような英文である。

英文を捨てないのは、[地の文から落とすもの](#地の文)とは理由が違うからである。コード
ブロックや記号だけのセルを落とすのは、それが書き手が日本語で書いた部分ではないから
である。一方、地の文に混ざる英文は、書き手が書いた散文である。これを落とすと、文数・
[段落あたりの文数](metrics/段落あたりの文数.md)・
[1 文だけの段落の割合](metrics/1文だけの段落の割合.md)・[文末表現](metrics/文末表現.md)が
まとめて狂い、英語を挟む書き手ほど文が少ないことになる。

日本語が無いことを理由に node ごと落とすのは、[表のセル](#地の文)だけである。そうした
セルは地の文に入らないので、そもそも文に切られない。

[地の文が含まないもの](#地の文)のうち、コードブロック、インラインコード、画像の代替文字、
リンクの参照先は、これとは別の理由で外れている。日本語かどうかは見ていない。

#### ASCII のピリオドでは切らない

文の終端記号に、ASCII のピリオド `.` は入れない。

`.` で切ると、`0.5` も `v1.2` も `Fig. 1` も文の切れ目になる。日本語の技術記事は版番号や
小数を多く含むので、誤って切る回数のほうが、正しく切る回数より多くなりうる。略語や小数を
見分ける規則は書けるが、決定的に正しい規則は書けない。

その結果、続けて書かれた英文はまとめて 1 文になる。`Rust is fast. Go is simple.` は、
2 文ではなく 1 文として数える。

これは承知のうえの制限である。日本語の散文に英文が 1 つだけ挟まる形が大半なので、
多くの場合は[node の末尾で文が切れる](#文)。そのため実害は小さいと見込んでいる。英文が
続く文書では、文の数が実際より少なく出る。日本語以外が主の文書は
[正規化の段階で断る](030-normalize.md#通らないものは断る)が、この制限は、断られずに
残る文書にも効く。

### 文末

文末表現を見る指標は、文から終端記号を外した末尾を見る。

[文](#文)は終端記号（`。！？!?`）と、それに続く閉じ括弧までを含んでいる。これを含んだまま
照合すると、「かもしれない」で終わる文は実際には「かもしれない。」なので一致しない。
値はいつまでも 0 のままで、エラーにもならない。

| | 何を見るか |
| --- | --- |
| 文 | `ここが違うかもしれない。` |
| 文末 | `ここが違うかもしれない` |

外すのは末尾の終端記号と閉じ括弧だけである。文の途中にある記号は残す。

### 段落

段落の node 1 つが 1 段落である。

箇条書き、番号リスト、引用、コードブロック、表、見出しは段落ではない。これらを段落に
数えると、箇条書きの多い文書ほど「段落が短い」ことになってしまう。

### 節

節は、見出しから、次に現れる同じ深さかそれより浅い見出しの手前までである。見出し自身を
含む。

文書の冒頭に、最初の見出しより前の本文があれば、それも 1 つの節として数える。見出しが
1 つも無い文書は、全体で 1 節である。

### 項目

項目は、箇条書きまたは番号リストの直接の子 1 つである。

入れ子になったリストの子は数えない。入れ子まで数えると、深く入れ子にする書き手ほど
項目が多いことになり、入れ子にする癖と項目数の癖が混ざってしまう。

「入れ子」かどうかは文書全体で見る。数えるのは、ほかのリストの中に入っていないリスト、
つまり最も外側のリストの直接の子だけである。内側のリストは、リストとして数えないだけで
なく、その子も項目として数えない。

| 書いたもの | 項目の数 |
| --- | --- |
| 3 項目の箇条書き | 3 |
| 2 項目の箇条書きで、1 つ目が 4 項目の入れ子を持つ | 2 |

この規則を「各リストの直接の子を数える」と読んではいけない。そう読むと、内側のリストの
子も結局は数に入り、入れ子の癖が項目数に混ざる問題がそのまま戻ってくる。

箇条書きと番号リストで項目の数え方を分けない。どちらを使うかは書き手の選択で、その選択
自体は[番号リストの指標](metrics/番号リスト.md)が測っている。項目の数え方まで分けると、
同じ現象を 2 か所で数えることになる。

### 見出しの深さ

見出しの深さは、文書内で最も浅い見出しを深さ 1 とし、そこからの相対で数える。

絶対の深さ（Markdown の `#` の数や HTML の `<h1>`〜`<h6>`）を使わないのは、記事の
タイトルを見出しとして含めるかどうかが取り込み元によって違うからである。同じ構成の
文書が、取り込み元によって違う深さになってはいけない。

## 消えるものと、残るもの

書式の違いには、記法と表記の 2 種類がある。この 2 つを混同すると、測る価値のあるものを
正規化で捨ててしまう。

| | 何か | どうなるか |
| --- | --- | --- |
| 記法 | 書式の選択 | [正規化で潰す](030-normalize.md#表記を潰さない)。測れない |
| 表記 | 地の文の中身 | 正規化のあとも残る。測る価値が高い |

### 記法は測れない。それでよい

記法とは、たとえば次のような書式の選択である。

- 箇条書きの記号が `-` か `*` か
- 強調が `**` か `__` か
- 見出しが `#` か下線か

入力の書式が混ざっている以上、こうした選択が書き手によるものか、取り込み元によるものかは
区別できない。区別できないものを測れば、書き手ではなく取り込み元を測ることになる。だから
記法は正規化で潰し、測らない。

### 表記は残る。優先して採る理由がある

表記とは、地の文の中で書き手が選んだ字や記号の使い方である。表記は正規化で潰さずに残し、
指標として優先して採る。

理由は先行研究にある。英語の文体表現を凝集型クラスタリングにかけると、上位のクラスタは
アポストロフィの字種、末尾に句読点を打つかどうか、発話中の改行で分かれた
（[Wegmann](../references/wegmann-2022.md)）。意味を持たない表記の選択が、文体表現の
主成分になっている。

人が自分で文章を直すときに手を入れるのも、この層である。em dash を削り、短縮形を足す
（[Post-Editing](../references/post-editing-2026.md)）。

日本語でこれに当たるのは、次のような表記である。

| | 例 |
| --- | --- |
| 三点リーダの字数 | `…` か `……` か |
| 感嘆符・疑問符の字幅 | `！` か `!` か |
| 括弧の種類 | `「」` `『』` `（）` `〈〉` の使い分け |
| 和欧間の空白 | 入れるか入れないか |
| 波ダッシュ | `〜` か `～` か |
| 中黒と読点 | 並列に `・` を使うか `、` を使うか |
| 数字の字幅 | `１` か `1` か |

どれも題材との相関が小さく、書き手の選択がそのまま出る。

ただし、これは取り込み元が表記を正規化していないことが前提である。表記の指標を足す前に、
取り込み元がその表記を潰していないかを確かめる。潰しているなら、測っているのは書き手では
なく取り込み元である。
