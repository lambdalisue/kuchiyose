# 文書の形

指標は「地の文で」「日本語 1,000 字あたり」「1 段落に」といった言葉で書かれる。
<strong>その言葉が何を指すかを、ここで 1 度だけ決める。</strong>

決めなければ指標の定義が読めない。指標ごとに決めれば、同じ言葉が指標によって違うものを
指す。[戦略](010-strategy.md#4-つとも対象が揃っていることを前提にする)が要求した「対象が
揃っていること」の、<strong>揃った先の形</strong>がこれである。そこへ落とす手順は
[正規化](030-normalize.md)が決める。

## ここに無いものは測れない

<strong>この文書が測れることの上限を決めている。</strong> ここで挙げた node と単位にあるものだけが
数えられる。無いものは、どんな指標を思いついても数えられない。

<strong>だから node を足すのは、指標を 1 つ足すのとは重さが違う。</strong> すべての取り込み元でそれ
を[意味として認識できる](030-normalize.md#意味で認識する)ことと対になる。認識できない
取り込み元では、その node は 0 が並ぶのではなく <strong>測れない</strong>。

## 文書は node でできている

| node | 子を持つか |
| --- | --- |
| 段落 | 持つ |
| 見出し | 持つ |
| 箇条書き | 項目を持つ |
| 番号リスト | 項目を持つ |
| 引用 | 持つ |
| 補足 | 持つ |
| 警告 | 持つ |
| 折りたたみ | 持つ |
| 脚注 | 持つ |
| 表 | セルを持つ |
| セル | 持つ |
| コードブロック | 持たない |
| 区切り線 | 持たない |
| 画像 | 持たない |
| 強調 | 持つ |
| インラインコード | 持たない |
| リンク | 持つ |

<strong>node は意味で定める。</strong> 書き手が「これは補足である」と示していれば、記法が何であって
も補足の node になる。記法の違いは取り込み元の事情であって、書きぶりではない。

構造について測れることの全体が、この表である。

## 数える単位

### 地の文

段落、見出し、箇条書きの項目、番号リストの項目、引用、補足、警告、折りたたみ、脚注、
表のセルに含まれるテキスト。

<strong>含まないもの。</strong> コードブロックの中身、インラインコードの中身、画像の代替文字、
リンクの参照先、<strong>日本語の文字を 1 つも含まない表のセル</strong>。

コードを外すのは、書き手が日本語で書いた部分ではないためである。外さなければ、コードの
多い記事ほど記号の率が上がり、<strong>書きぶりではなく題材を測る</strong>ことになる
（[題材を統制する](010-strategy.md#題材を統制する)）。

<strong>同じ理由で、日本語の無いセルを外す。</strong> 比較表の `o` `-` `✓` `〇` `×` は日本語の散文では
ない。残せば、表を作る書き手ほど[文字種](metrics/文字種.md)の記号と英字の割合が上がる——
<strong>表を作るという選択が、[表](metrics/表.md)ではなく文字種に出てしまう。</strong>

> セルが<strong>ひらがな・カタカナ・漢字を 1 つも含まなければ</strong>、そのセルは地の文ではない。

<strong>`ー` `々` は、ここでは数に入れない。</strong>[日本語の文字](#日本語の文字)には入っているが、
どちらも前の字に付く記号であって単独で語にならない。<strong>そして `ー` は比較表の
「該当なし」に使われる。</strong> 数に入れれば、`-` を使う書き手のセルは落ち `ー` を使う書き手の
セルは残り、<strong>その差が文字種のカタカナの割合に出る</strong>——外そうとしたものがそのまま戻る。

<strong>表記の証拠を捨てることは分かっている。</strong> `１２３` だけのセルは落ちるので、
[数字の字幅](metrics/数字の字幅.md)はその分を見ない。<strong>受け入れる</strong>——記号だけのセルの
字形は表の記法であって散文の組み方ではなく、<strong>2 つを決定的に見分ける手立てが無い。</strong>

記号を数える指標は、断りがなければ地の文だけを見る。

#### 地の文は 1 本の文字列ではない

<strong>node ごとに切れた、順序のある文字列の並びである。</strong> 文書に現れる順に並ぶ。

<strong>連結しない。</strong> つなげば、見出しの末尾と次の段落の先頭が隣り合う。<strong>その隣接は書き手が
選んだものではなく、構造が作った産物である。</strong>

<strong>表は 1 本ではない。セル 1 つが 1 本である。</strong> だから[セルも node である](#文書は-node-でできている)。
まとめれば、隣のセルの先頭が前のセルの末尾と隣り合い、<strong>桁揃えの空白まで地の文に入る。</strong>
そして[落としたセル](#地の文)の跡で、離れていたセルどうしが隣り合ってしまう。

| | node を跨ぐか |
| --- | --- |
| 文字 bigram、品詞 bigram、文節パターン | <strong>跨がない</strong> |
| 文の切り出し | <strong>跨がない</strong> |
| 率の分母（日本語の文字） | 全部を合計する |

<strong>入れ子の node は、内側だけを数える。</strong> 強調やリンクの中身は、それを含む段落の文字列の
一部として 1 度だけ現れる。二重に数えない。

<strong>そして入れ子の node は、数えるために残す。</strong> 記法を落とすだけで node を作らないと、
[強調](metrics/強調.md)も[コードブロック](metrics/コードブロック.md)も<strong>永久に 0 になる。</strong>
エラーにならないので、実際の文章に当てるまで気付けない。

| | |
| --- | --- |
| 段落の文字列 | 強調の中身を <strong>1 度だけ</strong>含む |
| 強調の node | <strong>数を数えるためにある。</strong> 文字列を足さない |

<strong>足すか足さないかを型で決める。</strong> 親の文字列と子の並び順を持たない形で子の文字列を
足すと、<strong>文中の強調がつねに末尾に来る。</strong>

### 日本語の文字

ひらがな、カタカナ、漢字、および `ー` `々`。

<strong>範囲を決めておく。</strong> 書かなければ実装ごとに違う文字が漢字になり、
<strong>1,000 字あたりの分母、[除外の下限](100-metrics.md#除外の既定)、
[取り込みの可否](030-normalize.md#通らないものは断る)がまとめてずれる。</strong>

| | 範囲 |
| --- | --- |
| ひらがな | U+3041〜U+3096、U+309D〜U+309F |
| カタカナ | U+30A1〜U+30FA、U+30FC〜U+30FF、<strong>半角カタカナ</strong> U+FF66〜U+FF9F（[潰さない](030-normalize.md#表記を潰さない)以上、来る）、および `々` U+3005 |
| 漢字 | <strong>CJK 統合漢字とその拡張、互換漢字、康熙部首</strong>——下の表に挙げた範囲 |

<strong>漢字は「U+20000 以降」のような開いた区間で書かない。</strong> 開いておくと未割り当ての符号
位置まで漢字になり、<strong>Unicode が更新されて別の文字がそこへ入った日に、分母が黙って
変わる。</strong> 割り当て済みの区画を 1 つずつ挙げる。

| 区画 | 範囲 |
| --- | --- |
| CJK 統合漢字 | U+4E00〜U+9FFF |
| 拡張 A | U+3400〜U+4DBF |
| 拡張 B | U+20000〜U+2A6DF |
| 拡張 C | U+2A700〜U+2B73F |
| 拡張 D | U+2B740〜U+2B81F |
| 拡張 E | U+2B820〜U+2CEAF |
| 拡張 F | U+2CEB0〜U+2EBEF |
| 拡張 G | U+30000〜U+3134F |
| 拡張 H | U+31350〜U+323AF |
| 拡張 I | U+2EBF0〜U+2EE5F |
| 互換漢字 | U+F900〜U+FAFF |
| 互換漢字補助 | U+2F800〜U+2FA1F |
| 拡張 J | U+323B0〜U+3347F |
| 康熙部首 | U+2F00〜U+2FDF |

<strong>この表は Unicode 17.0 の区画である。</strong> 版を書かなければ、実装が使う Unicode の版に
よって区画が増減し、<strong>同じ文書の分母が環境ごとに変わる。</strong>

<strong>区画の中の未割り当ての符号位置も、この表に従って漢字として数える。</strong> 割り当ての有無で
分けると、Unicode の版が上がるたびに過去の値が測り直しになる。

<strong>版を上げるときは、この表と一緒に上げる。</strong> 実装が新しい Unicode を使っても、区画は
この表が決める。<strong>そして版を[指紋](200-extract.md#何で測ったかを指紋にする)に出す</strong>——
上げれば区画が増え、分母が変わるからである。

<strong>数えないもの。</strong> 英数字、約物（`。` `、` `「` `（` など）、空白、記号。

<strong>「ブロック」と書いてはいけない。</strong> かなのブロックの中に約物が混ざっている。

| 符号位置 | 何か | ブロック |
| --- | --- | --- |
| U+30FB `・` | <strong>約物</strong>（[文字種](metrics/文字種.md#数え方)が約物に数えている） | Katakana |
| U+30A0 `゠` | 約物 | Katakana |
| U+3099〜U+309C | 濁点・半濁点。前の字に付く記号 | Hiragana |
| U+FF61〜U+FF65 `｡｢｣､･` | 半角の約物 | 半角カタカナの手前 |

<strong>`・` を入れると[中黒](metrics/中黒.md)が分母に入る。</strong> 中黒の多い書き手ほど分母が膨らみ、
中黒の率が下がる——<strong>下で禁じていることが、範囲の書き方だけで起きる。</strong>

<strong>繰り返し記号と長音符は数える。</strong> `ゝ` `ゞ` `ゟ` `ヽ` `ヾ` `ー` `々`。
ただし[表のセルが地の文かの判定](#地の文)では数に入れない。

率の分母はこれである。「日本語 1,000 字あたり」とは、この文字が 1,000 個あたりいくつか、
という意味になる。

<strong>約物を分母から外すのは、分母が測る対象と連動してはいけないからである。</strong> 含めれば、
読点の多い書き手ほど分母が膨らみ、読点の率が下がる。

### 文

地の文を `。` `！` `？` `!` `?` で切る。閉じ括弧（`」` `』` `）` `"`）が直後に続く場合は、
その括弧までを同じ文に含める。

<strong>半角も切る。</strong> 字幅は[書き手の選択であり、潰さない](030-normalize.md#表記を潰さない)。
全角だけで切れば、半角を使う書き手の文が黙って連結され、<strong>文を数えるものすべてが狂う</strong>
——段落あたりの文数、1 文だけの段落の割合、文末表現、文を単位にする語の指標。

`…` では切らない。言いさしであって文の終わりではない。

括弧の内側の `。` では切らない。引用の中の文を、外側の文として数えないためである。

<strong>node の末尾は、終端記号が無くても文の終わりである。</strong> 見出しや箇条書きの項目は
`。` で終わらないことが多い。0 文として捨てると、<strong>見出しの多い文書ほど文が少ない</strong>ことに
なり、構造の癖が文の癖に化ける。

<strong>切ったあとで文を捨てない。</strong> 日本語の文字を 1 つも含まない文——`Rust is fast.` のような
英文——も 1 文として数える。

捨てないのは、[地の文から落とすもの](#地の文)と理由が違うからである。コードブロックと
記号だけのセルを落とすのは <strong>書き手が日本語で書いた部分ではない</strong>からだが、地の文に混ざる
英文は書き手が書いた散文である。落とせば文数・[段落あたりの文数](metrics/段落あたりの文数.md)・
[1 文だけの段落の割合](metrics/1文だけの段落の割合.md)・[文末表現](metrics/文末表現.md)が
まとめて狂い、<strong>英語を挟む書き手ほど文が少ないことになる。</strong>

<strong>日本語が無いことを理由に node ごと落ちるのは、[表のセル](#地の文)だけである。</strong>
あちらは地の文に入らないので、そもそも文に切られない。

<strong>[地の文が含まないもの](#地の文)——コードブロック、インラインコード、画像の代替文字、
リンクの参照先——は、別の理由で外れている。</strong> 日本語かどうかを見ていない。

#### ASCII のピリオドでは切らない

<strong>上の終端記号に `.` は入っていない。入れない。</strong>

入れれば `0.5` も `v1.2` も `Fig. 1` も文の切れ目になる。<strong>日本語の技術記事は版番号と
小数を多く含む</strong>ので、誤って切れる回数のほうが、正しく切れる回数より多くなりうる。
略語と小数を見分ける規則は書けるが、<strong>決定的に正しくは書けない。</strong>

<strong>結果として、続けて書かれた英文はまとめて 1 文になる。</strong>`Rust is fast. Go is simple.` は
2 文ではなく 1 文である。

<strong>これは承知のうえの制限である。</strong> 日本語の散文に英文が 1 つ挟まる形が大半なので、
[node の末尾で切れる](#文)ことが多く、実害は小さいと見込む。<strong>英文が連なる文書では
文数が実際より少なく出る</strong>——[日本語以外が主なら断る](030-normalize.md#通らないものは断る)
が、その手前にある文書には効く。

### 文末

<strong>文末表現を見る指標は、終端記号を外した末尾を見る。</strong>

文は終端記号（`。！？!?`）と、それに続く閉じ括弧までを含む。<strong>含んだまま照合すれば、
「かもしれない」で終わる文は「かもしれない。」なので一致せず、値が永久に 0 になる。</strong>
エラーにはならない。

| | 何を見るか |
| --- | --- |
| 文 | `ここが違うかもしれない。` |
| <strong>文末</strong> | `ここが違うかもしれない` |

外すのは末尾の終端記号と閉じ括弧だけである。<strong>文中の記号は残す。</strong>

### 段落

段落の node ひとつが 1 段落。

箇条書き、番号リスト、引用、コードブロック、表、見出しは段落ではない。<strong>これらを段落に
数えると、箇条書きの多い文書ほど「段落が短い」ことになる。</strong>

### 節

見出しから、次の同じ深さ以上の見出しまで。見出し自身を含む。

文書の冒頭に見出しより前の本文があれば、それも 1 つの節として数える。見出しが 1 つも
無い文書は、全体で 1 節である。

### 項目

箇条書きまたは番号リストの、直接の子ひとつ。

<strong>入れ子の子は数えない。</strong> 入れ子まで数えると、深く入れ子にする書き手ほど項目が多いこと
になり、入れ子の癖と項目数の癖が混ざる。

<strong>「入れ子」は文書全体で見る。</strong> 数えるのは、ほかのリストの中に入っていないリスト——
最も外側のリストの直接の子だけである。<strong>内側のリストは、それ自体が数えられないだけで
なく、その子も数えない。</strong>

| 書いたもの | 項目の数 |
| --- | --- |
| 3 項目の箇条書き | 3 |
| 2 項目の箇条書きで、1 つ目が 4 項目の入れ子を持つ | <strong>2</strong> |

<strong>「各リストの直接の子」と読んではいけない。</strong> そう読むと入れ子の子が結局数に入り、
上の理由がそのまま戻る。

<strong>箇条書きと番号リストで単位を分けない。</strong> どちらを選ぶかは書き手の選択であって、それ
自体が[別の指標](metrics/番号リスト.md)で測られている。項目の数え方まで分ければ、同じ
現象を 2 か所で数えることになる。

### 見出しの深さ

文書内で最も浅い見出しを深さ 1 とし、そこからの相対で数える。

絶対の深さを使わないのは、記事のタイトルを見出しにするかどうかが取り込み元によって違う
ためである。<strong>同じ構成の文書が、取り込み元によって別の深さになってはいけない。</strong>

## 消えるものと、残るもの

<strong>記法と表記は違う。</strong> 混同すると、測る価値のあるものを正規化で捨てる。

| | 何か | どうなるか |
| --- | --- | --- |
| <strong>記法</strong> | 書式の選択 | [正規化で潰す](030-normalize.md#表記を潰さない)。測れない |
| <strong>表記</strong> | 地の文の中身 | <strong>残る。そして測る価値が高い</strong> |

### 記法は測れない。それでよい

箇条書きの記号が `-` か `*` か、強調が `**` か `__` か、見出しが `#` か下線か。

<strong>入力の形式が混ざっている以上、これらは書き手のものか取り込み元のものか区別がつかない。</strong>
区別がつかないものを測れば、書き手ではなく取り込み元を測る。

### 表記は残る。優先して採る理由がある

英語の文体表現を凝集型クラスタリングにかけると、上位のクラスタが <strong>アポストロフィの字種、
末尾に句読点を打つか、発話中の改行</strong>で分かれた（[Wegmann](../references/wegmann-2022.md)）。
<strong>意味を持たない表記の選択が、文体表現の主成分になっている。</strong>

人が自分で直すときに手を入れるのも、この層である。em dash を削り、短縮形を足す
（[Post-Editing](../references/post-editing-2026.md)）。

日本語で対応するもの。

| | 例 |
| --- | --- |
| 三点リーダの字数 | `…` か `……` か |
| 感嘆符・疑問符の字幅 | `！` か `!` か |
| 括弧の種類 | `「」` `『』` `（）` `〈〉` の使い分け |
| 和欧間の空白 | 入れるか入れないか |
| 波ダッシュ | `〜` か `～` か |
| 中黒と読点 | 並列に `・` を使うか `、` を使うか |
| 数字の字幅 | `１` か `1` か |

<strong>どれも題材と相関しにくく、書き手の選択がそのまま出る。</strong>

<strong>ただし取り込み元が正規化していないことが前提である。</strong> 潰されていないかを、指標を足す
前に確かめる。潰しているなら、測っているのは取り込み元である。
