# kakiburi の戦略

[軸](000-axis.md)に到達するための道筋を決める。何をどう測るか、どう持つかは、それぞれの文書で
決める。

## 何をするか

曖昧な書きぶりを指標に落とし、本人の文章を評価してその人の値と <strong>目盛り</strong> を得て、
<strong>その目盛りで、書かれたものを検めて直す。</strong>

やることを 3 つに分け、順に並べる。

| | すること | どこに書いてあるか |
| --- | --- | --- |
| 1 | <strong>借りた指標</strong>を kakiburi の文書モデルの上で定義する | [指標を決める](100-metrics.md) |
| 2 | 既存の文章を評価して、その人の値と目盛りにする | [評価して、値と目盛りにする](200-extract.md) |
| 3 | 文章を検めて、直す | [検めて、直す](300-revise.md) |

進むにつれて、対象そのものが変わる。曖昧なもの、指標、その人の値、検めた結果。

<strong>文書はもう 2 つある。</strong>[文書の形](020-document.md)と
[入力を正規形にする](030-normalize.md)は、上の 3 つが共通して使うので、順番の中に並ばない。
片方だけ違う語彙で書いたり、違う揃え方をすれば、比べたものに意味が無い。<strong>1 か所に
置いて、そこから呼ぶ。</strong>

<strong>指標を発明しない。</strong> 何が書き手を分けるかは日本語で確かめられている
（[先行研究](../references/README.md#分かったこと測定)）。<strong>kakiburi が
決めるのは数え方だけである。</strong>

### 書かせることはしない

<strong>「その人らしく書かせる」ことはしない。</strong> 文章を作るのは[軸の外](000-axis.md#軸の外)
である。

置かない理由は、<strong>置いても効かないことが測られているから</strong>である。同じ課題で、
書かせる側の工夫を 4 通り比べた結果がある（[Sawant](../references/authorship-gap-2026.md)）。

| 手法 | 本人との一致 |
| --- | --- |
| 何もしない（内容の要約だけ渡す） | 0.484 |
| 手本を見せる | 0.508 |
| 文体プロファイルを渡す | 0.502 |
| 対照例と文体特徴を渡す | 0.494 |

<strong>何をやっても 0.024 しか動かない。しかも 4 つとも「赤の他人どうし」の 0.626 を
下回っている。</strong>

一方、<strong>直す作業には効果が測られている</strong>——本人が LLM の草稿を直すと、自分の文章との
一致が効果量 0.55 上がる（[Post-Editing](../references/post-editing-2026.md)）。そして
特徴を並べて指示すると、手本だけより <strong>悪くなる</strong>
（[Bhandarkar](../references/bhandarkar-2024.md)）。

<strong>効くのは直す側である。</strong> だから kakiburi は直す側だけを持つ。

草稿がどう作られたかは問わない。目的も章立ても文体の指定も、書く人が好きに決めてよい。
<strong>kakiburi はできあがったものを検めて、どこがどう外れているかを返す。</strong>

指標の集合は[通るための 2 条件](000-axis.md#通るには-2-つ要る)の両方を覆う。その人
らしさの指標と、人が書いたものに見えるかの指標（繰り返し、エントロピー、圧縮後の
大きさ）を、同じ集合の中に置く。<strong>片方だけ揃っても通らない。</strong>

### 検めることと直すことは離さない

[検め](300-revise.md) は 2 つのことをする。<strong>検めることと、直す指示を出すこと</strong>である。
同じ値と同じ目盛りを使う。違うものを使えば、指示どおりに直したものが次の周で落ちる。

### 使うときはループになる

<strong>1 回で寄せきる前提は
立たない。</strong> 最先端の手法でも、個人化した出力は赤の他人より遠い。人が手で直しても
LLM 寄りの差は残る。

したがってこの道具の成果物は「寄った文章」ではなく <strong>ループ</strong> である。

<strong>誰かが書く（外）→ 検める → 直す → 検める → ……</strong>

<strong>回数で寄せる。</strong> 1 周を安くすることが、そのまま品質になる。

<strong>入口が外にあることは、弱点ではない。</strong> 草稿を誰がどう作ってもループは同じように
回る。人が全部自分で書いたものを持ちこんでもよい。

## どの順に作るか

<strong>順に作れる。</strong> 指標は借りるので、良いかどうかを測って決める必要がない
（[指標](100-metrics.md)）。書き下せば終わる。

<strong>初回の構築に循環は無い。</strong>

| | 何を必要とするか |
| --- | --- |
| 1 | 先行研究と[文書の形](020-document.md)。<strong>測定を必要としない</strong> |
| 2 | 1 と、本人の文章と、基準 |
| 3 | 2 と、検める対象の文章 |

閾値も循環しない。<strong>幅も天井も床も [評価](200-extract.md) の出力である。</strong>
コーパスから導くのであって、導くために別のものを待つ必要はない。

### 運用に入ると、戻る線が 2 本できる

<strong>1 度作ったら終わりではない。</strong> 回し始めると、後ろが前に返すものが出る。

| 戻る線 | 何が返るか |
| --- | --- |
| <strong>[検め](300-revise.md) → [評価](200-extract.md)</strong> | <strong>指示して動いたか</strong>。[効くかどうかの条件 3](200-extract.md#どの指標が効くかを決める) は、書かせてみるまで分からない |
| <strong>[検め](300-revise.md) → [指標](100-metrics.md)</strong> | <strong>本人の指摘</strong>。数値が通ると言い本人が違うと言うなら、指標を足す（[指標](100-metrics.md#集合が変わるとき)） |

<strong>この 2 本は設計の一部であって、偶発ではない。</strong> 初回に無いだけである。

### それでも骨格を先に通す

順に作れることと、順に完成させてよいことは別である。<strong>細くても端から端まで通してから
太らせる。</strong>

理由は循環ではなく、<strong>この設計が成立するかどうかが端まで通さないと分からない</strong>ことに
ある。確かめたいのは 3 つで、どれも最後まで通さないと出てこない。

| 確かめること | 分かる場所 |
| --- | --- |
| 借りた指標が、我々の文書モデルの上で意味のある値を出すか | [評価](200-extract.md) |
| <strong>天井と床が分離するか</strong> | [評価](200-extract.md) |
| 指摘どおりに直すと、実際に数値が動くか | [検め](300-revise.md) を 2 周 |

<strong>2 つ目が最も危ない。</strong> 分離しなければ、そこから先のすべてが読めない値の上に建つ。
先行研究は日本語ブログで分離を確かめているが、コードブロックや見出しを含む文書では
誰も確かめていない（[指標](100-metrics.md#場面で成立しないことがある)）。

<strong>骨格が通るまで、手で決めた定数を持ちこまない。</strong> 持ちこめば、分離しなかったことが
定数に隠れる。

## 決めておくこと

### 訊かずに測る

書きぶりは本人が意識していない（性質 4）。取り出す手段は、本人への質問ではなく、
書いたものを数えることになる。

同じ理由で、どこまでが普通かも人が決めない。本人が実際に書いたものから取る。

### 訊けるものは訊く

<strong>いちばん紛らわしいのが判断軸である。</strong> 何を良しとし、何を書かないか。その人らしい
文章に要るものなので、取り出したくなる。

<strong>取り出さない。諦めではなく、訊けば答えが返るからである。</strong>

| 訊いたときに | |
| --- | --- |
| 「すべて」と「全て」のどちらを使いますか | 答えられない |
| 何を書かないと決めていますか | 答えられる |

書きぶりが計測でしか取れないのは、無意識の選択の集積だからである。判断軸は意識して
取っている立場なので、本人が言葉にできる。<strong>しかも本人の答えが常に正しく、推定する
必要が無い。</strong>

書く人が判断軸を自分で添えることは禁じない。[軸の外](000-axis.md#軸の外)が決めている
のは <strong>この道具が何を取り出すか</strong> であって、本人が書いた紙を重ねてはいけないとは
言っていない。

### 目盛りを作る

<strong>値そのものには意味が無い。</strong> 0.5 が近いのか遠いのかは、比べる先が無ければ決まらない
（[Sawant](../references/authorship-gap-2026.md)）。

<strong>2 つの端を測る。</strong>

| | 何を測るか | 何が言えるか |
| --- | --- | --- |
| <strong>天井</strong> | <strong>本人の文章どうし</strong> | ここまで来れば本人の揺れの中である |
| <strong>床</strong> | <strong>本人と、LLM の既定出力</strong> | ここを超えなければ何もしていないのと同じ |

床に LLM の既定出力を置くのは、<strong>直したいのがそれだから</strong>である。そして <strong>集めるのでは
なく作れる</strong> ので、素材が手に入らずに止まることがない。

<strong>他人の文章が手に入るなら、床をもう 1 つ足す。</strong> LLM に対する床は「良くなったか」を
言うだけで、「本人のものとして通るか」は言わない。他人に対する床が、通ったかを言う
（[財津・金](../references/zaitsu-2018.md)）。ただし複数の書き手のコーパスが集まるかは
確かめていないので、<strong>無くても成立する設計にする。</strong>

### 届かないときは「判定できない」と言う

2 つの端の間には、どちらとも言えない帯ができる。<strong>そこを無理に判定しない。</strong>

日本語のブログ 100 人で、2 割弱を「判定不能」に逃がすと、残りで感度 100%・特異度
95.1% が出ている（[財津・金](../references/zaitsu-2018.md)）。<strong>分からないと言えることが、
言えるときの正しさを支えている。</strong>

返すのは点数ではなく <strong>3 値</strong>——通る、通らない、判定できない——である。

### 題材を統制する

書きぶりは題材を決めたあとに残る差である（性質 3）。<strong>だがこれは理想である。</strong> 実際には
機能語も文字 n-gram も題材情報を拾う（[Stamatatos](../references/stamatatos-2009.md)）。
題材を統制した課題では、最良の文体表現でも文体より題材を優先する
（[Wegmann](../references/wegmann-2022.md)）。

<strong>減らすことはできても、消しきれない。</strong> 統制しなければ、測っているのは題材である。

2 つを守る。

<strong>比べる 2 つを同じ題材にする。</strong> 基準は同じ場面、できるだけ同じ題材で作る。

<strong>依頼文に「どう書くか」を漏らさない。</strong> 本文の書き出しから依頼文を作ると、書き出しの
癖がそのまま手掛かりになり、基準値が <strong>28 ポイント</strong>膨らむ
（[Sawant](../references/authorship-gap-2026.md)）。依頼文は「何について書くか」の中立な
要約にする。

### 場面ごとに閉じる

書きぶりは場面ごとにある（軸）。評価も、照らすのも、1 つの場面の中で閉じる。
混ぜたものは、どの場面のものでもない。

<strong>場面の寄与は人の寄与と同じ大きさである</strong>（[水上ほか](../references/mizukami-2014.md)）。
閉じないことは、精度が少し落ちることではなく、<strong>測っているものの半分が場面になる</strong>
ことである。

場面は人が指定する。相手も立ち位置も目的も文章の外にあるので、文章から当てにいけば
外す。

### 数える側に LLM を置かない

同じ入力からは同じ結果を出す。<strong>決定性は好みではなく、成立条件である。</strong>

LLM を数える側に置くと 2 つのことが起きる。

<strong>物差しが動く。</strong> 同じ人から 2 回特徴を抽出して、一致は <strong>Jaccard 0.22</strong>。測るたびに
目盛りが変わる。

<strong>循環する。</strong> LLM に特徴を挙げさせ、LLM に採点させると、<strong>本人の文章（0.427）より
個人化した生成文（0.542）の方が高く出る</strong>。測っているのは指示に従えたかであって、
その人らしさではない（[Sawant](../references/authorship-gap-2026.md)）。

<strong>この 2 つ目は、そのまま検査に使える。</strong> 本人の実際の文章を採点して、生成文より低く
出る指標は壊れている。安く、決定的で、強い。

### 本人の読みは、判定ではなく候補として使う

<strong>本人には判定できない。</strong> 81 人が LLM の草稿を自分らしく直した実験で、本人は直した
文章を自分で書いたものと同じくらい自分らしいと評価した。測ると LLM 寄りの差が効果量
1.43 残っていた（[Post-Editing](../references/post-editing-2026.md)）。

<strong>したがって「本人が受け入れた」は、寄ったことの証拠にならない。</strong>

だが読ませる価値はある。<strong>本人に見えるものと見えないものが分かっている。</strong>

| | |
| --- | --- |
| 見える | <strong>表層の異物</strong>。特定の記号、特定の語、飾りの多さ |
| 見えない | <strong>分布</strong>。頻度、揺れ、組み立ての癖 |

見えるものは、その場で直せばよい。<strong>見えないものは数値でしか捕まらない。</strong>

そして <strong>本人が違うと感じたときは、依然として信号である</strong>。前身では、本人が読んで拒否
した文章が満点を取ったことがある。数値が取りこぼしている何かがそこにある。

<strong>食い違いは両方向に起きる。</strong>

| 数値 | 本人 | 意味 |
| --- | --- | --- |
| 通る | 違うと言う | <strong>指標が足りない。</strong>[指標](100-metrics.md) に戻る入口 |
| 通らない | 気付かない | <strong>正常。</strong> 本人には見えない層を数値が捕まえている |

<strong>2 行目を「数値が神経質すぎる」と読んではいけない。</strong> それが数値を置いている理由で
ある。
