# kuchiyose の戦略

[軸](000-axis.md)の 1 行「その人の代わりに書けるようにする」へたどり着く道筋を決める。
大半は、検める部分の軸「どこがその人と違うかを、言えるようにする」についての決定である。
書かせる部分がどこまでを受け持つかは[下](#書かせるのは-llm道具はプロンプトまで)で決め、
中身は[代筆する](400-write.md)が決める。

この文書が決めるのは、何が要るか、どの順に作るか、どこで間違えやすいか、である。
個々の数え方や値の持ち方は、この先の文書が決める。言葉の意味は[用語集](../glossary.md)に
ある。

## 味が出るには 2 つ要る

軸の出発点は、代筆させた文章に[その人の味が出ている](000-axis.md#やりたいこと)ように
することだった。これは次の 2 つの条件に分かれ、両方を満たして初めて味が出る。

| 条件 | 何を言うか |
| --- | --- |
| その人の書きぶりが出ている | 語の選び方・読点の打ち方・文末が、その人の書き方に近づいているか |
| 基準の書きぶりが残っていない | 同じものを毎回違う語で言う、といった読みづらさが消えているか |

2 つ目の条件は、1 つ目を満たしても自動的には満たされない。語や読点の分布がその人に
近づいていても、その人が一度も書かなかった濃さで同じ言い回しが並ぶことがある。
その人に寄せる方向の直しだけでは、この種の読みづらさは残る。

実測の例：本人が 42 本の記事で合わせて 34 回しか使わない言い回しが、直した 1 本の中に
14 回入った。

2 つ目の条件は「機械が書いたと見破られないこと」とは別である。見破られないことを
目指すなら「機械と判定されない」ところまで行けば足りる。こちらの目的は、読みづらさの
元を取り除いて、その人の書きぶりが入る余地を空けることである。測るものは近いが、
目的が違う。

2 つ目の条件は、本人と[基準](../glossary.md#基準)を、繰り返し・語彙の狭さ・エントロピー・
圧縮率・句読点の密度のような、誰の文章にも使える次元で分けて測る。これを
[基準との距離](../glossary.md#基準との距離)と呼ぶ。既定の基準は LLM が素で書いた文章なので、
既定のままなら「機械の書きぶりが残っていないか」を見ることになる。人の文章と機械の文章が
古典的な計量文体論の特徴で分かれることは確かめられている
（[Przystalski ほか](../references/przystalski-2025.md)）ので、読みづらさの元が残っている
度合いの代わりに使える。ただしこれは代理であり、読みやすさそのものを測ってはいない。
機械かどうかを判定しているのでもない。

基準に別の人の文章を置けば、2 つ目の条件は「その人の書きぶりが残っていないか」になる。
条件の中身は、何を基準に置いたかで決まる。

道具は両方の条件について言えるようにする。片方だけ揃っても味は出ないので、片方だけを
測る道具は役に立たない。

## 言うために何が要るか

「言えた」状態とは、次のように言えることである。

> この文章は、その人と比べて、ここが、こちらへ、これだけ違う。

これを言うには次のものがすべて要る。どれか 1 つでも欠ければ言えない。

| | 要るもの | 欠けると | どこが作るか |
| --- | --- | --- | --- |
| 1 | 違いを載せる量（[指標](../glossary.md#指標)） | 「なんとなく違う」で終わる | [指標](100-metrics.md) |
| 2 | その人の側の値 | 「違う」と言う相手がいない | [評価](200-extract.md) |
| 3 | 値を読む[目盛り](../glossary.md#目盛り) | 0.5 が近いのか遠いのか決まらない | [評価](200-extract.md) |
| 4 | 直す側が受け取れる形 | 言ったことにならない | [検め](300-revise.md) |

目盛り（3）がその人の値（2）と同じ文書で決まるのは、同じ材料から作れるからである。
目盛りは別に集めてくるものではなく、本人の文章と[基準](../glossary.md#基準)（既定では、
広く散らした題材を LLM に素で書かせた文章から、本人と題材の近い分を選んだもの）を測れば出る。

### どれも、対象が揃っていることを前提にする

素材の取り込み元はばらばらである。Markdown にも方言があり、HTML もある。同じ「補足」が、
ある場所では引用の記法で、別の場所では専用の記法で書かれる。

これを揃えずに測ると、測った差は書き手の差ではなく取り込み元の差になる。

そこで[文書の形](020-document.md)と[正規化](030-normalize.md)は、[指標](100-metrics.md)・
[評価](200-extract.md)・[検め](300-revise.md)のどれか 1 つに持たせず、全部が同じものを
使う。どれか 1 つだけ揃え方が違えば、比べた結果に意味が無くなる。

## 何を扱うか

扱うのは、ある人の、ある[場面](../glossary.md#場面)での、書きぶりの違いだけである。
場面とは、技術記事や社内向けの報告のような、書く状況の区別である（詳しくは
[下](#書きぶりとは何か)）。

軸は「どこが違うか」としか言っておらず、違いのうちどれを扱うかは軸からは決まらない。
ここで決める。

上の条件のうち 1 つ目がこの「書きぶりの違い」にあたる。2 つ目（基準の書きぶりが
残っていないか）はその人との違いではないが、同じ指標の集合に入れて扱う
（[指標](100-metrics.md#味が出るための-2-条件を両方覆う)）。

書きぶりに絞るのは選択である。違いを言うだけなら、内容の選び方や判断の下し方も対象に
なりえた。書きぶりに絞る理由は、書きぶりだけが本人に訊かずに文章から取れて、しかも
同じ人の中で安定するからである。

### 書きぶりとは何か

書きぶりとは、題材と場面を決めたあとに、なお人によって違ってしまう部分である。
場面とは、誰に向けて、どういう立ち位置で、何のために書くかを指す。同じ題材を同じ場面で
10 人が書けば 10 通りの文章になる。その差が書きぶりである。

書きぶりは次の性質をすべて持つ。1 つでも欠けるものは書きぶりとして扱わない。

| | 性質 | どこから来たか |
| --- | --- | --- |
| 1 | 人によって違いうる | 個人差（[財津・金](../references/zaitsu-2018.md)） |
| 2 | 同じ場面で書いたものに一貫して現れる | 個人内恒常性（同） |
| 3 | 題材が変わっても変わらない | 機能語は題材に依存しない（[Stamatatos](../references/stamatatos-2009.md)） |
| 4 | 必要な形（分布）では、文章からしか取れない | 機能語は無意識に使われる（同） |
| 5 | 文章に現れる | この分野が一貫して文章を対象にしてきた |

土台は性質 1 と 2 である。これは書き手を識別できるための条件そのもので、
[財津・金](../references/zaitsu-2018.md)が名指ししている。

> 各個人によって表出される文体的特徴に「個人差」と「個人内恒常性」が存在することから
> 筆者の識別が可能となる

性質 3 から 5 は、1 と 2 をどこまで信じてよいかを限定する。3 は恒常性が題材の違いに
対しても成り立つことを求める。4 は、取り出す手段が質問ではなく計測になる理由である。
5 は、何を対象にするかの線引きである。

性質 4 は「無意識である」という意味ではない。[Stamatatos](../references/stamatatos-2009.md)が
無意識だと言っているのは機能語についてであり、
[表記の選択](020-document.md#表記は残る優先して採る理由がある)まで無意識だという裏付けは
無い。括弧をどちらで括るかは、訊けば答えられることがある。

それでも表記の選択を書きぶりに入れるのは、必要なのが分布だからである。要るのは
「だいたい `「」` を使う」という答えではなく、どの割合でどこに使うかという値、つまり
[幅](200-extract.md#値は幅で持つ)（本人が実際に取った値の範囲）を作れる形の値である。
その形の値は文章からしか取れない。

本人の自己申告がどれだけ正確かは確かめていない。正確に言える書き手もいるかもしれないが、
書き手ごとにそれを確かめる手立てが無いので、全員について文章から測る。

このことは、後で決める[訊けるものは訊く](#訊けるものは訊く)と衝突しない。あちらで訊くのは
判断軸（何を良しとし、何を書かないか）であって、書きぶりではない。[場面](#場面ごとに閉じる)と
[題材](#題材を統制する)も人が指定するが、それは書きぶりを揃えて比べるための前提である。
どれも書きぶりそのものではない。

### 境界が紛らわしい 2 つ

性質 1 について：誰が書いても同じになるものは書きぶりから外れる。たとえば「文頭の
接続詞の後に読点を打つ」は性質 2 から 5 をすべて満たすが、公用文の手引きに書かれている
常識であり、人によって違わない。読点という 1 つの現象の中に、誰もが打つ層と、人によって
違う層が混ざっている（石黒 2011、[岩崎](../references/japanese-attribution-others.md)）。
そのため[規範の層を分ける](#規範の層を分ける)。

性質 2 について：場面が変われば一貫性は成り立たない。場面が文章に与える影響は、人が与える
影響と同じくらい大きい（[水上ほか](../references/mizukami-2014.md)。ただし話し言葉での
測定であり、書き言葉で再現するかは確かめられていない）。だから性質 2 は「同じ場面で」と
限定している。場面を分けるのは媒体ではない。同じチャットでも、チームへの報告と社外への
連絡は別の場面になる。そのため[場面ごとに閉じる](#場面ごとに閉じる)。

### 数えない違い

次の違いは、あっても書きぶりの違いとしては数えない。どれも上の性質のどれかを満たさない。

| 違い | なぜ数えないか |
| --- | --- |
| 題材が違う | 書くたびに変わる。性質 2 と 3 を満たさない |
| 場面が違う | 扱う前に決めておく前提である。違いとして出すと、人の違いと混ざる |
| 文章の出来が違う | 性質 1 を満たさない。出来は読む側が決めるものである |
| 文法が誤っている | 性質 1 を満たさない。違っていればそれは単に誤りである |
| 規範に従っているかどうか | 性質 1 を満たさない。誰を測っても同じ値になる（[規範の層](#規範の層を分ける)の表の 1 行目） |
| 考えかた・判断軸が違う | 性質 4 を満たさない。本人が言葉にできる（[訊けるものは訊く](#訊けるものは訊く)） |
| 場面をまたいだ書き分けの度合いが違う | 性質 2 を満たさない |

### 日本語だけ

扱う言語は日本語だけにする。

特徴量は言語ごとに違い、既製の特徴量セットも日本語向けの資源も、それぞれ別の言語を前提に
作られている（[Writeprints](../references/writeprints-liwc.md)）。複数の言語を同時に
扱おうとすると、どちらかに合わない特徴量を持ち込むことになるので、1 つの言語に合わせる。

## 量を決めるときの決定

[言うために何が要るか](#言うために何が要るか)の表の 1（違いを載せる量）についての決定である。
詳細は[指標](100-metrics.md)が決める。

### 指標を発明しない

指標は先行研究で確かめられたものを使い、自前では考え出さない。kuchiyose が決めるのは
数え方だけである。

理由は、何が書き手を分けるかが日本語ですでに確かめられているからである
（[先行研究](../references/README.md#分かったこと測定)）。日本語ブログ 2,287 人で
EER 9.3% を出した特徴の組み合わせがあり（[尤度比](../references/fusing-lr-2026.md)）、
独立した研究も同じ顔ぶれにたどり着いている（[金 2014](../references/jin-2014.md)）。
自前で候補を思いつき、実験し、採否を決める手続きを持っても、確かめられていることを
確かめ直すだけになる。

特徴の選抜もしない。特徴は頻度で選ぶ。判別力の高いものを選び抜くのは話題分類の作法であり、
そうして選ばれた特徴は使ったコーパスに依存してしまう
（[Stamatatos §2.6](../references/stamatatos-2009.md)）。

### 種類の違うものを混ぜる。ただし 5 系統前後まで

判定には種類の違う特徴を組み合わせて使う。ただし一度に突き合わせる[系統](../glossary.md#系統)
（文字 bigram のような、多数の次元をまとめて見る指標）の数は 5 を上限とする。

組み合わせると識別の精度が上がり、特に種類の違う特徴をまたいで組み合わせると大きく
上がる。次の表は[尤度比](../references/fusing-lr-2026.md)の結果である。Cllr は 0 が最良、
1 が偶然と同じである。

| 組み合わせ | Cllr（0 が最良、1 が偶然） |
| --- | --- |
| 文字 bigram 単独 | 0.47115 |
| 単語埋め込み単独 | 0.38757 |
| 同じ種類どうし——計量文体論 3 つ | 0.43964 |
| 同じ種類どうし——埋め込み 2 つ | 0.36186 |
| 種類をまたぐ——文字 bigram + 単語埋め込み | 0.34603 |
| 最良（5 系統） | 0.32484 |
| 6 系統 | 0.32579 |
| 全 7 系統 | 0.32855 |

同じ種類どうしを重ねても少しは良くなる。しかし種類をまたげば 2 つだけで、同じ種類を
3 つ重ねたものを上回る。

一方、3 系統から 7 系統までの結果はほぼ横ばいである。論文はこれを、残りの系統は矛盾は
しないが新しい情報を大して足していない、と解釈している。EER で見た最良はむしろ 4 系統
（0.09273）である。

したがって「5」という数そのものに根拠は無い。根拠があるのは、ある数を超えると足しても
良くならない、という事実だけである。上限を 5 に置いたのは我々の判断で、横ばいの区間の
真ん中を取り、測る手間を抑えた。4 でも 6 でも、報告された差はほとんど無い。

この上限は、判定のときに突き合わせる系統の数に対するものである。持っておく指標の集合を
5 つに絞る話ではない（[指標](100-metrics.md#集合は広く持つ絞るのはあとである)）。
どの系統を判定に使うかは[評価](200-extract.md#判定に使う系統を選ぶ)が決める。

### 単独で弱いことは、落とす理由にならない

単独で成績の悪い特徴でも、それだけを理由に集合から外さない。単独での順位は、組み合わせた
ときにどれだけ役立つかを予測しないからである。

例として、文節パターンは単独では F1 0.704 で最下位なのに、最良の組み合わせには必ず
入っている（[統合アンサンブル](../references/japanese-attribution-recent.md)）。逆に、
機能語 unigram は単独では 7 系統中 5 位（0.63002）でありながら、最良の組み合わせから
外れた例がある（[尤度比](../references/fusing-lr-2026.md)）。

### 規範の層を分ける

1 つの現象の中に、誰もがやることと、人によって違うことが混ざっている。これを 1 つの
数字にまとめずに、層ごとに分けて数える。

| 層 | 何が決めるか | 個人差 |
| --- | --- | --- |
| 誰もが打つ | 意味・長さ・構造 | 出ない |
| 人により異なる | 表記・音調・リズム | 出る |
| 一部の人が打つ | 強調 | 出る |

（読点について、石黒 2011 を[岩崎](../references/japanese-attribution-others.md)が引用）

たとえば読点を「読点の密度」という 1 つの数字にすると、3 つの層が混ざり、個人差の出る
層が、誰でも同じになる規範の層に薄められてしまう。粗いほうへ丸めない。<strong>これが数え方の
中でいちばん効く判断である。</strong>

この決まりは、書き手どうしを見分ける指標に掛かる。人らしさの指標にある
[句読点の密度](metrics/句読点の密度.md)は粗い密度だが、それでよい。この指標が問うのは、
本人と基準が誰の文章にも使える次元で分かれるかであって、規範の層に埋もれた個人差を
取り出すことではない（[指標](100-metrics.md#粗い括りに丸めない)）。

## どう数えるかの決定

### 判定できるのは数値だけである

本人の文章に近いかどうかの判定は、決定的で解釈できる数値だけで行う。これは
[軸](000-axis.md#なぜ道具が要るのか)が道具を必要とした根拠であり、以下の決定の前提でもある。

人や LLM に判定させた場合、次のように崩れる。

| 誰が言うか | 何が起きるか |
| --- | --- |
| 本人 | 直した文章を自分の文章と区別できない（g = 1.43 の差が残っていた） |
| 他人 | 文体についての判断が一致しない（評価者間 0.641、推敲は 0.400） |
| LLM に判定させる | 判定が循環する。生成文（0.542）が本人の文章（0.427）より高く出る |
| LLM に特徴を挙げさせる | 同じ人から 2 回抽出して一致しない（Jaccard 0.22） |

（[根拠](../references/README.md#分かったこと評価)）

残るのが数値である。決定的（同じ入力に同じ値を返す）でなければ物差しにならず、解釈
できなければ「どこが」違うかを言えない。

### 数える側に LLM を置かない

数える処理には LLM を使わない。同じ入力からは必ず同じ結果を出す。決定性は好みではなく、
物差しとして成り立つための条件である。これは上の表の 3 行目と 4 行目から直接出る。

表の 3 行目の循環（LLM が生成文を本人の文章より高く採点すること）は、指標の検査にも使える。
本人が実際に書いた文章を採点して、生成文より低い値が出る指標は壊れている。そういう指標が
測っているのは著者性ではなく、指示にどれだけ従ったかである
（[Sawant](../references/authorship-gap-2026.md)）。この検査は安く、決定的で、判別力も強い。

### 訊かずに測る

書きぶりは、本人に質問するのではなく、書いたものを数えて取り出す。書きぶりは必要な形
（分布）では文章からしか取れないからである（[性質 4](#書きぶりとは何か)）。

同じ理由で、どこまでが普通の範囲かも人が決めず、本人が実際に書いたものから取る。

### 訊けるものは訊く

判断軸（何を良しとし、何を書かないか）は文章から取り出さない。必要なら書く人に訊く。

判断軸は書きぶりといちばん紛らわしい。その人らしい文章に要るものなので、取り出したく
なる。しかし取り出さないのは諦めたからではなく、訊けば答えが返るからである。

| 訊いたときに | |
| --- | --- |
| 「すべて」と「全て」のどちらを使いますか | 答えられない |
| 何を書かないと決めていますか | 答えられる |

書きぶりが計測でしか取れないのは、必要なのが分布だからである（[性質 4](#書きぶりとは何か)）。
判断軸はそうではない。訊けば答えが返り、しかも本人の答えが常に正しい。推定する必要の
無いものは推定しない。

判断軸の置き場は[ペルソナ](400-write.md#ペルソナ)である。LLM の道具に記事を読ませて下書きを
作らせ、本人が読んで直す。下書きを LLM に任せるのは、白紙から書くより直すほうが本人に
安いからで、答えを決めるのは直す本人である。項目ごとに記事からの引用を付けさせ、引用が
実在するかだけを道具が確かめる。ペルソナは代筆のプロンプトにだけ使い、測った値にも判定
にも入れない。検める部分が判断軸を測らないことは変わらない。

## 値を作るときの決定

[言うために何が要るか](#言うために何が要るか)の表の 2（その人の側の値）についての決定である。
詳細は[評価](200-extract.md)が決める。

### 場面ごとに閉じる

値を作るのも、草稿をそれに照らすのも、1 つの場面の中だけで行う。場面をまたいだ素材は
混ぜない。個人内恒常性は場面の中でしか成り立たないからである（[性質 2](#境界が紛らわしい-2-つ)）。

混ぜた場合の影響は、精度が少し落ちる程度では済まない。クロスエントロピーで測ると、同じ人
でも役割が変われば +0.77、違う人でも役割が同じなら +0.85 で、ほぼ同じ大きさである
（[水上ほか](../references/mizukami-2014.md)）。場面を混ぜれば、測っているものの半分が
場面の差になる。ただしこの実験の対象は話し言葉であり、書き言葉で再現するかは確かめられて
いない。

場面は人が指定する。読み手も立ち位置も目的も文章の外にあるので、文章から推定すれば外す。

閉じる単位は入れ物で表す。1 つの[形代](../glossary.md#形代)は 1 つのフォルダから
作り、1 つの場面の名前を持つ。フォルダの中で場面を混ぜなければ、場面をまたいだ統計値は
できない。場面の指定は本人の形代を選ぶことで行い、引数では渡さない。

どの形代を基準と組み合わせるかは、使う人に任せる。場面の名前は名札であって、道具は
名前の食い違いで断らない。その代わり、判定には本人と基準の両方の場面の名前を並べて出す。
組み合わせが合っているかは、人が見て決める。

> 経緯：以前は 1 つの入れ物に複数の場面を持たせていた。場面をまたいで使ってよい素材を
> 扱うためだったが、その素材は一度も入らなかった。残ったのは、検めるたびに場面を指定し直す
> 手間と、場面をまたいだ目盛りを作れてしまう経路だけだったので、やめた。

例外は置かない。その場面の文章が集まっていないときは、近い場面の文章で代用せず、判定を
断る（[検め](300-revise.md#当てにならないときは言う)）。

場面をまたいで使える特徴が見つかれば、この制限を緩める余地はある。しかし今は緩めない。
場面をまたいでも一貫すると確かめられているのは品詞 unigram と読点の打ち方で、文字・記号の
unigram と文節パターンは場面によって大きく動く（[柳・金 2022](../references/yanagi-jin-2022.md)）。
このうち品詞 unigram は指標の集合に入っていない。残る読点の打ち方 1 つだけでは
[照合値](../glossary.md#照合値)（草稿が本人の書いたものに見えるかを表す数）を
[作れない](200-extract.md#判定に使う系統を選ぶ)。

品詞 unigram を集合に足せば、緩める道が開く。実際に緩めるかどうかは、その 2 つだけで
下す判定に意味があるかを測ってから決める。同じ論文の中でも、実験によって順位が入れ
替わっているからである。

### 題材を統制する

本人の文章と、比べるときに使う基準の文章の題材を揃える。揃えなければ、測っているのは
書きぶりではなく題材の違いになる。

書きぶりは題材を決めたあとに残る差である（[性質 3](#書きぶりとは何か)）。ただしこれは
理想であり、実際には機能語も文字 n-gram も題材の情報を拾ってしまう
（[Stamatatos §5](../references/stamatatos-2009.md)）。

この影響には数値がある（[Wegmann](../references/wegmann-2022.md)）。題材を統制せずに
訓練した文体表現は、訓練と同じ条件では AUC .79 を出すが、題材を揃えたテストでは .58 まで
落ちる。つまりその .79 は文体ではなく題材を当てた精度だった。会話で統制して訓練すれば
3 条件とも .69〜.71 で安定するが、文体と題材のどちらを選ぶかを問う課題では最良でも 0.42 で、
無作為の 0.50 を下回る。

題材の影響は減らせても消しきれない。そこで次の規則を守る。

題材は、比べるときに選んで揃える。基準は、その種類の文章が扱う領域に題材を広く散らして
作っておき、組み立てのたびに本人の素材と[題材の近い分を選ぶ](200-extract.md#基準の文書は文体が同じで題材の近い分だけを使う)。
基準を本人の題材で書く必要は無い。揃えるのはコーパス全体として、本人側と基準側で題材の
散らばり方が系統的にずれないことであり、1 本ずつの対で揃えることはしない
（[理由](200-extract.md#題材の統制は対ではなく素材に効かせる)）。

こうするのは、基準が機械の書き方であって書き手ごとに変わらないからである。本人の題材から
作った基準はその人にしか合わず、人ごとに作り直すことになる。実測でも、本人の題材から
取っていない同梱の基準で、本人の記事を「通らない」と言うことは無く、機械の草稿のすり抜けは
104 回中 3 回だった（[実測](000-axis.md#本人の記事)）。すり抜けたうち 2 回は、本人の記事と
同じ題材で書かせた草稿である。選ぶ手順は題材より文書の長さをよく拾っていて、重なりの数は
語彙の大きさとほぼ比例する（r = 0.93。[選び方](200-extract.md#基準の文書は文体が同じで題材の近い分だけを使う)）。
基準の側で効いているのは、題材を合わせることより文体を合わせることである。

基準の文書には、その題材で名指しする物（製品名、コマンド名、版番号など）を含める。題名
だけを渡すと足りない。「Vim のファイラー系プラグインについて書け」と言われた LLM は、
プラグイン名もコマンド名も版番号もほとんど書かないが、人の技術記事はそれらで埋まっている。
その結果、基準の側だけラテン文字と ASCII 記号が薄くなる。名指しする物は「何について
書くか」の側に属するので、伏せれば題材を選んでも揃わない。

実測では、この差だけで[天井](../glossary.md#天井)（本人の文章どうしの照合値の範囲）と
[床](../glossary.md#床)（基準の照合値の範囲）が分離した。[文字種](metrics/文字種.md)を
日本語の 3 種に絞ると、分離したのは 10 通り中 3 通りに減った。

依頼文に「どう書くか」を漏らさない。本人の本文の書き出しから依頼文を作ると、書き出しの癖が
そのまま手掛かりになり、基準値が 28 ポイント膨らむ
（[Sawant](../references/authorship-gap-2026.md)）。依頼文は「何について書くか」を中立に
要約したものにする。

名指しする物を渡すときも、その表記は写さない。上の規則は物の名前を渡せと言っているが、
名前の書き方まで渡すと書きぶりが漏れる。「Vim script」と書くか「Vim スクリプト」と書くか、
版番号を半角で書くか全角で書くか、括弧をどちらで括るか。これらは
[和欧間スペース欠落](metrics/和欧間スペース欠落.md)や[数字の字幅](metrics/数字の字幅.md)が
測っている書きぶりの層である。要約は人が書くので、この規則は人が守る。

## 目盛りを作るときの決定

[言うために何が要るか](#言うために何が要るか)の表の 3（値を読む目盛り）についての決定である。
詳細は[評価](200-extract.md#目盛りを作る)が決める。

### 天井と床を測る

目盛りとして、天井と床という 2 つの端を測る。

値そのものには意味が無いからである。0.5 が近いのか遠いのかは、比べる先が無ければ決まらない
（[Sawant](../references/authorship-gap-2026.md)）。

| | 何を測るか | 何が言えるか |
| --- | --- | --- |
| 天井 | 本人の文章どうし | ここまで来れば本人の揺れの中である |
| 床 | 本人と、基準の文章 | ここを超えなければ基準と変わらない |

床は基準の形代で決まる。既定の基準は LLM の既定出力である。直したい対象がまさにそれ
だからで、既定出力は集めてくるのではなく作れるので、素材が手に入らずに止まることもない。

基準には別の人の形代も渡せる。LLM に対する床が言えるのは「良くなったか」までで、
「その人の味が出ているか」までは言わない。他人に対する床がそれに近づく
（[財津・金](../references/zaitsu-2018.md)）。道具は基準が機械か人かを区別しないので、他人を
床に置くのに別の仕組みは要らない（[評価](200-extract.md#他人と比べるなら他人の形代を基準に渡す)）。

返す言葉は、何を床に置いたかで変わる。

| 基準 | 通ったときに言えること |
| --- | --- |
| 同梱の基準（既定） | LLM の既定出力より本人の側にある |
| 他人の形代 | その人の文章より本人の側にある |

他人を床に置いても「その人の味が出ている」とは言えない。排除できたのは、その基準に入れた
文章だけである。入れていない書き手、別の母集団、別の場面の文章は確かめていない。基準を
替えて検めるたびに言えないことの範囲は狭まるが、0 にはならない。

言えないことは言わない。3 値の判定で同じ「通る」が出ても、何を確かめた上での「通る」かは
床によって違う。そのため判定には、使った基準の場面の名前と中身のハッシュを添える
（[評価](200-extract.md#同じ基準形代で比べる)）。

床を 2 本同時に置くことはしない。判定の形が複雑になる割に、得られるものが確かめられて
いない。基準を替えて 2 度検めれば同じことが分かる。

### 目盛りは比べるときに組み立てる

目盛りは保存しない。本人の形代と基準の形代から、比べるたびにその場で組み立てる。
形代が持つのは、フォルダの文書を 1 本ずつ測った統計値だけである。

こうすると、どの形代も特定の基準に縛られない。基準を替えても作り直しは要らず、
本人の形代も基準の形代も同じ形になる。保存した目盛りと今の実装が食い違うことも
起きない。

> 経緯：以前は本人の形代が目盛りを持っていた。基準を替えるたびに作り直しになり、
> 基準の来歴を人に名乗らせていた。文書ごとの統計値だけから目盛りを組み立てても、判定が
> 動いたのは 104 回の検めのうち 1 回だけだったので、組み立てる形に変えた。

### 届かないときは「判定できない」と言う

天井と床のあいだには、どちらとも言えない区間（[帯](../glossary.md#帯)）ができる。草稿の値が
帯に入ったときは、無理に判定せず「判定できない」を返す。

返すのは点数ではなく、通る・通らない・判定できないの 3 値である。

理由は、分からないときに分からないと言えることが、言えるときの正しさを支えるからである。
日本語のブログ 100 人の実験では、2 割弱を判定不能に回すと、残りで感度 100%・特異度 95.1%
が出ている（[財津・金](../references/zaitsu-2018.md)）。

## 言うときの決定

[言うために何が要るか](#言うために何が要るか)の表の 4（直す側が受け取れる形）についての
決定である。詳細は[検め](300-revise.md)が決める。

### 一度に渡すのは 3 本か 4 本

直す側に一度に渡す[指摘](../glossary.md#指摘)は 3 本か 4 本までにする。幅から外れた指標を
全部並べてはいけない。

特徴を並べて指示すると、手本だけを見せるより結果が悪くなる
（[Bhandarkar](../references/bhandarkar-2024.md)）。原因は渡すこと自体ではなく、渡す数が
多すぎることらしい。渡す本数を変えた実験が 2 つあり、独立に同じところへたどり着いている。

| | 頂点 | それを超えると |
| --- | --- | --- |
| 文体の軸を混ぜる（[StyleRemix](../references/styleremix-2024.md)） | 3〜4 | 5 本以上で文法が 16% 落ちる |
| 他の著者を混ぜる（[AuthorMix](../references/authormix-2026.md)） | 4 | 7 本以上で劣化 |

これは測る側の集合を絞る話ではない。集合は広く持ち、渡すときだけ絞る。

3 本渡しても、ちょうど 3 本ぶんの指標が動くとは限らない。指標どうしは独立ではないからで
ある。実測では、段落の切り方を直す 1 つの改稿が、[段落長の変動係数](metrics/段落長の変動係数.md)と
[1文だけの段落の割合](metrics/1文だけの段落の割合.md)の両方を動かした。

したがって 3 本か 4 本という枠は渡す本数の上限であり、独立な指示の本数ではない。直した
結果は[測り直して見る](300-revise.md#直したら測り直す)。指示していない指標が一緒に動いて、
幅の外へ出ることもありうる。

### 観測・普段・直し方を揃える

1 本の指摘には、観測（草稿での値）・普段（本人の値）・直し方の 3 つを揃えて渡す。指標の
名前と数値だけでは直せない。

これは軸の要求そのものである。「ここが、こちらへ、これだけ」の 3 つに、それぞれ観測・
直し方・普段が対応する。

### 本人の読みは、判定ではなく候補として使う

直した文章を本人に読ませた感想は、判定には使わず、指標を見直す手掛かり（候補）として使う。

本人には判定できないからである。81 人が LLM の草稿を自分らしく直した実験で、本人は直した
文章を、自分で書いた文章と同じくらい自分らしいと評価した。しかし測ると、効果量 1.43 の
差が残っていた（[Post-Editing](../references/post-editing-2026.md)）。したがって「本人が
受け入れた」ことは、本人の文章に近づいた証拠にならない。

それでも読ませる価値はある。本人に見えるものと見えないものが分かっているからである。

| | |
| --- | --- |
| 見える | 表層の異物。特定の記号、特定の語、飾りの多さ |
| 見えない | 分布。頻度、揺れ、組み立ての癖 |

数値と本人の読みの食い違いは、両方向に起きる。

| 数値 | 本人 | 意味 |
| --- | --- | --- |
| 通る | 違うと言う | 指標が足りない。[指標](100-metrics.md#集合が変わるとき)に戻る入口になる |
| 通らない | 気付かない | 正常。本人には見えない層を数値が捕まえている |

2 行目を「数値が神経質すぎる」と読んではいけない。本人に見えない層を捕まえることこそ、
数値を置いている理由である。

## 書かせるのは LLM、道具はプロンプトまで

書くのは使う人の LLM の道具で、kuchiyose は書かせるためのプロンプトを作り、その道具を
起動するところまでを受け持つ（[軸](000-axis.md#だからしないこと)）。検める側は、草稿が
どう作られたかを問わない。kuchiyose のプロンプトで書かせたものも、ほかで書かせたものも、
人が自分で書いたものも、同じように検める。

プロンプトに期待するものは狭く取る。書かせる側を工夫しても表面の書きぶりは寄らないことが
測られている。同じ課題で、書かせる側の工夫を 4 通り比べた結果がある
（[Sawant](../references/authorship-gap-2026.md)）。

| 手法 | 本人との一致 |
| --- | --- |
| 何もしない（内容の要約だけ渡す） | 0.484 |
| 手本を見せる | 0.508 |
| 文体プロファイルを渡す | 0.502 |
| 対照例と文体特徴を渡す | 0.494 |

どの工夫をしても一致は最大 0.024 しか動かない。しかも 4 つとも、赤の他人どうしの一致
0.626 を下回っている。

一方、直す作業には効果が測られている。本人が LLM の草稿を直すと、自分の文章との一致が
効果量 0.55 上がる（[Post-Editing](../references/post-editing-2026.md)）。効くのは直す側で
ある。

だからプロンプトの役目を分ける。

| プロンプト | 期待すること | 期待しないこと |
| --- | --- | --- |
| [代筆のプロンプト](400-write.md#代筆のプロンプト) | ペルソナで内容・構成・考え方を本人に近づける。文体の事実で大きな外れ（文体、一人称）を先に防ぐ | 表面の書きぶりを揃えること |
| [直させるプロンプト](400-write.md#表現を寄せる周回) | 検めて出た指摘の箇所だけを直させる | 内容を良くすること |

表面の書きぶりを閉じるのは、書く前の指定ではなく、書いた後の周回である。

### 使うときはループになる

この道具の成果物は「寄った文章」ではなく、検めて直すループである。

書く → 検める → 直す → 検める → ……

1 回で寄せきれる前提は立たない（[軸](000-axis.md#なぜ言うが要るのか)）。回数を重ねて寄せる
ので、1 周を安くすることがそのまま品質になる。

周回は kuchiyose が回す（[表現を寄せる周回](400-write.md#表現を寄せる周回)）。1 周ごとに
使う人の LLM の道具を対話なしで起動して直させ、kuchiyose が検める。人が周回に付き合わずに
済めば、1 周はそれだけ安くなる。直す側に人を置く周回もそのまま使える。人が直して
`review` を打てば、同じ判定と指摘が返る。書くところから人が自分でやった文章を持ち込んでも
よい。

## どの順に作るか

指標 → 評価 → 検めの順に作れる。指標は既にあるものを使うので、良いかどうかを測って決める
必要が無く、書き下せば終わる。

| | 何を必要とするか |
| --- | --- |
| [指標](100-metrics.md) | 先行研究と[文書の形](020-document.md)。除外の下限を除いて、測定を必要としない |
| [評価](200-extract.md) | 指標と、本人の文章と、基準 |
| [検め](300-revise.md) | 評価の出力と、検める対象の文章 |
| [代筆](400-write.md) | 評価の出力（型・基準の型・基準の語）と、検めの判定と指摘 |

閾値を決めるためにも循環は起きない。幅も天井も床も[評価](200-extract.md)の出力であり、
コーパスから導く。導くために、ほかの何かの完成を待つ必要は無い。

### それでも骨格を先に通す

順に作れても、1 つずつ順に完成させてはいけない。まず細い実装で端から端まで通し、その後で
太らせる。

理由は、この設計が成立するかどうかが、端まで通してみないと分からないことにある。確かめたい
ことはどれも、最後まで通さないと結果が出ない。

| 確かめること | 分かる場所 |
| --- | --- |
| 既存の指標が、kuchiyose の文書モデルの上で意味のある値を出すか | [評価](200-extract.md) |
| 天井と床が分離するか | [評価](200-extract.md) |
| 指摘どおりに直すと、実際に数値が動くか | [検め](300-revise.md)を 2 周 |

最も危ないのは、天井と床が分離するかである。分離しなければ、そこから先のすべてが意味の
読めない値の上に建つ。先行研究は日本語ブログで分離を確かめているが、コードブロックや見出しを
含む文書では誰も確かめていない（[指標](100-metrics.md#場面で成立しないことがある)）。

<strong>骨格が端まで通るまで、判定の閾値を手で決めない。</strong> 天井と床の帯、幅の境目、系統の
重みがこれにあたる。ここを手で埋めると、分離しなかったという事実が定数の中に隠れてしまう。

除外の下限はこの例外である。分母が小さいと値が大きくぶれるのは、分離するかどうかとは無関係
なので、暫定の値を置いてよい（[指標](100-metrics.md#除外の既定)）。ただし暫定であることを
書いておき、骨格が通ったら導き直す。

### 運用に入ると、戻る線が 2 本できる

1 度作って終わりではない。運用を始めると、後ろの段が前の段へ返すものが出てくる。

| 戻る線 | 何が返るか |
| --- | --- |
| [検め](300-revise.md) → [評価](200-extract.md) | 指示して値が動いたか。[効くかどうかの条件 3](200-extract.md#どの指標が効くかを決める)は、実際に直させてみるまで分からない。動かないと分かった指標は、使う人が形代で[無効にする](300-revise.md#動かない指標は使う人が無効にする) |
| [検め](300-revise.md) → [指標](100-metrics.md) | 本人の指摘。数値は通ると言い、本人は違うと言うなら、指標を足す（[指標](100-metrics.md#集合が変わるとき)） |

この 2 本の線は設計の一部であり、たまたま生じるものではない。初回の構築に無いだけである。
