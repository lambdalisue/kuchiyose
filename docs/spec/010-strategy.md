# kakiburi の戦略

[軸](000-axis.md)『どこがその人と違うかを、言えるようにする』へ到達する道筋を決める。

この文書が決めるのは、<strong>何が要るか</strong>、<strong>どの順に作るか</strong>、<strong>どこで間違えやすいか</strong>の 3 つ
である。個々の数え方・持ち方は、この先の文書が決める。

## 通るには 2 つ要る

軸の出発点は「代筆させたものが、その人が書いたものとして通る」ことだった。<strong>これは
2 つに分かれる。</strong>

| 条件 | 先行研究の状況 |
| --- | --- |
| <strong>その人らしい</strong> | 誰も届いていない（[Sawant](../references/authorship-gap-2026.md), [AuthorMix](../references/authormix-2026.md)） |
| <strong>人が書いたものに見える</strong> | 解かれた例がある（[SICO](../references/sico-2024.md)） |

<strong>2 つ目は 1 つ目から出てこない。</strong> GPT 系の生成文が人と判定される割合はほぼ 0% であり
（[Catch Me](../references/catch-me-2025.md)）、文体がどれだけ寄っても、機械が書いたと
分かる文章は別の条件で落ちる。

<strong>両方について言えるようにする。</strong> 片方だけ揃っても通らない以上、片方だけ測る道具は
役に立たない。

## 言うために何が要るか

言えた状態とは、こう言えることである。

> この文章は、その人と比べて、<strong>ここが、こちらへ、これだけ</strong>違う。

成り立たせるには 4 つ要る。<strong>1 つでも欠ければ言えない。</strong>

| | 要るもの | 欠けると | どこが作るか |
| --- | --- | --- | --- |
| 1 | <strong>違いを載せる量</strong> | 「なんとなく違う」で終わる | [指標](100-metrics.md) |
| 2 | <strong>その人の側の値</strong> | 「違う」の相手がいない | [評価](200-extract.md) |
| 3 | <strong>値を読む目盛り</strong> | 0.5 が近いのか遠いのか決まらない | [評価](200-extract.md) |
| 4 | <strong>直す側が受け取れる形</strong> | 言えていない | [検め](300-revise.md) |

3 が 2 と同じ場所にあるのは、<strong>同じ材料から作れる</strong>からである。目盛りは別に集めてくる
ものではなく、本人の文章と基準を測れば出る。

### 4 つとも、対象が揃っていることを前提にする

素材は取り込み元がばらばらである。Markdown の方言、HTML、チャットの書き出し。同じ
「補足」が、ある場所では引用の記法で、別の場所では専用の記法で書かれる。

<strong>揃えなければ、測っているのは書き手ではなく取り込み元である。</strong>

だから[文書の形](020-document.md)と[正規化](030-normalize.md)は、
[指標](100-metrics.md)・[評価](200-extract.md)・[検め](300-revise.md)のどれかが持つので
はなく、<strong>3 つ全部が同じものを使う</strong>。片方だけ違う揃え方をすれば、比べたものに意味が
無い。

## 何を扱うか

軸は「どこが違うか」としか言っていない。<strong>違いのうち、どれを扱うかは決まっていない。</strong>

扱うのは <strong>ある人の、ある場面での、書きぶりの違いだけ</strong> である。上の条件 1 つ目がこれに
あたる。2 つ目——人が書いたものに見えるか——は書きぶりの違いではないが、同じ指標の集合
に入れる（[指標](100-metrics.md#通るための-2-条件を両方覆う)）。

<strong>これは選択である。</strong> 何が違うかを言うだけなら、内容の選び方も、判断の下し方も対象に
なりえた。書きぶりに絞る理由は、<strong>そこだけが訊かずに取れて、同じ人の中で安定するから</strong>
である。

### 書きぶりとは何か

書きぶりとは、<strong>題材と場面を決めたあとに、なお人によって違ってしまう部分</strong>である。
場面とは、誰に向けて、どういう立ち位置で、何のために書くかを指す。同じ題材を同じ場面
で 10 人が書けば 10 通りになる。その差が書きぶりである。

5 つの性質を持つ。<strong>1 つでも欠けるものは書きぶりではない。</strong>

| | 性質 | どこから来たか |
| --- | --- | --- |
| 1 | 人によって違いうる | <strong>個人差</strong>（[財津・金](../references/zaitsu-2018.md)） |
| 2 | 同じ場面で書いたものに一貫して現れる | <strong>個人内恒常性</strong>（同） |
| 3 | 題材が変わっても変わらない | 機能語は題材に依存しない（[Stamatatos](../references/stamatatos-2009.md)） |
| 4 | 本人が意識していない | 機能語は無意識に使われる（同） |
| 5 | 文章に現れる | この分野が一貫して文章を対象にしてきた |

1 と 2 が土台である。書き手識別が成り立つ条件そのもので、
[財津・金](../references/zaitsu-2018.md)が名指ししている。

> 各個人によって表出される文体的特徴に「個人差」と「個人内恒常性」が存在することから
> 筆者の識別が可能となる

3 から 5 は、この 2 つをどこまで信じてよいかを限定する。3 は恒常性が題材に対しても
求められること、4 は取り出す手段が計測になる理由、5 は対象の線引きである。

### 境界が紛らわしい 2 つ

<strong>性質 1——誰が書いても同じになるものは外れる。</strong>「文頭の接続詞の後に読点を打つ」は
性質 2 から 5 をすべて満たすが、公用文の手引きに書かれている常識である。読点という
1 つの現象の中に、誰もが打つ層と、人によって違う層が混ざっている（石黒 2011、
[岩崎](../references/japanese-attribution-others.md)）。だから
[規範の層を分ける](#規範の層を分ける)。

<strong>性質 2——場面が変われば成り立たない。</strong> 場面の寄与は人の寄与と同じ大きさである
（[水上ほか](../references/mizukami-2014.md)。<strong>ただし話し言葉での測定であり</strong>、書き言葉での
再現は確かめられていない）。だから
「同じ場面で」と限定されている。場面を分けるのは媒体ではない。同じチャットでも、
チームへの報告と社外への連絡は別の場面になる。だから[場面ごとに閉じる](#場面ごとに閉じる)。

### 数えない違い

違いはあっても、書きぶりの違いではないもの。どれも上の性質のどれかを満たさない。

| 違い | なぜ数えないか |
| --- | --- |
| 題材が違う | 書くたびに変わる。性質 2 と 3 を満たさない |
| 場面が違う | 扱う前に決まっている前提である。違いとして出せば、人の違いと混ざる |
| 文章の出来が違う | 性質 1 を満たさない。読む側にあるものである |
| 文法が誤っている | 性質 1 を満たさない。違えばそれは誤りである |
| 規範に従っているかどうか | 性質 1 を満たさない。誰を測っても同じ値になる（[規範の層](#規範の層を分ける)の 1 行目） |
| 考えかた・判断軸が違う | 性質 4 を満たさない。本人が言葉にできる（[訊けるものは訊く](#訊けるものは訊く)） |
| 場面をまたぐ書き分けの度合いが違う | 性質 2 を満たさない |

### 日本語だけ

特徴量は言語ごとに違う。既製の特徴量セットも、日本語向けの資源も、それぞれ別の言語を
前提にして作られている（[Writeprints](../references/writeprints-liwc.md)）。1 つに合わせる。

## 量を決めるときの決定

要るもの 1 についての決定である。詳細は[指標](100-metrics.md)が決める。

### 指標を発明しない

<strong>何が書き手を分けるかは、日本語で既に確かめられている</strong>（[先行研究](../references/README.md#分かったこと測定)）。
日本語ブログ 2,287 人で EER 9.3% の組み合わせがあり
（[尤度比](../references/fusing-lr-2026.md)）、独立した研究が同じ顔ぶれに落ちている
（[金 2014](../references/jin-2014.md)）。

自前で候補を思いつき、実験し、採否を決める手続きは持たない。<strong>やっても、確かめられて
いることを確かめ直すことにしかならない。</strong> kakiburi が決めるのは <strong>数え方だけ</strong> である。

<strong>そして選抜もしない。</strong> 特徴は頻度で選ぶ。判別力で選抜するのは話題分類の作法であり、
選抜された特徴はコーパス依存になる（[Stamatatos §2.6](../references/stamatatos-2009.md)）。

### 種類の違うものを混ぜる。ただし 5 系統前後まで

<strong>混ぜると当たる。そして種類をまたぐと、大きく当たる。</strong>

| 組み合わせ | Cllr（0 が最良、1 が偶然） |
| --- | --- |
| 文字 bigram 単独 | 0.47115 |
| 単語埋め込み単独 | 0.38757 |
| 同じ種類どうし——計量文体論 3 つ | 0.43964 |
| 同じ種類どうし——埋め込み 2 つ | 0.36186 |
| <strong>種類をまたぐ——文字 bigram + 単語埋め込み</strong> | <strong>0.34603</strong> |
| <strong>最良（5 系統）</strong> | <strong>0.32484</strong> |
| 6 系統 | 0.32579 |
| 全 7 系統 | 0.32855 |

（[尤度比](../references/fusing-lr-2026.md)）<strong>同じ種類どうしでも少しは伸びる。だが種類を
またげば 2 つで、同じ種類を 3 つ重ねたものを超える。</strong>

<strong>そして 3 系統から 7 系統までは、ほぼ横ばいである。</strong> 論文はこれを「残りの系統は、矛盾は
しないが <strong>新しい情報を大して足していない</strong>」と読んでいる。EER の最良はむしろ 4 系統
（0.09273）にある。

<strong>だから 5 という数に根拠は無い。</strong> あるのは <strong>足しても伸びなくなる</strong>という事実だけである。

<strong>上限を 5 に置くのは我々の判断である。</strong> 横ばいの帯の真ん中を取り、測る手間を抑えた。
<strong>4 でも 6 でも報告された差はほとんど無い。</strong>

<strong>この上限は、判定のときに突き合わせる系統の数である。</strong> 集合そのものを 5 つに絞る話では
ない（[指標](100-metrics.md#集合は広く持つ絞るのはあとである)）。どれを入れるかは
[評価](200-extract.md#判定に使う系統を選ぶ)が決める。

### 単独で弱いことは、落とす理由にならない

文節パターンは単独 F1 0.704 で最下位なのに、<strong>最良の組み合わせには必ず入っている</strong>
（[統合アンサンブル](../references/japanese-attribution-recent.md)）。逆に、機能語 unigram が
最良の組み合わせから落ちた例もある（単独では 7 系統中 5 位、0.63002）
（[尤度比](../references/fusing-lr-2026.md)）。

<strong>単独の順位は、組み合わせでの寄与を予測しない。</strong>

### 規範の層を分ける

<strong>1 つの現象の中に、誰もがやることと、人によって違うことが混ざっている。</strong>

| 層 | 何が決めるか | 個人差 |
| --- | --- | --- |
| 誰もが打つ | 意味・長さ・構造 | 出ない |
| 人により異なる | 表記・音調・リズム | <strong>出る</strong> |
| 一部の人が打つ | 強調 | <strong>出る</strong> |

（読点について、石黒 2011 を[岩崎](../references/japanese-attribution-others.md)が引用）

<strong>「読点の密度」という 1 つの数字にすると、3 層が混ざって規範に薄められる。</strong> 粗い方に
丸めない。ここが数え方でいちばん効く判断である。

## どう数えるかの決定

### 判定できるのは数値だけである

[軸](000-axis.md#なぜ道具が要るのか)が道具を要求した根拠であり、以下の決定の前提でも
ある。

| 誰が言うか | 何が起きるか |
| --- | --- |
| 本人 | 直した文章を自分のものと<strong>区別できない</strong>（g = 1.43 の差が残っていた） |
| 他人 | 文体についての判断が<strong>一致しない</strong>（評価者間 0.641、推敲は 0.400） |
| LLM に判定させる | <strong>循環する。</strong> 生成文（0.542）が本人の文章（0.427）より高く出る |
| LLM に特徴を挙げさせる | 同じ人から 2 回抽出して<strong>一致しない</strong>（Jaccard 0.22） |

（[根拠](../references/README.md#分かったこと評価)）

<strong>残るのは、決定的で解釈できる数値である。</strong> 決定的でなければ物差しにならず、
解釈できなければ「どこが」を言えない。

### 数える側に LLM を置かない

上の 3 行目と 4 行目から直接出る。<strong>同じ入力からは同じ結果を出す。</strong> 決定性は好みでは
なく成立条件である。

<strong>この循環は、そのまま検査に使える。</strong> 本人の実際の文章を採点して、生成文より低く出る
指標は壊れている——測っているのは著者性ではなく指示追従である
（[Sawant](../references/authorship-gap-2026.md)）。安く、決定的で、強い。

### 訊かずに測る

書きぶりは本人が意識していない（[性質 4](#書きぶりとは何か)）。取り出す手段は、本人へ
の質問ではなく、書いたものを数えることになる。

同じ理由で、どこまでが普通かも人が決めない。本人が実際に書いたものから取る。

### 訊けるものは訊く

<strong>いちばん紛らわしいのが判断軸である。</strong> 何を良しとし、何を書かないか。その人らしい
文章に要るものなので、取り出したくなる。

<strong>取り出さない。諦めではなく、訊けば答えが返るからである。</strong>

| 訊いたときに | |
| --- | --- |
| 「すべて」と「全て」のどちらを使いますか | 答えられない |
| 何を書かないと決めていますか | 答えられる |

書きぶりが計測でしか取れないのは、無意識の選択の集積だからである。判断軸は意識して
取っている立場なので、本人が言葉にでき、<strong>しかも本人の答えが常に正しい。</strong> 推定する
必要が無いものを推定しない。

書く人が判断軸を自分で添えることは禁じない。この道具が測らないと決めただけである。

## 値を作るときの決定

要るもの 2 についての決定である。詳細は[評価](200-extract.md)が決める。

### 場面ごとに閉じる

恒常性は場面の中でしか成り立たない（[性質 2](#境界が紛らわしい-2-つ)）。評価も、照らす
のも、1 つの場面の中で閉じる。

<strong>閉じないことは、精度が少し落ちることではない。</strong> クロスエントロピーで測ると、同じ人
でも役割が変われば +0.77、違う人でも役割が同じなら +0.85——<strong>ほぼ同じ大きさ</strong>である
（[水上ほか](../references/mizukami-2014.md)）。混ぜれば、<strong>測っているものの半分が場面に
なる。</strong> ただしこの実験の対象は話し言葉であり、書き言葉での再現は確かめられていない。

場面は人が指定する。相手も立ち位置も目的も文章の外にあるので、文章から当てにいけば
外す。

<strong>例外は置かない。</strong> その場面の文章が集まっていないときは、近い場面から取るのではなく
<strong>断る</strong>（[検め](300-revise.md#当てにならないときは言う)）。

<strong>取れる余地はある。だが今は通らない。</strong> 場面をまたいでも一貫すると確かめられているのは
<strong>品詞 unigram と読点の打ち方</strong>で、文字・記号の unigram と文節パターンは大きく動く
（[柳・金 2022](../references/yanagi-jin-2022.md)）。<strong>そのうち品詞 unigram が集合に無い。</strong>
残る 1 つでは[照合値が作れない](200-extract.md#判定に使う系統を選ぶ)。

<strong>足せば開く。</strong> 開けるかどうかは、その 2 つで下す判定に意味があるかを測ってから決める
——同じ論文の中でも、実験によって順位が入れ替わっている。

### 題材を統制する

書きぶりは題材を決めたあとに残る差である（[性質 3](#書きぶりとは何か)）。<strong>だがこれは
理想である。</strong> 機能語も文字 n-gram も題材情報を拾う
（[Stamatatos §5](../references/stamatatos-2009.md)）。

<strong>数値が付いている</strong>（[Wegmann](../references/wegmann-2022.md)）。統制せずに訓練した
文体表現は、自分と同じ条件では AUC .79 出るのに、題材を揃えたテストでは <strong>.58</strong> へ落ちる。
<strong>その .79 は文体ではなく題材の精度だった。</strong> 会話の統制で訓練すれば 3 条件とも .69〜.71 で安定するが、文体と題材のどちらを選ぶかを問う課題では <strong>最良でも 0.42</strong>、無作為の 0.50 を
下回る。

<strong>減らすことはできても、消しきれない。</strong> 統制しなければ、測っているのは題材である。
3 つを守る。

<strong>基準の題材を、本人が実際に書いた題材から取る。</strong> コーパス全体として、本人側と基準側の
題材の散り方を揃える。<strong>対ごとに揃えることはしない</strong>（[理由](200-extract.md#題材の統制は対ではなく素材に効かせる)）。

<strong>題材には、記事が名指しする物を含める。</strong> 題名だけを渡すと足りない。「Vim のファイラー系
プラグインについて書け」と言われた LLM は、プラグイン名も、コマンド名も、版番号もほとんど
書かない。同じ題材の本人の記事はそれらで埋まっている。

<strong>結果として、基準の側だけラテン文字と ASCII 記号が薄くなる。</strong> 実測では、この差だけで
天井と床が分離した——[文字種](metrics/文字種.md)を日本語 3 種に絞ると分離は
10 通り中 3 通りに落ちる（[実験](../spike/300-baseline-scene.md#分離の出どころを割った)）。
<strong>名指しする物は「何について書くか」の側である。</strong> 伏せれば題材が揃わない。

<strong>依頼文に「どう書くか」を漏らさない。</strong> 本文の書き出しから依頼文を作ると、書き出しの
癖がそのまま手掛かりになり、基準値が <strong>28 ポイント</strong>膨らむ
（[Sawant](../references/authorship-gap-2026.md)）。依頼文は「何について書くか」の中立な
要約にする。

<strong>名指しする物も、表記を写してはいけない。</strong> 上の 2 つ目は物の名前を渡せと言っているが、
<strong>その名前の書き方まで渡すと漏れる。</strong>「Vim script」と書くか「Vim スクリプト」と書くか、
版番号を半角で書くか全角で書くか、括弧をどちらで括るか——それは
[和欧間スペース欠落](metrics/和欧間スペース欠落.md)や[数字の字幅](metrics/数字の字幅.md)が
測っている書きぶりの層である。<strong>要約は人が書く</strong>ので、ここは人が守る規則になる。

## 目盛りを作るときの決定

要るもの 3 についての決定である。詳細は[評価](200-extract.md#目盛りを作る)が決める。

### 天井と床を測る

<strong>値そのものには意味が無い。</strong> 0.5 が近いのか遠いのかは、比べる先が無ければ決まらない
（[Sawant](../references/authorship-gap-2026.md)）。<strong>2 つの端を測る。</strong>

| | 何を測るか | 何が言えるか |
| --- | --- | --- |
| <strong>天井</strong> | 本人の文章どうし | ここまで来れば本人の揺れの中である |
| <strong>床</strong> | 本人と、LLM の既定出力 | ここを超えなければ何もしていないのと同じ |

床に LLM の既定出力を置くのは、<strong>直したいのがそれだから</strong>である。そして <strong>集めるのでは
なく作れる</strong>ので、素材が手に入らずに止まることがない。

<strong>他人の文章が手に入るなら、床をもう 1 つ足す。</strong> LLM に対する床は「良くなったか」を
言うだけで、「本人のものとして通るか」は言わない。他人に対する床がそれを言う
（[財津・金](../references/zaitsu-2018.md)）。ただし複数の書き手のコーパスが集まるかは
確かめていないので、<strong>無くても成立する設計にする。</strong>

### 届かないときは「判定できない」と言う

2 つの端の間には、どちらとも言えない帯ができる。<strong>そこを無理に判定しない。</strong>

日本語のブログ 100 人で、2 割弱を判定不能に逃がすと、残りで感度 100%・特異度 95.1% が
出ている（[財津・金](../references/zaitsu-2018.md)）。<strong>分からないと言えることが、言える
ときの正しさを支えている。</strong>

返すのは点数ではなく <strong>3 値</strong>——通る、通らない、判定できない——である。

## 言うときの決定

要るもの 4 についての決定である。詳細は[検め](300-revise.md)が決める。

### 一度に渡すのは 3 本か 4 本

<strong>外れた指標を全部並べてはいけない。</strong> 特徴を並べて指示すると、手本だけを見せるより
悪くなる（[Bhandarkar](../references/bhandarkar-2024.md)）。

原因は渡すこと自体ではなく <strong>多すぎること</strong>らしい。本数を振った実験が 2 つあり、独立に
同じところへ着いている。

| | 頂点 | それを超えると |
| --- | --- | --- |
| 文体の軸を混ぜる（[StyleRemix](../references/styleremix-2024.md)） | <strong>3〜4</strong> | 5 本以上で文法が 16% 落ちる |
| 他の著者を混ぜる（[AuthorMix](../references/authormix-2026.md)） | <strong>4</strong> | 7 本以上で劣化 |

<strong>測る側の集合を絞る話ではない。</strong> 集合は広く持ち、渡すときだけ絞る。

<strong>3 本渡して 3 本ぶん動くとは限らない。</strong> 指標どうしは独立ではない。実測では、
段落の切り方を直す 1 つの改稿が[段落長の変動係数](metrics/段落長の変動係数.md)と
[1文だけの段落の割合](metrics/1文だけの段落の割合.md)の<strong>両方を動かした</strong>
（[実験](../spike/500-directive-loop.md#1-つの直しが-2-つの指標を動かした)）。

<strong>だから枠の本数は上限であって、独立な指示の本数ではない。</strong> 直した結果は
[測り直して見る](300-revise.md#直したら測り直す)——<strong>連れて動いた指標が幅の外へ出ることも
ありうる。</strong>

### 観測・普段・直し方を揃える

名前と数値だけでは直せない。3 つ揃って初めて直せる。

<strong>これは軸の要求そのものである。</strong>「ここが、こちらへ、これだけ」の 3 つに、それぞれ
観測・直し方・普段が対応する。

### 本人の読みは、判定ではなく候補として使う

<strong>本人には判定できない。</strong> 81 人が LLM の草稿を自分らしく直した実験で、本人は直した
文章を自分で書いたものと同じくらい自分らしいと評価した。測ると差が効果量 1.43 残って
いた（[Post-Editing](../references/post-editing-2026.md)）。

<strong>したがって「本人が受け入れた」は、寄ったことの証拠にならない。</strong>

だが読ませる価値はある。<strong>本人に見えるものと見えないものが分かっている。</strong>

| | |
| --- | --- |
| 見える | <strong>表層の異物</strong>。特定の記号、特定の語、飾りの多さ |
| 見えない | <strong>分布</strong>。頻度、揺れ、組み立ての癖 |

<strong>食い違いは両方向に起きる。</strong>

| 数値 | 本人 | 意味 |
| --- | --- | --- |
| 通る | 違うと言う | <strong>指標が足りない。</strong>[指標](100-metrics.md#集合が変わるとき)に戻る入口 |
| 通らない | 気付かない | <strong>正常。</strong> 本人には見えない層を数値が捕まえている |

<strong>2 行目を「数値が神経質すぎる」と読んではいけない。</strong> それが数値を置いている理由で
ある。

## 書かせることはしない

<strong>「その人らしく書かせる」ことはしない。</strong> 文章を作るのは
[軸の外](000-axis.md#だからしないこと)である。

<strong>置かない理由は、置いても効かないことが測られているから</strong>でもある。同じ課題で、
書かせる側の工夫を 4 通り比べた結果がある（[Sawant](../references/authorship-gap-2026.md)）。

| 手法 | 本人との一致 |
| --- | --- |
| 何もしない（内容の要約だけ渡す） | 0.484 |
| 手本を見せる | 0.508 |
| 文体プロファイルを渡す | 0.502 |
| 対照例と文体特徴を渡す | 0.494 |

<strong>何をやっても 0.024 しか動かない。しかも 4 つとも「赤の他人どうし」の 0.626 を
下回っている。</strong>

一方、<strong>直す作業には効果が測られている</strong>——本人が LLM の草稿を直すと、自分の文章との
一致が効果量 0.55 上がる（[Post-Editing](../references/post-editing-2026.md)）。

<strong>効くのは直す側である。</strong> 草稿がどう作られたかは問わない。目的も章立ても文体の指定も、
書く人が好きに決めてよい。

### 使うときはループになる

<strong>1 回で寄せきる前提は立たない</strong>（[軸](000-axis.md#なぜ言うが要るのか)）。したがって
この道具の成果物は「寄った文章」ではなく <strong>ループ</strong> である。

<strong>誰かが書く（外）→ 検める → 直す → 検める → ……</strong>

<strong>回数で寄せる。</strong> 1 周を安くすることが、そのまま品質になる。入口が外にあることは弱点
ではない。人が全部自分で書いたものを持ちこんでもよい。

## どの順に作るか

<strong>順に作れる。</strong> 指標は既にあるものを使うので、良いかどうかを測って決める必要がない。
書き下せば終わる。

| | 何を必要とするか |
| --- | --- |
| [指標](100-metrics.md) | 先行研究と[文書の形](020-document.md)。<strong>除外の下限を除いて、測定を必要としない</strong> |
| [評価](200-extract.md) | 指標と、本人の文章と、基準 |
| [検め](300-revise.md) | 評価の出力と、検める対象の文章 |

閾値も循環しない。<strong>幅も天井も床も[評価](200-extract.md)の出力である。</strong> コーパスから
導くのであって、導くために別のものを待つ必要はない。

### それでも骨格を先に通す

順に作れることと、順に完成させてよいことは別である。<strong>細くても端から端まで通してから
太らせる。</strong>

理由は循環ではなく、<strong>この設計が成立するかどうかが端まで通さないと分からない</strong>ことに
ある。確かめたいのは 3 つで、どれも最後まで通さないと出てこない。

| 確かめること | 分かる場所 |
| --- | --- |
| 既存の指標が、kakiburi の文書モデルの上で意味のある値を出すか | [評価](200-extract.md) |
| <strong>天井と床が分離するか</strong> | [評価](200-extract.md) |
| 指摘どおりに直すと、実際に数値が動くか | [検め](300-revise.md)を 2 周 |

<strong>2 つ目が最も危ない。</strong> 分離しなければ、そこから先のすべてが読めない値の上に建つ。
先行研究は日本語ブログで分離を確かめているが、<strong>コードブロックや見出しを含む文書では
誰も確かめていない</strong>（[指標](100-metrics.md#場面で成立しないことがある)）。

<strong>骨格が通るまで、判定の閾値を手で決めない。</strong> 天井と床の帯、幅の境目、系統の重み。
ここを手で埋めれば、<strong>分離しなかったことが定数に隠れる。</strong>

<strong>除外の下限は別である。</strong> 分母が小さいと値が暴れるのは分離とは無関係なので、暫定の値を
置いてよい（[指標](100-metrics.md#除外の既定)）。ただし暫定であることを書き、骨格が通った
ら導き直す。

### 運用に入ると、戻る線が 2 本できる

<strong>1 度作ったら終わりではない。</strong> 回し始めると、後ろが前に返すものが出る。

| 戻る線 | 何が返るか |
| --- | --- |
| <strong>[検め](300-revise.md) → [評価](200-extract.md)</strong> | <strong>指示して動いたか。</strong>[効くかどうかの条件 3](200-extract.md#どの指標が効くかを決める)は、書かせてみるまで分からない |
| <strong>[検め](300-revise.md) → [指標](100-metrics.md)</strong> | <strong>本人の指摘。</strong> 数値が通ると言い本人が違うと言うなら、指標を足す（[指標](100-metrics.md#集合が変わるとき)） |

<strong>この 2 本は設計の一部であって、偶発ではない。</strong> 初回に無いだけである。
