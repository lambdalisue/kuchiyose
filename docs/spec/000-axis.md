# kuchiyose の軸

> その人の代わりに書けるようにする。書くのは LLM で、道具はプロンプトと検めまで。

kuchiyose が目指すのはこの 1 行である。迷ったときはここに戻る。

道具は 2 つの部分からなり、検める部分にはもう 1 行の軸がある。

> どこがその人と違うかを、言えるようにする。

| 部分 | 何をするか | LLM を使うか |
| --- | --- | --- |
| 書かせる部分 | 代筆のプロンプトを作り、使う人の LLM の道具に渡す | 使う人の道具が書く。kuchiyose は API を呼ばない |
| 検める部分 | 書かれた文章を数えて、判定と指摘を返す | 使わない。同じ入力に同じ答えを返す |

この文書は、なぜ道具がこの形になるのかと、検める部分がどんな仮説の上に立っているかを
書く。どうやって実現するかは[戦略](010-strategy.md)から先の文書が決め、書かせる部分は
[代筆する](400-write.md)が決める。言葉の意味は[用語集](../glossary.md)にある。

## やりたいこと

LLM に代筆させた文章に、その人の書き方が出ているようにしたい。書くものの種類は
限らない。自分に限る理由も無いので、以後は「その人」と書く。

### 隠すための道具ではない

AI が書いたことを隠すのが目的ではない。内容が良ければ、AI が書いたものでかまわない。

困るのは、代筆させた文章が素のままだと読みづらいことである。同じものを指すのに毎回
違う語を使い、どの段落も同じ調子で並び、その人が書くはずのない言い回しが混ざる。
読みづらさの原因は、その人の書き方が無いことにある。

だから「見破られないこと」は目標にしない。生成文が人と判定される割合のような、検出を
避ける側の指標は根拠に使わない。見るのは次の 2 つである。

- その人の書き方が出ているか
- 読みづらさの元が残っていないか

2 つ目は、本人と比べる相手（[基準](../glossary.md#基準)）との距離で測る。既定の基準は LLM が
素で書いた文章なので、既定のままなら機械の癖が残っていないかを見ることになる。ただし道具は
機械かどうかを判定しない。本人と基準を、誰の文章にも使える次元で分けているだけである
（[基準との距離](../glossary.md#基準との距離)）。

## 書くのは LLM、道具はプロンプトと検めまで

代筆で要るものは 2 種類あり、得意な者が違う。

| 要るもの | 誰が得意か |
| --- | --- |
| その人が書きそうな内容・話の運び方・考え方 | LLM。記事を読めば扱え、使う人と対話して詰められる |
| 表面の書きぶり（句読点、機能語、文字や品詞の並び、文末、括弧や記号、言い回しの癖） | 数える道具。LLM がいちばん苦手なところである |

だから書くのは LLM に任せ、道具は LLM が書く前と書いた後を受け持つ。書く前には、その人の
考え方を書いた[ペルソナ](../glossary.md#ペルソナ)と、形代から取り出した文体の事実を
プロンプトにまとめる。書いた後には、数えて検め、直させる周回を回す。

### 書かせ方の工夫では表面は寄らない

ペルソナや手本を渡して書かせても、表面の書きぶりはほとんど寄らない。書かせ方を 4 通り
比べた実験で、本人との一致は最大 0.024 しか動かず、どれも赤の他人どうしより本人から遠い
（[Sawant](../references/authorship-gap-2026.md)）。一方、LLM の草稿を直す作業には効果が
測られている。本人が直すと、自分の文章との一致が効果量 0.55 上がる
（[Post-Editing](../references/post-editing-2026.md)）。

したがってペルソナに期待するのは、内容・構成・考え方を本人に近づけるところまでとする。
表面の書きぶりは、検めて直す周回で寄せる。周回を安く速く回すことが、ペルソナの作り込みより
効く（[戦略](010-strategy.md#使うときはループになる)）。

### プロンプトを作るところまでにする

kuchiyose は LLM の API を呼ばない。使う人が手元に持つ LLM の道具（`claude`、`codex`
など）を、組み立てたプロンプトで起動するところまでを受け持つ。

- 検める部分に LLM が入らない。同じ入力に同じ答えを返すことが崩れない
  （[数える側に LLM を置かない](010-strategy.md#数える側に-llm-を置かない)）。
- 特定の LLM に縛られない。LLM の出来は道具の責任にならない。
- 内容を詰めるのは、人と LLM の対話がいちばん速い。道具はそこに割りこまない。

## なぜこの軸になるのか

ここから先は、検める部分の軸「どこがその人と違うかを、言えるようにする」について書く。

代筆させた文章がその人と違うことは、読めば分かる。分からないのは、どこが違うのかで
ある。しかも手を入れるほど、違うという感触のほうが先に薄れていく。この軸はその欠けを
埋めるためにある。

### なぜ「言う」が要るのか

1 回で満足のいく文章は出てこない。最新の手法で個人化しても、出力はまだ、赤の他人
どうしより本人から遠い（[Sawant](../references/authorship-gap-2026.md)）。

だから直すことになる。そして、人が直すにしても LLM に直させるにしても、受け取れるのは
言葉である。数値のベクトルを渡して寄せてもらう、という道は無い。

したがって違いは、言葉にできる形で出さなければならない。「同じ人か違う人か」だけでは
直せない。どの観点が、どちらへ、どれだけ外れているかが要る。

### なぜ道具が要るのか

人にも LLM にも、それを言わせられないからである。

| 誰が言うか | 何が起きるか | 根拠 |
| --- | --- | --- |
| 本人 | 手で直しても差は残るのに、直したものを自分の文章と同じくらい自分らしいと感じてしまう | [Post-Editing](../references/post-editing-2026.md) |
| 他人 | 文体についての判断が人によって揃わない（評価者間の一致 0.641） | [SPTG の評価](../references/sptg-evaluation-2025.md) |
| LLM | 生成文のほうを本人の文章より本人らしいと採点してしまう | [Sawant](../references/authorship-gap-2026.md) |

3 つとも、判断を人か LLM に任せているところで崩れている。残るのは、同じ入力に同じ答えを
返す数え方だけである。それがこの道具であり、ここから
[判定できるのは数値だけ](010-strategy.md#判定できるのは数値だけである)という決定が出る。

## この軸が置いている仮説

検める部分の軸は 1 つの仮説の上に立っている。検める部分の文書はどれもこれを前提にしている。

> 「その人らしさ」には、機械的に数えられる部分がある。
> そして、その部分だけで、直すのに足りるだけの違いが言える。

前半は計量文体論がすでに示している。本当に賭けているのは後半で、数えられる部分が
薄すぎて何も言えない、という結末もありうる。

### 仮説が主張していないこと

主張を広く取るほど外れるので、言っていないことを先に挙げておく。

| 言っていないこと | 補足 |
| --- | --- |
| らしさを全部数えられる | 内容・論理・機知は数えていない |
| 数字が揃えば人がそう感じる | まだ確かめていない（[下](#仮説のどこがまだ確かめられていないか)） |
| 本人だと断定できる | 言えるのは「差が見つからなかった」ことまで |
| 生成でそこに届く | 見分けられることと、そう書けることは別。先行研究では[まだ誰も届いていない](010-strategy.md#味が出るには-2-つ要る)。仮説は測る側についてのもの |
| 誰にでも同じだけ効く | 効き方は書き手ごとに違う（[効く指標の決め方](200-extract.md#どの指標が効くかを決める)） |

### なぜ数えられると考えるのか

著者を見分ける研究が、数えるだけで人を分けているからである。日本語のブログ 2,287 人・
1 人あたり 1,000 字で、文字 bigram・読点の打ち方・文字種などの頻度だけから、誤り率
（EER）9.3% が報告されている（[尤度比](../references/fusing-lr-2026.md)）。意味を
理解していない量でも、書き手は分かれる。

> [!WARNING]
> この数字をそのまま持ち込まない。素材は 2008〜09 年の日記で、別のジャンルに移すと
> 変わりうると論文自身が書いている
> （[較正されているのは層 1 の一部である](100-metrics.md#較正されているのは層-1-の一部である)）。
> 借りるのは「どの量を見るか」だけで、どれだけ効くかは手元で測る。

### 外れたら分かるようにしてある

仮説が成り立たない書き手や場面では、黙って通すのではなく「判定できない」として表に出る
ように作ってある。

| 外れ方 | どう表に出るか |
| --- | --- |
| 本人と基準が分かれない | [帯](../glossary.md#帯)が全体を覆い、「判定できない」しか返らない |
| 本人がいちばん高く出ない | 目盛りを組み立てるたびに確かめ、崩れていれば「本人を基準と見分けられない」として「判定できない」を返す（[検め](300-revise.md#自分を検査する)） |
| 数えた量で書き手が分かれない | [効く指標](../glossary.md#効く指標)が 1 本も無く、3 段目が「この書き手には効く指標が無い」として「判定できない」を返す（[検め](300-revise.md#前に出す指標が無ければ判定できない)） |
| 素材が足りない | 目盛りを組み立てず、「判定できない」を返す（[評価](200-extract.md#見る前に標本の範囲を確かめる)） |
| 草稿が短すぎる | 「短すぎて測れない」と字数と下限を添えて「判定できない」を返す（[検め](300-revise.md#段が測れないとき)） |
| 直しても動かない | 使う人がその指標を無効にし、以後は直し方として出さない（[検め](300-revise.md#動かない指標は使う人が無効にする)） |

「判定できない」を返すのは、謙虚さのためではない。仮説が当てはまっていないことを、
値ではなく状態として知らせるためである
（[戦略](010-strategy.md#届かないときは判定できないと言う)）。

### いまのところ仮説は成り立っている

本人の側では成り立っている。機械の側では、本人と同じ題材で書かせた文章がまだまれに通る。
ペルソナの書き手では、同梱の基準を置くと、書き手によってほかの書き手の記事が通る。

以下は 2026-09-26 の測定である。いまのコード（形代は文書ごとの統計値だけを持ち、
目盛りは review が組み立てる）と、同梱の基準をそのまま使った。閾値は何も動かしていない。

#### 本人の記事

素材は 1 人分である。本人の記事は 49 本（はてなと Zenn）。126 KB の外れ値 1 本は
長さの防護柵に当たるので外した。基準は同梱のものを使い、組み立てが本人の多い側の文体に
絞って題材の近い分を選ぶ。本人は敬体で書くので、4 通りとも敬体の基準だけが選ばれた。

本人の記事を名前順に並べて 4 つに分け、1 つを外して残りで形代を作り、外した分を
検める。これを 4 通りすべてで行った。4 通りとも目盛りは組み立てられた。1 通りだけで
出した数は当てにならない。

機械の側には、その回の目盛りに使っていない文章だけを当てた。

- 同梱の基準に無い LLM の記事 26 本。うち 15 本は本人の記事と同じ題材で書かせたもの
- 同梱の基準のうち、その回の組み立てに選ばれなかった 64 本

| 回 | 本人 通る / 外した本数 | 機械 通る（基準に無い 26 本） | 照合値 本人 | 照合値 機械（選ばれなかった分を含む） |
| --- | --- | --- | --- | --- |
| 1 | 6 / 13 | 1 | 1.762〜3.684 | −3.239〜0.179 |
| 2 | 8 / 12 | 0 | 0.929〜3.653 | −3.253〜1.271 |
| 3 | 8 / 12 | 0 | 2.362〜5.455 | −2.779〜0.720 |
| 4 | 6 / 12 | 2 | 0.777〜3.871 | −3.561〜1.106 |

4 通りを合わせると次のとおりである。機械は 1 本を 4 回検めたので、回数で数えている。

| | 通る | 判定できない | 通らない |
| --- | --- | --- | --- |
| 本人（外した 49 本） | 28 | 21 | 0 |
| 機械（基準に無い 26 本 × 4 回） | 3 | 25 | 76 |
| 機械（選ばれなかった 64 本 × 4 回） | 0 | 3 | 253 |

本人の記事が「通らない」になったことは 1 度も無い。

判定できなかった本人の記事 21 本の内訳は次のとおりである。

- 19 本は 1,000 字未満（53〜892 字）で、短すぎて測れない
- 1 本は系統が 2 つ欠けて、基準との距離が測れなかった
- 1 本は両方の値が出たうえで、指示できる指標が 1 本だけ幅の外にあった

短い記事について、この道具は何も言わない。これは欠陥ではなく、
[外れたら分かるようにしてある](#外れたら分かるようにしてある)とおりに出ている。

照合値は、回 2 と回 4 で本人と機械が重なった。機械の値 360 個のうち、本人の最小値を
上回ったのは 2 個で、どちらも同じ記事である。

通らなかった機械の記事 76 回は、照合値で止まったのが 51 回、基準との距離で止まったのが
25 回である。通ってしまった 3 回のうち 2 回は、本人の記事と同じ題材（Vim のファイラー、
iPhone の音楽）で書かせたものだった。選ばれなかった基準は 1 度も通らないが、題材の近い分を
選んだ残りなので、易しい相手である。

同じ日の先の測定では、池が常体だけのときは本人 通る 23 / 判定できない 26 / 通らない 0、
機械 104 回中 8 回が通った。敬体で書く本人と草稿に対して床が低く出ていたためで、文体で
池を絞ると 21 / 28 / 0、6 回になった。そのあと、基準との距離の窓を延べ 729 語に揃え、
3 段目で[小さな外れを数えない](300-revise.md#小さな外れは数えない)ことにし、
[欠けた系統を 1 つまで埋める](200-extract.md#欠けた系統は-1-つまで基準の側へ寄せて埋める)
ことにした。いまの数字はこの 3 つを入れたもので、事前に見込んだ 28 / 21 / 0、3 回前後と
合っている。目盛りの揺れで機械の通過は ±3 回ほど動くので、6 回から 3 回への変化を
減ったとまでは言えない。

#### ペルソナの書き手

本人が 1 人しかいないことを補うため、LLM にペルソナを指定して書かせた書き手 4 人で
同じことをした。敬体の 2 人（web-polite、student-casual）と常体の 2 人（sre-plain、
data-formal）で、1 人 20 本、地の文は 919〜2,953 字である。20 本とも使った。

1 人ごとに 5 本ずつ 4 つに分け、1 つを外して残りで形代を作り、外した分、上と同じ機械の
記事 26 本、ほかの 3 人の記事 60 本を検めた。

| 書き手 | 長さの窓で選び直した回 | 本人 通る / 判定できない / 通らない | 機械 通る（104 回） | ほかの書き手 通る（240 回） |
| --- | --- | --- | --- | --- |
| web-polite | 3 / 4 | 12 / 5 / 3 | 3 | 56 |
| sre-plain | 4 / 4 | 14 / 6 / 0 | 0 | 11 |
| student-casual | 0 / 4 | 14 / 4 / 2 | 0 | 0 |
| data-formal | 3 / 4 | 8 / 8 / 4 | 0 | 0 |

16 回すべてで目盛りが組み立てられた。本人より短い基準を選べない回は、本人の長さの窓の中から
基準を選び直している。ペルソナの記事は本物の本人の記事より短いので、半分以上の回がこれに当たった。

本人の記事が 9 本「通らない」になった。止まった段はどれも基準との距離である。本人の側が
LLM の文章なので、基準との距離が小さく出るのは自然である。本物の人の記事では、この段の
出方が違うかもしれない。

ほかの書き手の記事は、web-polite と sre-plain の目盛りで通った。止まらずに最後の段まで
進んでいる。web-polite の目盛りでは、student-casual の記事が 80 回中 36 回、data-formal が
19 回、sre-plain が 1 回通った。常体の書き手まで通るので、文体の違いだけでは説明できない。
sre-plain の目盛りでは、student-casual が 7 回、data-formal が 3 回、web-polite が 1 回通った。
student-casual と data-formal の目盛りでは、ほかの書き手は 1 度も通らない。

書き手の組みをすべて katashiro diff で比べたところ、4 人のどの 2 人も見分けられた。
基準に同梱のものでなく相手の書き手を置けば、照合値の帯は 12 組すべてで分かれる。
同梱の基準を置いたときは、書き手によって、ほかの書き手を本人から切り離せない。

#### 独立した検証ではない

帯の閾値（隙間の真ん中で切ることと、そのまわりの保留の幅）も、上の 3 つの規則の線も、
本人の取り置いた記事を見ながら決めた。本人の側の通る割合は、その選び方の影響を受けている。

本物の人の素材はまだ 1 人分である。ペルソナは LLM が書いた「人」で、ほかの書き手で
成り立つことの代わりにはならない。

### 仮説のどこがまだ確かめられていないか

数字が揃った文章を、読んだ人が「その人らしい」と感じるかは測っていない。

道具が測っているのは表に出る統計である。統計が揃うことと、読んでそう感じることの
あいだは、まだつながっていない。つなぐには読者を集めた評価が要るが、そこは
[他人の判断が揃わない](#なぜ道具が要るのか)という、この軸が最初に避けた場所に戻ることになる。

ここが埋まっていないことは、道具の限界そのものなので、消さずに書いておく。

書かせる部分にも、測っていないところがある。ペルソナが内容や考え方を本人らしくしたかは、
数えられない。本人が読んで判断する（[確かめ方](400-write.md#ペルソナが効いたかは本人が読んで決める)）。

## だからしないこと

道具の内と外は、1 つの基準で分ける。その人の代わりに書かせるために道具の中に無ければ
ならないか、外から渡されれば済むか、である。

| しないこと | 理由 |
| --- | --- |
| 自分で文章を書く・LLM の API を呼ぶ | 書くのは使う人の LLM の道具である。道具はプロンプトを作って渡せば済む |
| 文章の中身を決める | 目的も章立ても主張も、使う人が LLM との対話で決める |
| 文章を集めてくる | 素材は渡されればよい |

プロンプトの組み立て、ペルソナの引用の確かめ、読み込み、正規化、計測、周回の進め方は、
渡されただけでは済まないので道具の中にある。

作ってはいけないという意味ではない。この道具の仕事ではない、という意味である。
