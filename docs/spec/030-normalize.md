# 入力を正規形にする

集めた文章を、[文書の形](020-document.md)が定める形に落とす手順を決める。

[評価](200-extract.md)と[検め](300-revise.md)は、測る前に必ずここを通る。
<strong>片方だけ違う揃え方をすれば、比べたものに意味が無い。</strong>

## 何のためにやるか

<strong>同じ内容が、書式の違いだけで別の値にならないようにする。</strong>

素材は取り込み元がばらばらである。Markdown の方言、HTML、プレーンテキスト、チャットの
書き出し。同じ「補足」が、ある場所では引用の記法で、別の場所では専用の記法で書かれる。

揃えなければ、<strong>測っているのは書き手ではなく取り込み元である。</strong>

## 守るべき 4 つ

| | 守ること | 破るとどうなるか |
| --- | --- | --- |
| 1 | [決定的である](#決定的である) | 下流のすべてが揺れる |
| 2 | [意味で認識する](#意味で認識する) | 測っているのが記法になる |
| 3 | [表記を潰さない](#表記を潰さない) | 測る価値の高い層を捨てる |
| 4 | [通らないものは断る](#通らないものは断る) | 値の狂った文書が正常な顔で混ざる |

## 決定的である

<strong>同じ入力からは、いつでも同じ正規形が出る。</strong>

[数える側に LLM を置かない](010-strategy.md#数える側に-llm-を置かない)の言い換えでは
ない。<strong>正規化にも同じ制約が独立にかかる。</strong> ここが揺れれば、指標がどれだけ決定的でも
値は揺れる。

推測を混ぜない。「これはたぶん補足だろう」と判断しない。<strong>書き手が記法で示したものだけ
を認識する。</strong>

## 意味で認識する

[文書の形](020-document.md#文書は-node-でできている)は node を意味で定めている。記法は
取り込み元の事情である。<strong>だから記法から意味への対応表は、ここが持つ。</strong>

### 黙って壊れる場所がある

<strong>ここがいちばん危ない。</strong> GitHub の Alert 記法は、引用の記法の上に建っている。

```markdown
> [!NOTE]
> ここは補足である。
```

<strong>素朴に CommonMark として解釈すると、これは引用になる。</strong> そして——

| | 何が起きるか |
| --- | --- |
| 引用の密度 | <strong>実際より高く出る</strong> |
| 補足の密度 | <strong>0 が並ぶ</strong> |

<strong>エラーにならない。</strong> 値が出て、判定が回り、結果だけが違う。

<strong>Alert 記法を持つ取り込み元では、引用より先に Alert を認識する。</strong> 同じことが脚注、
折りたたみ（`<details>`）、独自の補足記法にも起きる。

### 対応表は取り込み元ごとに持つ

| 取り込み元 | 補足をどう書くか |
| --- | --- |
| GitHub 系 | `> [!NOTE]` |
| directive 記法 | `:::note` |
| HTML | `<aside>` |
| 素の Markdown | <strong>書けない。</strong> 引用として現れる |

<strong>最後の行が重要である。</strong> 補足を書けない取り込み元では、補足の密度は測れない。

<strong>0 と「測れない」を区別する。</strong> 0 を並べれば、その書き手は補足を使わない人だと判定
される。

## 表記を潰さない

<strong>正規化と称して、字種を揃えてはいけない。</strong>

全角と半角、`〜` と `～`、`…` と `……`。これらは
[書き手の選択であり、測る価値が高い](020-document.md#表記は残る優先して採る理由がある)。

<strong>潰す側と潰さない側を、はっきり分ける。</strong>

| | 例 |
| --- | --- |
| <strong>潰す</strong>（記法） | 箇条書きの `-` と `*`、見出しの `#` と下線、強調の `**` と `__` |
| <strong>潰さない</strong>（表記） | 字種、字幅、空白の入れ方、改行の位置 |

多くの整形ツールは、頼まなくても表記まで揃える。<strong>既製のフォーマッタを通す前に、何を
書き換えるかを確かめる。</strong> 通したあとでは、潰れたことに気付けない。

## 通らないものは断る

<strong>正規形に落ちない入力がある。</strong> 落ちないまま無理に通さない。

| | どうするか |
| --- | --- |
| 記法が壊れていて解釈できない | <strong>断る</strong> |
| 対応表に無い記法が使われている | <strong>断る。</strong> 対応表を足してから通す |
| 日本語以外が主 | <strong>断る</strong>（[日本語だけ](010-strategy.md#日本語だけ)） |

黙って一部を落として通せば、<strong>落ちた分だけ値が狂った文書</strong>が、正常な文書と同じ顔で
コーパスに入る。

## 正規形が原本である

[元のファイルは手元に残らない](200-extract.md#3-つに分けて持つ)前提で設計する。

したがって、<strong>正規形から測れないものは、永久に測れない。</strong> 迷ったら残す側に倒す。

<strong>往復は目的ではない。</strong> 正規形から元の書式を復元できる必要は無い。復元性を求めれば
記法の情報を抱えることになり、[潰すと決めたもの](#表記を潰さない)が残ってしまう。

## 変換したことを記録する

<strong>何をどう変換したかを、値と一緒に残す。</strong>

- 取り込み元の種類
- 使った変換の実装と版
- 適用した対応表

[指紋](200-extract.md#何で測ったかを指紋にする)に含める。<strong>変換規則が変われば、過去の値
と比べられない。</strong> 記録が無ければ、比べられないことにも気付けない。

### 変換規則を変えると、戻れない

<strong>指標が増えたときの測り直しとは、性質が違う。</strong> 指標は本文から何度でも計算し直せるが、
<strong>本文そのものは元のファイルが無いので作り直せない。</strong>

したがって変換規則を変えると、コーパスは <strong>古い規則で落とした本文</strong>と <strong>新しい規則で
落とした本文</strong>に割れ、二度と揃わない。

| 変わったもの | 過去の本文 |
| --- | --- |
| 指標の集合 | 測り直せる |
| <strong>変換規則</strong> | <strong>作り直せない。割れたまま残る</strong> |

<strong>だから変換規則を変えるときは、割れることを承知で決める。</strong> 取りうる道は 2 つしかない。

- 素材を集め直して、新しい規則で入れ直す
- 古い規則の本文を別のコーパスとして分け、混ぜて評価しない

<strong>黙って変えない。</strong> 混ざれば、[場面ごとに閉じる](010-strategy.md#場面ごとに閉じる)を
守っていても、規則の差が人の差として出る。
