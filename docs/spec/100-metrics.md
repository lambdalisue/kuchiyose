# 戦術: 指標を決める

[戦略](010-strategy.md)の 1 段目。曖昧な書きぶりを、定量評価できる指標の集合と
して定義する。

ここで決めるのは、指標が何を備えていなければならないか、候補をどう出すか、集合に
入れる条件は何かである。どの指標がどの書き手に効くかは決めない。
それは書き手ごとに決まる（[200](200-extract.md#どの指標が効くかを決める)）。

## 1 つの指標が備えるもの

| | |
| --- | --- |
| 意味 | 何を捉えようとしているか |
| 数え方 | 何を分子に、何を分母に取るか |
| 単位 | 率（日本語 1,000 字あたり）か、無次元か |
| 除外 | 測っても意味を持たない文書の条件 |
| 向き | 上に外れるのを見るか、下も見るか、両方か |
| 直し方 | 外れたときに何をすればよいか |

意味と数え方を別に書く。名前だけでは数え方が決まらない。「見出しの密度」と書いて
あっても、深さを区別したか、タイトルを数えたかは分からない。決め方ひとつで値は
倍も変わる。

除外が要るのは、分母が小さいと値が暴れるためである。段落が 3 つしかない文書で
段落長のばらつきを測っても、書きぶりではなく偶然を測ることになる。

## 候補の出し方

思いつきから。人が仮説として挙げる。早いが、思いつける範囲を超えない。

比較から。ある書き手の文章と基準の文章を突き合わせ、目立つ差を拾う。思いつけな
かったものはここからしか出ない。

## 集合に入れる条件

[軸](000-axis.md)の性質から出る。実験で確かめる。

<strong>決定的に計算できる</strong>（性質 4）。同じ文章からは同じ値が出る。意味を取らないと
決まらないものは、指標ではない。

<strong>題材で動かない</strong>（性質 3）。同じ人の、題材の違う文書どうしで測って、値が動かない。
動くなら、拾っているのは話題である。

<strong>場面の中で一貫する</strong>（性質 2）。同じ人の同じ場面で、1 本ごとに暴れない。暴れる
なら、その記事の事情を測っている。

<strong>ほかのものと連動していない</strong>。文書の長さ、段落や節の数、書かれた時期と相関を
取る。連動しているなら、測っているのはその何かである。

いずれも <strong>1 人の書き手の文章だけで確かめられる</strong>。だからここで確かめる。

## 人によって差が出るかは、ここでは見ない

軸の定義からすれば「人によって差が出る」ことも要件である。だがそれは、この段では
確かめられない。書き手が 1 人分しか無ければ、差が出るかどうかを見る相手がいない。

そして確かめられないだけでなく、<strong>ここで見てはいけない</strong>。何が特徴になるかは人に
よって違う（[軸](000-axis.md#何が特徴になるかも人による)）。ある書き手で差が出な
かったことを理由に外すと、「この人の特徴ではない」を「誰の特徴でもない」と取り
違える。

したがってこの段が作るのは <strong>候補の集まり</strong> であって、採用された指標の一覧では
ない。上の条件を満たすものは、誰かに効くかもしれないものとして入れておく。

入れる費用は小さく、外す損失は大きい。入れれば測る手間が少し増えるだけだが、外せ
ばその指標が決め手になる書き手を永久に取りこぼす。迷ったら入れる。

外すのは、複数の書き手で効かないと分かったときだけである。それが分かるのは、複数
の書き手を測ったあとになる。

<strong>その人にとってどれが効くかは、その人の文章を測ったときに決まる</strong>
（[200](200-extract.md#どの指標が効くかを決める)）。

## 足し引きを安くする

指標が入れ替わり続けるなら、入れ替えの安さは実装の都合ではなく、精度が上がるか
どうかを決める条件である。1 つ足すのに何か所も直す必要があれば、実験は回らず、
指標は最初に思いついたまま固定される。

### 1 つの指標は 1 か所に書く

上の表の項目を、すべて 1 つのエントリに入れる。足すのはエントリを 1 つ増やす
こと、外すのは 1 つ消すことで終わる。

### 名前は 1 度しか書かない

同じ指標の名前が 2 か所にあってはいけない。ずれたときに何が起きるかを考えると、
理由が分かる。

測った値の側に名前があって幅の側に無ければ、その指標は <strong>黙って発火しなくなる</strong>。
エラーにならない。動き続けて、結果だけが変わる。落ちてくれるなら気付けるが、
落ちないので気付けない。

### 使う側は一覧を持たない

指標を使うところ——指示を作る、外れを出す、値を保存する、中身を覗く——は、指標の
一覧を自分で書かない。定義を回す。

自分で書くと、足した指標が一部にしか現れない。現れていないことにも気付かない。

### 数え方は指標ごとに 1 関数でなくてよい

定義が 1 か所であることと、実装が指標ごとに割れていることは別である。1 度の走査で
まとめて数えられるものを分けても、走査が増えるだけで得るものが無い。

まとめてよい。ただし、実装が返す名前と定義にある名前が一致していることは機械で
確かめる。どちらか一方にしか無い名前があれば落ちるようにする。

### 実験のための出口を持つ

条件を確かめるにも、書き手ごとの採否を決めるにも、コーパスを測って値を見る必要が
ある。1 本を測る、2 本を比べる、
コーパス全体の分布を出す。この 3 つを、指標を試す人が直接使えるようにする。

無ければ、候補を 1 つ試すのに本体の処理を通すことになり、実験が重くなる。重く
なった手続きは回らなくなる。

## 定義はここに置く

指標の定義は仕様である。実装が何を計算すべきかを決めるものだからである。
[metrics/](metrics/) に 1 指標 1 ファイルで置く。

1 つにまとめない。指標を足し引きするたびに同じファイルを編集することになり、
[足し引きを安くする](#足し引きを安くする)ことに反する。

集合そのものが「試したことの記録」でもある。ある書き手で効かなかった候補も残るので、
同じ候補を思いつき直しても、既にそこにあると分かる。

## 測った値はリポジトリに置かない

ある書き手を測った値は、その書き手のものであって、この道具の仕様ではない。置き
場所は 2 段目が作る成果物の中であり（[200](200-extract.md)）、リポジトリの文書では
ない。

候補を試した結果も同じである。1 人で見た結果は採否を決めていない
（[人によって差が出るかは、ここでは見ない](#人によって差が出るかは-ここでは見ない)）。
決めていないものを仕様の隣に置いても、確かめた気にさせるだけになる。

手法として残す価値があるものは、結果ではなく手続きの側に書く。標本の範囲を先に
確かめること、交絡を疑うことは、どれも実際の失敗から出てきたが、書くべきは失敗の
記録ではなく手続きである。

## 集合として点検する

書きぶりは語にも文にも組み立てにも現れ、目立つのは大きい方である（軸）。候補は
放っておくと語に寄る。数えやすいからである。

個々の指標が要件を満たすことと、集合として書きぶりを覆っていることは別である。
偏りは集合として見ないと分からない。
