# 戦術: 指標を決める

[戦略](010-strategy.md)の 1 段目。曖昧な書きぶりを、定量評価できる指標の集合と
して定義する。

ここで決めるのは、指標が何を備えていなければならないか、候補をどう出すか、差が
あるとどう判定するか、結果をどう記録するかである。どの指標を採ったかは決めない。
それは実験の結果であり、[docs/metrics/](../metrics/) にある。

## 1 つの指標が備えるもの

| | |
| --- | --- |
| 意味 | 何を捉えようとしているか |
| 数え方 | 何を分子に、何を分母に取るか |
| 単位 | 率（日本語 1,000 字あたり）か、無次元か |
| 除外 | 測っても意味を持たない文書の条件 |
| 向き | 上に外れるのを見るか、下も見るか、両方か |
| 直し方 | 外れたときに何をすればよいか |

意味と数え方を別に書く。名前だけでは数え方が決まらない。「見出しの密度」と書いて
あっても、深さを区別したか、タイトルを数えたかは分からない。決め方ひとつで値は
倍も変わる。

除外が要るのは、分母が小さいと値が暴れるためである。段落が 3 つしかない文書で
段落長のばらつきを測っても、書きぶりではなく偶然を測ることになる。

## 要件

[軸](000-axis.md)の定義から 4 つ出る。

1. 人によって差が出る。出ないなら、書きぶりを測っていない。
2. 同じ人なら題材が変わっても動かない（性質 3）。動くなら、話題を測っている。
3. 同じ場面の中で一貫する（性質 2）。1 本ごとにばらつくなら、その記事の事情を
   測っている。
4. 文章から決定的に計算できる（性質 4）。同じ文章からは同じ値が出る。

## 候補の出し方

思いつきから。人が仮説として挙げる。早いが、思いつける範囲を超えない。

比較から。本人の文章と基準の文章を突き合わせ、目立つ差を拾う。思いつけなかった
ものはここからしか出ない。

## 差があると判定する

素材は少ない。統計的な検定に足りる件数は集まらないので、範囲で見る。

### 分離

本人側と基準側の値の範囲を出し、交わり方を見る。

| 形 | 判定 |
| --- | --- |
| 交わらない | 分離した |
| 一方が他方を完全に含む | 分離しない。含む側は「その値も取りうる」としか言っていない |
| 端が重なる | 重なりの幅を本人側の幅と比べる。半分を超えるなら分離しない |

### 安定

同じ人の、題材の違う文書どうしのばらつきを見る。それが本人と基準の差より大きい
なら、拾っているのは題材である。

分離だけで採ってはいけない。本人と基準とで題材が違えば、題材の差が分離として
出る。この検査はそれを弾くために要る。

### 交絡を疑う

分離したとき、その指標が別の何かと連動していないかを見る。文書の長さ、段落や節の
数、書かれた時期。連動しているなら、測っているのはその何かである。

疑いは、連動しそうなものとの相関を出して晴らす。晴れないなら採らない。

### 測る前に標本の範囲を確かめる

両側の標本が同じ範囲を覆っているかを、値を見る前に確かめる。覆っていなければ、
分離しても重なっても、どちらの結果も信じられない。

数を増やすより先に、範囲を見る。

## 1 人で落とさない

分離しなかったからといって、集合から外してはいけない。何が特徴になるかは人に
よって違う（[軸](000-axis.md#何が特徴になるかも人による)）。ある人にとって何も
言っていない指標が、別の人にとっては決め手になる。

1 人で見て外すと、「この人の特徴ではない」を「誰の特徴でもない」と取り違える。

したがってこの段で決めるのは、<strong>候補の集まりに入れるかどうか</strong> だけである。分離
しなかった候補も、安定して測れて定義がはっきりしているなら残す。

外してよいのは 2 つの場合だけである。複数の書き手で効かないと分かったとき。
そして、そもそも安定して測れないと分かったとき。前者は素材が 1 人分しかないうちは
判定できない。

その人にとってどれが効くかは、その人の文章を測ったときに決まる
（[200](200-extract.md#どの指標が効くかを決める)）。

## 足し引きを安くする

指標が入れ替わり続けるなら、入れ替えの安さは実装の都合ではなく、精度が上がるか
どうかを決める条件である。1 つ足すのに何か所も直す必要があれば、実験は回らず、
指標は最初に思いついたまま固定される。

### 1 つの指標は 1 か所に書く

上の表の項目を、すべて 1 つのエントリに入れる。足すのはエントリを 1 つ増やす
こと、外すのは 1 つ消すことで終わる。

### 名前は 1 度しか書かない

同じ指標の名前が 2 か所にあってはいけない。ずれたときに何が起きるかを考えると、
理由が分かる。

測った値の側に名前があって幅の側に無ければ、その指標は <strong>黙って発火しなくなる</strong>。
エラーにならない。動き続けて、結果だけが変わる。落ちてくれるなら気付けるが、
落ちないので気付けない。

### 使う側は一覧を持たない

指標を使うところ——指示を作る、外れを出す、値を保存する、中身を覗く——は、指標の
一覧を自分で書かない。定義を回す。

自分で書くと、足した指標が一部にしか現れない。現れていないことにも気付かない。

### 数え方は指標ごとに 1 関数でなくてよい

定義が 1 か所であることと、実装が指標ごとに割れていることは別である。1 度の走査で
まとめて数えられるものを分けても、走査が増えるだけで得るものが無い。

まとめてよい。ただし、実装が返す名前と定義にある名前が一致していることは機械で
確かめる。どちらか一方にしか無い名前があれば落ちるようにする。

### 実験のための出口を持つ

採否を決めるには、コーパスを測って値を見る必要がある。1 本を測る、2 本を比べる、
コーパス全体の分布を出す。この 3 つを、指標を試す人が直接使えるようにする。

無ければ、候補を 1 つ試すのに本体の処理を通すことになり、実験が重くなる。重く
なった手続きは回らなくなる。

## 定義はここに置く

指標の定義は仕様である。実装が何を計算すべきかを決めるものだからである。
[metrics/](metrics/) に 1 指標 1 ファイルで置く。

1 つにまとめない。指標を足し引きするたびに同じファイルを編集することになり、
[足し引きを安くする](#足し引きを安くする)ことに反する。

集合そのものが「試したことの記録」でもある。分離しなかった候補も残るので、同じ
候補を思いつき直しても、既にそこにあると分かる。

## 測った値はリポジトリに置かない

ある書き手を測った値は、その書き手のものであって、この道具の仕様ではない。置き
場所は 2 段目が作る成果物の中であり（[200](200-extract.md)）、リポジトリの文書では
ない。

候補を試した結果も同じである。1 人で見た結果は採否を決めていない
（[1 人で落とさない](#1-人で落とさない)）。決めていないものを仕様の隣に置いても、
確かめた気にさせるだけになる。

手法として残す価値があるものは、結果ではなく手続きの側に書く。標本の範囲を先に
確かめること、交絡を疑うことは、どれも実際の失敗から出てきたが、書くべきは失敗の
記録ではなく手続きである。

## 集合として点検する

書きぶりは語にも文にも組み立てにも現れ、目立つのは大きい方である（軸）。候補は
放っておくと語に寄る。数えやすいからである。

個々の指標が要件を満たすことと、集合として書きぶりを覆っていることは別である。
偏りは集合として見ないと分からない。
