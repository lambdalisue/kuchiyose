# 戦術: 指標を決める

[戦略](010-strategy.md)の 1 段目。曖昧な書きぶりを、定量評価できる指標の集合として
定義する。

指標の集合は一度で決まらない。<strong>回して育てる。</strong> 品質はループが何周したかで決まる
ので、この戦術の中心は、各段をどれだけ安くするかにある。

| | 段 | 止まる原因 |
| --- | --- | --- |
| 1 | 思いつく | — |
| 2 | 実験する | 素材が無い。測るのが高い |
| 3 | 採る、否定する | 判定の規準が無い |
| 4 | 実装に組みこむ | 1 つ足すのに何か所も直す |
| 5 | 文章に当てる | — |

5 で気付いたことが 1 に戻る。閉じているので回る。

どれか一段でも高ければ回らなくなり、指標は最初に思いついたまま固定される。以下は
段ごとに、何をするかと、どうすれば安いかを決める。

## 1. 思いつく

### 候補の出し方

<strong>思いつきから。</strong> 人が仮説として挙げる。早いが、思いつける範囲を超えない。

<strong>比較から。</strong> ある書き手の文章と基準の文章を突き合わせ、目立つ差を拾う。思いつけ
なかったものはここからしか出ない。

### 思いついたら定義に落とす

1 つの指標は次を持つ。どれか 1 つでも欠けているものは、まだ指標ではない。

| | |
| --- | --- |
| 意味 | 何を捉えようとしているか |
| 数え方 | 何を分子に、何を分母に取るか |
| 単位 | 率（日本語 1,000 字あたり）か、無次元か |
| 除外 | 測っても意味を持たない文書の条件 |
| 向き | 上に外れるのを見るか、下も見るか、両方か |
| 直し方 | 外れたときに何をすればよいか |

「地の文」「日本語の文字」「文」「段落」の意味は
[020-document.md](020-document.md) が決める。指標ごとに決め直さない。

<strong>意味と数え方は別に書く。</strong> 名前だけでは数え方が決まらない。「見出しの密度」と
書いてあっても、深さを区別したか、タイトルを数えたかは分からない。決め方ひとつで値は
倍も変わる。

<strong>除外を持つ。</strong> 分母が小さいと値が暴れる。段落が 3 つしかない文書で段落長のばらつき
を測っても、書きぶりではなく偶然を測ることになる。

## 2. 実験する

### 素材を用意する

測ることが 3 段目の前提である。素材が無ければ、この戦術は 1 段目で止まる。

[軸](000-axis.md)は「文章を集めてこない」と定めているが、それは <strong>道具が</strong> 集めない
という意味である。道具を作る側は、素材が無ければ何も確かめられない。

要るのは 2 つだけである。

<strong>ある書き手の文章。</strong> 1 つの場面で、まとまった本数。題材はばらけている方がよい。
条件 2 を確かめるのに、題材の違う文書どうしを比べる必要があるためである。

<strong>基準。</strong> 同じ場面、できるだけ同じ題材で、LLM に書かせたもの。<strong>集めるのではなく
作る</strong> ので、人手はほとんど要らない。基準を LLM の既定出力に置いたことの実利がここに
出る。

この 2 つで、次の段の条件は <strong>全て</strong> 確かめられる。書き手が何人も要る条件は置かない。

### 測るのを安くする

候補を 1 つ試すのに本体の処理を通すのでは、実験が重くなる。重くなった手続きは回らない。

3 つを、指標を試す人が直接使えるようにする。

- 1 本を測る
- 2 本を比べる
- コーパス全体の分布を出す

## 3. 採る、否定する

<strong>入る条件と、残る条件を分けない。</strong> 満たすものが入り、満たさなくなったものが外れる。

分けると、入るときの検査を通ればあとは問われない状態ができる。思いついただけの指標
は、そこに溜まる。

| | 何を見るか |
| --- | --- |
| 1. 決定的に計算できる | 同じ文章から同じ値が出る（[軸](000-axis.md)の性質 4） |
| 2. 題材で動かない | 同じ人の、題材の違う文書で値が動かない（性質 3） |
| 3. 場面の中で一貫する | 同じ人の同じ場面で、1 本ごとに暴れない（性質 2） |
| 4. 値が動く | 書き手側と基準側を合わせた全文書で、同じ値ということがない |
| 5. ほかのものと連動していない | 長さ、段落や節の数、書かれた時期と相関しない |
| 6. ほかの指標と連動していない | 集合の中に、同じものを測っている指標が無い |

### 通ると何が言えるか

<strong>区別する力があること</strong> までである。実際に誰かを区別できたことではない。

条件 4 は、その指標が実在の文章で値を変えることを示す。条件 3 は、その変化が書き手の
中の揺れに埋もれないことを示す。合わせると、書き手どうしが違えばその差が値に出る、
という力が確かめられる。思いつきとの違いはここにある。

### 目の前の書き手で効かないことは、否定の理由にならない

条件 3 と 4 を満たしていても、その書き手の幅が基準の幅のちょうど内側に収まることは
ある。読点の密度が本人 25、基準 15 から 35、というような形である。両方を通り、それでも
分離していない。

このとき外してはいけない。分離しなかったのは、その指標に力が無いからではなく、
<strong>この書き手がその点で基準と似ていた</strong> からである。何が特徴になるかは人によって違う
（[軸](000-axis.md#何が特徴になるかも人による)）。

効くかどうかは書き手ごとに決まる（[200](200-extract.md#どの指標が効くかを決める)）。

### 1 つの場面で効かないことも、否定の理由にならない

条件 2 から 4 は、測った場面の中でしか判定できない。絵文字は技術記事ではどの書き手も
0 が並ぶので、技術記事だけで見れば条件 4 で落ちる。だがチャットでは書き手を強く分ける。

場面ごとに判定し、<strong>どこかの場面で通れば残す</strong>。ある場面で死んでいることは、その場面
で使わない理由にはなるが、集合から外す理由にはならない。

### 否定してよいのは

<strong>条件 4 で落ちたとき。</strong> どの文書でも同じ値しか出ない指標は、まだ効くと分かっていない
のではなく、原理的に誰も区別できない。思いつきで入れた指標の多くはここに落ちる。数え方
が悪いのか着眼が悪いのかは分けて考え、前者なら直して入れ直す。

<strong>条件 6 で重複と分かったとき。</strong> 名前が違うだけで同じものを測っている指標は、片方を
外す。残す方を選ぶ基準は、定義が単純な方、除外の少ない方、意味を 1 文で言える方である。

それ以外では外さない。入れる費用は測る手間が少し増えるだけだが、外す損失は、その指標
が決め手になる書き手を永久に取りこぼすことである。<strong>費用が非対称なので、外すには理由が
要り、入れるには要らない。</strong>

### それでも絞るのは

集合が広いほど、<strong>偶然効いて見える指標が増える</strong>。30 の指標を 7 本で測れば、いくつかは
まぐれで揃う。無駄な指標は無駄なだけでなく、本物を埋もれさせる。

### 「誰にも効かない」を理由にはしない

多くの書き手で試して 1 人も効かなかった指標を外す、という規則は置かない。

置くには複数の書き手のコーパスが要る。それが集められるかは確かめていない。<strong>確かめて
いない前提の上に規則を建てない。</strong> 建てれば、動かない規則が仕様に残る。動かない規則は、
外す手立てがあるかのように見せる分だけ、無いより悪い。

### 判定の結果を書き留めない

どの条件を確かめたかを、指標のファイルに書かない。草案と本採用のような区分も持たない。

条件 1 は定義の性質で、読めば分かる。満たさないものは草案ではなく <strong>未完成</strong> であり、
直してから置く。条件 2 から 6 は測定の結果で、コーパスと場面が変われば変わる。これは
[測った値](#測った値は置かない)と同じ性質のもので、書いて持つものではない。

<strong>忘れて困るなら、それは測るのが高いということである。</strong> 答えは「書き留める」ではなく
「[測るのを安くする](#測るのを安くする)」になる。書き留めた状態は必ず古くなり、古い
状態は無いより悪い。

## 4. 実装に組みこむ

1 つ足すのに何か所も直す必要があれば、ここでループが止まる。

### 定義は 1 指標 1 ファイル

指標の定義は仕様である。実装が何を計算すべきかを決めるものだからである。
[metrics/](metrics/) に 1 指標 1 ファイルで置く。

1 つにまとめない。指標を足し引きするたびに同じファイルを編集することになる。

集合そのものが「試したことの記録」でもある。ある書き手で効かなかった候補も残るので、
同じ候補を思いつき直しても、既にそこにあると分かる。

### 実装も 1 指標 1 エントリ

[定義の項目](#思いついたら定義に落とす)を、すべて 1 つのエントリに入れる。足すのは
エントリを 1 つ増やすこと、外すのは 1 つ消すことで終わる。

### 名前は 1 度しか書かない

同じ指標の名前が 2 か所にあってはいけない。測った値の側に名前があって幅の側に無ければ、
その指標は <strong>黙って発火しなくなる</strong>。エラーにならない。動き続けて、結果だけが変わる。
落ちてくれるなら気付けるが、落ちないので気付けない。

### 使う側は一覧を持たない

指標を使うところ——指示を作る、外れを出す、値を保存する、中身を覗く——は、指標の一覧を
自分で書かない。定義を回す。

自分で書くと、足した指標が一部にしか現れない。現れていないことにも気付かない。

### 数え方はまとめてよい

定義が 1 か所であることと、実装が指標ごとに割れていることは別である。1 度の走査でまとめ
て数えられるものを分けても、走査が増えるだけで得るものが無い。

ただし、実装が返す名前と定義にある名前が一致していることは機械で確かめる。どちらか一方
にしか無い名前があれば落ちるようにする。

### 測った値は置かない

ある書き手を測った値は、その書き手のものであって、この道具の仕様ではない。置き場所は
2 段目が作る成果物の中であり（[200](200-extract.md)）、リポジトリの文書ではない。

## 5. 文章に当てて、次の候補を得る

集合ができたら、書き手の値を出し（[200](200-extract.md)）、書かせ（[300](300-generate.md)）、
既存の文章に当てる（[400](400-revise.md)）。

そこで <strong>数値は揃っているのに本人が違うと感じたなら、足りないのは指標である</strong>。何が
足りないかは、当ててみないと分からない。だから 5 段目は、使う段であると同時に、次の候補
を出す段でもある。

### 集合の偏りを見る

書きぶりは語にも文にも組み立てにも現れ、目立つのは大きい方である（軸）。候補は放って
おくと語に寄る。数えやすいからである。

個々の指標が条件を満たすことと、集合として書きぶりを覆っていることは別である。偏りは
集合として見ないと分からない。当てたときに気付くのは、たいていこの偏りである。
