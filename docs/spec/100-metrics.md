# 指標を決める

[戦略](010-strategy.md#言うために何が要るか)が挙げた 1 つ目——<strong>違いを載せる量</strong>——を作る。

作るのは <strong>指標の集合</strong>である。1 つ 1 つが、名前と、数え方と、出どころを持つ。

## 何を使うか

<strong>指標は発明しない</strong>（[決定](010-strategy.md#指標を発明しない)）。<strong>ただし出どころは
一様ではない。</strong> 3 つの層に分けて持つ。混ぜれば、確かめられていないものが確かめられた
ものと同じ顔で並ぶ。

### 層 1——日本語の書き手識別で確かめられているもの

日本語のブログ・作文・日記・文学作品で、繰り返し採られている顔ぶれである。

| 特徴 | 出どころ |
| --- | --- |
| <strong>文字 bigram</strong> | [金 2014](../references/jin-2014.md), [尤度比](../references/fusing-lr-2026.md), [柳・金](../references/yanagi-jin-2022.md) |
| <strong>機能語</strong>（助詞・助動詞・接続詞・副詞・感動詞） | [財津・金](../references/zaitsu-2018.md)。ほかに[水上ほか](../references/mizukami-2014.md)（<strong>話し言葉</strong>）、[Writeprints](../references/writeprints-liwc.md)（<strong>英語</strong>） |
| <strong>品詞 bigram</strong> | [金 2014](../references/jin-2014.md), [財津・金](../references/zaitsu-2018.md) |
| <strong>読点の打ち方</strong> | [財津・金](../references/zaitsu-2018.md), [尤度比](../references/fusing-lr-2026.md), [柳・金](../references/yanagi-jin-2022.md) |
| <strong>文字種</strong> | [尤度比](../references/fusing-lr-2026.md) |
| 文節パターン | [金 2013](../references/jin-2013.md), [柳・金 2023](../references/yanagi-jin-2023.md)。<strong>[保留中](metrics/文節パターン.md#保留)</strong> |
| <strong>埋め込み</strong>（単語・文字） | [尤度比](../references/fusing-lr-2026.md)。<strong>[定義が無く、当面使わない](#埋め込みは保留する)</strong> |

<strong>読点の打ち方を否定している研究は見当たらない。</strong> 独立した特徴として立てているのが
上の 3 本で、残る[金 2014](../references/jin-2014.md)は <strong>文字 bigram に包含される</strong>と
しており、落としてはいない。

### 層 2——別の目的の研究から取るもの

<strong>書き手を分けるかは確かめられていない。</strong> 日本語の資源として使えることは分かっている
が、著者識別で検証された報告が無い。

| 特徴 | 何の研究か | 何が確かめられていないか |
| --- | --- | --- |
| 文末表現 | [有馬ら](../references/arima-2018.md)。有益投稿の選別 | 4 クラスは<strong>集団の文体</strong>であって個人の文体ではない。<strong>辞書が配布されているかも確かめていない</strong> |
| 語の文体値 | [馬場](../references/baba-2022.md)。BCCWJ の語彙表 | 語に文体値が付くことと、書き手を分けることは別 |
| 表記の選択 | [Wegmann](../references/wegmann-2022.md) | <strong>英語</strong>での知見。日本語の対応物は未検証 |
| 構造（見出し・箇条書き・表・引用などの使い方） | [Stamatatos §2.5](../references/stamatatos-2009.md)の応用固有の特徴 | <strong>英語</strong>での知見。段落長・字下げ・挨拶や結びの型として挙げられている |
| 長さ（段落・節・項目の長さとそのばらつき） | 同上の<strong>拡張</strong>（平均ではなくばらつきを見る） | 上に加えて、<strong>拡張が元の特徴と同じ性質を持つ保証が無い</strong> |
| 文法形式の因子 | [中俣](../references/nakamata-multidimensional.md), [Neurobiber](../references/neurobiber-2025.md) | 中俣は日本語だが<strong>ジャンルの軸</strong>であり、著者識別では未検証。Neurobiber は 96 の文法形式で著者検証 F1 0.77 を出しているが、日本語の 89 形式での著者識別は未検証。D3 がジャンル固有であることは<strong>我々の読み</strong>である |

<strong>層 2 は測ってよいが、[効くかの判定](200-extract.md#どの指標が効くかを決める)を通るまで
は層 1 と同じ重さで扱わない。</strong>

### 層 3——系統に遡れないもの

<strong>どの系統から切り出したのかを言えないもの。</strong>[進行の実況](metrics/進行の実況.md)・
[脱線](metrics/脱線.md)・[対比構文](metrics/対比構文.md)・[自己否定の密度](metrics/自己否定の密度.md)
は、どれも語彙素や句を手で選んでいる。<strong>機能語の頻度分布のどの次元にも対応しない</strong>ので、
系統の裏付けを継ぐ足場が無い。

<strong>消さずに、層として立てる。</strong> 消せば、同じものがまた出どころ無しで入ってくる。

<strong>層 3 は測ってよいが、指摘にも判定にも使わない。</strong> 分離することが確かめられた時点で層を
上げる。判定から外すのは、<strong>止めた理由を言えないものは止めてはいけない</strong>からである
（[検め](300-revise.md#3-種類を合わせて通るを出す)）。

> [!NOTE]
> <strong>裏付けが薄いことと、遡れないことは別である。</strong> 長さの指標も構造の指標も、切り口それ自体
> を調べた報告は無い。<strong>だが[系統を名指しできる](#層-2別の目的の研究から取るもの)ので層 2
> になる</strong>——薄いことは層 2 という位置がすでに表している。

### 層は系統の属性である。指標は系統から引く

[判定に使う系統](200-extract.md#判定に使う系統を選ぶ)は層 1 だけから取り、指摘は層 3 を
外す。<strong>規則が層を見る以上、層は機械から引けなければならない。</strong>

<strong>だが層を指標ごとに書き写さない。</strong> 50 を超えるファイルに同じ値が散らばれば、系統の層が
変わったときに全部を直すことになり、直し忘れたものが古い層のまま残る
（[名前を 1 度しか書かない](#名前は-1-度しか書かない)と同じ事故）。

<strong>層は上の 3 つの表にだけ書く。指標は自分の系統を名指しし、層はそこから引く。</strong>

| | |
| --- | --- |
| 系統（`照合`） | <strong>自分が層のどれに属するかを、上の表が決めている</strong> |
| 指示できる指標 | <strong>[札](#定義に落とす)が名指しした系統の層を継ぐ</strong> |
| <strong>人らしさ</strong> | <strong>層を持たない</strong> |

<strong>人らしさに層が付かないのは、層が効く 2 か所のどちらにも入らないからである。</strong>
[判定に使う系統](200-extract.md#判定に使う系統を選ぶ)は照合の中から選び、
[指摘の 3〜4 本](300-revise.md#指摘は-3-本か-4-本に絞る)は指示できる指標から選ぶ。人らしさ
は[別の門](300-revise.md#3-種類を合わせて通るを出す)を通るので、層で振り分ける必要が無い。

<strong>そして層 1 とは呼べない。</strong> 出どころの[Zeng & Nini](../references/zeng-nini-2026.md)は
英語であり、扱っているのは書き手識別ではなく人と機械の別である。層 1 の定義
（日本語の書き手識別で確かめられているもの）に当てはまらない。<strong>実際、
[語彙の豊富さ](#使わないと決めたもの)は書き手識別では弱いと名指しされている側である。</strong>

### なぜ人らしさは、層 2 を判定から外す原則にかからないのか

<strong>[判定に使う系統](200-extract.md#判定に使う系統を選ぶ)から層 2 を外すのは、確かめられて
いないものを目盛りの土台にしないためである。</strong> 人らしさは層 1 とは呼べないのに、自分の
目盛りを持ち、[判定の 1 段目](300-revise.md#3-種類を合わせて通るを出す)に座る。<strong>矛盾して
見えるので、理由を書く。</strong>

<strong>層 2 を外すのは「借りた根拠が当てはまるか分からない」からである。</strong> 英語で著者を分けた
特徴が日本語でも分けるかは、当ててみるまで分からない。

<strong>人らしさは借りていない。</strong> 人と機械の境目は、<strong>手元の材料で実際に測る</strong>——本人の文書と
基準の出力から、その場で分布を出す（[評価](200-extract.md#人らしさの境目は同じ材料から出る)）。
先行研究から借りているのは <strong>どの量を見るか</strong> だけで、境目そのものは借りていない。

<strong>だから分離しなければ、その場で分かる。</strong> 2 つの分布が重なりきれば帯が全体を覆い、
1 段目は判定できないしか返さなくなる。<strong>当てはまらないことが、黙って通るのではなく、
判定不能として出る。</strong>

<strong>指示できる指標は、系統を札で名指しする。</strong> 出どころの散文から読み取らせない——リンクが
あるかどうかで層が変わるのでは、<strong>説明のために張ったリンクが層を上げてしまう。</strong>

```
指示 / 読点の打ち方 / 記号 / 両側 / 割合。   ← 系統を名指しした
指示 / なし / 語 / 上限 / 日本語 1,000 字あたり。   ← 名指しできない
```

| 札の系統 | 層 |
| --- | --- |
| 系統の名前 | <strong>その系統の層</strong> |
| `表記` `構造` `長さ` | 同じ名前の[定義ファイルを持たない系統](#層-2別の目的の研究から取るもの)の層 |
| <strong>`なし`</strong> | <strong>層 3</strong> |

<strong>`表記` `構造` `長さ` を系統名として書けるのは、この 3 つが定義ファイルを持たない系統
だからである。</strong> 切り口だけが指標として存在し、系統そのものは
[文書の形](020-document.md#表記は残る優先して採る理由がある)と上の層 2 の表が説明して
いる。

<strong>同じ分類に定義ファイルを持つ系統があっても、そちらとは別である</strong>——分類 `表記` には
[文字種](metrics/文字種.md)もあるが、それを使うなら `文字種` と名指しする。

<strong>書き漏らしは `なし` ではなく、書き漏らしとして落とす。</strong> 札の位置が埋まっていない定義
ファイルは、登録簿を組み立てる時点で弾く。<strong>`なし` は「調べた結果、名指しできないと判断
した」という表明であって、書き忘れの受け皿ではない。</strong>

### 較正されているのは、層 1 の一部である

[尤度比](../references/fusing-lr-2026.md)が日本語ブログ 1,000 字・2,287 人で較正した最良
は、<strong>文字 bigram・読点 bigram・文字種・単語埋め込み・文字埋め込み</strong>の 5 系統で、
Cllr 0.32484、EER 9.3% だった。

> [!WARNING]
> <strong>素材は技術記事ではない。</strong> 2008〜09 年の Yahoo! ブログの日記であり、しかも 1,000 字
> <strong>に切り詰めた</strong>ものである（「1,000 字以上」ではない）。<strong>論文自身がジャンル間の転移を
> 警告している。</strong> 長さが近いことだけを根拠にする。

<strong>機能語 unigram と品詞 bigram は、その組み合わせに入っていない。</strong> 単独では 7 系統中、
品詞 bigram が 4 位（0.54215）、機能語 unigram が 5 位（0.63002）である。<strong>どちらも最下位
ではない。</strong>

<strong>上の表は「較正済みの最良集合」ではない。</strong> 何が候補かを示す
だけで、どれが効くかは書き手と場面ごとに決まる
（[評価](200-extract.md#どの指標が効くかを決める)）。

<strong>そして 5 つのうち 2 つが埋め込みである。</strong> 埋め込みを外した集合でこの水準に届くとは
報告されていない。

### 埋め込みは保留する

<strong>禁じられてはいない。</strong>[数える側に LLM を置かない](010-strategy.md#数える側に-llm-を置かない)
が禁じているのは、判断が揺れることと循環することである。重みを固定した埋め込みは同じ
入力に同じベクトルを返すので、どちらも起きない。使うなら版を留め、
[指紋](200-extract.md#何で測ったかを指紋にする)にモデルと版を含める。

<strong>それでも、当面は使わない。</strong> 理由は 2 つある。

| | |
| --- | --- |
| <strong>定義が無い</strong> | [metrics/](metrics/)に数え方も次元も置いていない。[定義に落とす](#定義に落とす)を満たしていない以上、まだ指標ではない |
| <strong>日本語での裏付けが薄い</strong> | 公開されている多言語の文体埋め込みは、日本語部分が英語からの機械翻訳である（[mStyleDistance](../references/mstyledistance-2025.md)）。日本語で書かれた文章での挙動は確かめられていない |

<strong>したがって EER 9.3% は、当面の到達目標ではない。</strong> あの値は埋め込み 2 系統を含む組み
合わせのものである。<strong>計量文体論だけでどこまで行くかは、我々が測って知るしかない</strong>
（[骨格を先に通す](010-strategy.md#それでも骨格を先に通す)）。

### 通るための 2 条件を両方覆う

[通るには 2 つ要る](010-strategy.md#通るには-2-つ要る)。<strong>集合はその両方を覆う。</strong>

| 覆うもの | どういう指標か |
| --- | --- |
| その人らしい | 上の表 |
| <strong>人が書いたものに見える</strong> | <strong>繰り返し、エントロピー、圧縮率、語彙の豊富さ</strong> |

2 つ目を忘れやすい。だが GPT 系の生成文が人と判定される割合はほぼ 0% であり
（[Catch Me](../references/catch-me-2025.md)）、文体がどれだけ寄っても通らない。

<strong>寄せる向きも分かっている。</strong> 人の文章は繰り返しでできており、機械の文章は語彙が散り
すぎて繰り返せない。圧縮後の大きさ・エントロピー・Type-Token 比の 3 つとも、なりすまし
文の方が高かった（[Zeng & Nini](../references/zeng-nini-2026.md)）。<strong>圧縮後の大きさは
長さと連動するので、率にして持つ。</strong>

<strong>同じ集合の中に置き、同じ機械で測る。</strong> 別立てにすると、片方だけ測って通ったことに
する事故が起きる。

### 使わないと決めたもの

先行研究が <strong>効かないと報告している</strong>ものは入れない。

| | なぜ |
| --- | --- |
| 文の長さ、単語の長さ、漢字の使用率 | <strong>普通の人が書いた現代文では弱い</strong>と名指し（[金 2014](../references/jin-2014.md)） |
| 文字 n-gram の n が 3 以上 | 内容とジャンルの雑音を拾う（[金 2014](../references/jin-2014.md)） |
| 係り受け距離の分布 | 著者の特徴が現れない（[浅石](../references/asaishi-2017.md)） |

<strong>語彙の豊富さ（Type-Token 比）だけは、2 条件で扱いが割れる。</strong>

| 何に使うか | 採るか |
| --- | --- |
| その人らしさ | <strong>採らない。</strong> 上と同じ理由（[金 2014](../references/jin-2014.md)） |
| <strong>人らしさ</strong> | <strong>採る。</strong> なりすまし文の方が高い（[Zeng & Nini](../references/zeng-nini-2026.md)） |

<strong>同じ量が、片方では弱く、もう片方では効く。</strong> どちらに使っているかを取り違えない。

## 指標には 3 種類ある

<strong>集合を並べると、形の違うものが混ざる。</strong> 分けなければ、どちらの側でも使えないものが
できる。

| | <strong>系統</strong> | <strong>指示できる指標</strong> | <strong>人らしさ</strong> |
| --- | --- | --- | --- |
| 札 | `照合` | `指示` | `人らしさ` |
| 形 | 数百次元の頻度ベクトル | 1 つのスカラー | 1〜数次元のスカラー |
| 例 | 文字 bigram、品詞 bigram、埋め込み | 三点リーダの密度、接続詞直後の読点 | 繰り返し、エントロピー、圧縮率、語彙の豊富さ |
| 何と比べるか | <strong>本人の分布</strong> | <strong>本人の幅</strong> | <strong>人と機械の境目</strong> |
| 比べ方 | ベクトル間の距離 | 幅に入っているか | 境目のどちら側か |
| <strong>直し方</strong> | <strong>書けない。</strong>「342 次元目を増やせ」は指示にならない | 書ける | 書ける |
| 判定 | 使う | 使う | <strong>別立てで使う</strong> |
| 指摘 | 出てこない | <strong>3〜4 本を選んで渡す</strong> | [枠の外で渡す](300-revise.md#人らしさの直し方は書き直しに戻ることがある) |

<strong>系統と指示できる指標の割れ</strong>は[戦略](010-strategy.md#言うために何が要るか)の要るもの
1 と 4 の違いから来る。判定は距離で足りるが、<strong>言うには言葉にできる単位が要る。</strong>

<strong>人らしさが 3 つ目として立つ</strong>のは、比べる相手が違うからである。系統も指示できる指標も
<strong>その人</strong>と比べるが、人らしさは <strong>人という集団と機械という集団の境目</strong>と比べる。本人の
幅に入っているかを問うても意味が無い。

<strong>だから人らしさは、書きぶりの指摘と同じ枠を奪わない。</strong> 3〜4 本という上限は書きぶりの
側の話であり、人らしさはそこに数えない（[検め](300-revise.md#指摘は-3-本か-4-本に絞る)）。

### 指示できる指標は、系統の細い切り口である

<strong>2 つは別物ではない。</strong> 指示できる指標は、系統が見ている現象の一部を細く取り出したもの
である。

<strong>ここで 2 つの問いを混ぜない。</strong>

| 問い | 何に効くか |
| --- | --- |
| <strong>どの系統から切り出したか言えるか</strong> | <strong>層</strong>。言えなければ層 3 |
| その切り口そのものを調べた研究があるか | <strong>[指摘の順位](300-revise.md#指摘は-3-本か-4-本に絞る)</strong>。層には効かない |

<strong>層を後者で決めない。</strong> 決めれば、ほとんどの指標が層 3 に落ちる——「em dash の密度」や
「見出しの密度」をそれ自体として調べた報告は無く、<strong>残るのは接続詞直後の読点だけになる。</strong>
指摘に出せるものが尽きて、[3〜4 本](300-revise.md#指摘は-3-本か-4-本に絞る)が組めない。

<strong>層が問うのは、系統に遡れるかだけである。</strong> 遡れれば系統の層を継ぐ——<strong>裏付けの強さは
その層が表している。</strong> 層 2 の指標は「借りた根拠が当てはまるか分からない」ものとして扱われ
るので、切り口が調べられていないことは <strong>すでに層に入っている。</strong>

<strong>切り口まで調べられているものは、指摘で前に出す。</strong> 同じ外れの大きさなら、そちらを先に
言う。<strong>落とすのではなく、順序で効かせる。</strong>

そして切り口の細かさは、[規範の層を分ける](010-strategy.md#規範の層を分ける)の要求その
ものである。系統のまま渡せば規範に薄まり、細く切れば人が出る。

## 数え方は kakiburi が決める

先行研究から得られるのは <strong>何を見るか</strong> までである。<strong>どう数えるかは、
[文書の形](020-document.md)に合わせて決め直す。</strong>

論文の「文字 bigram」は、コードブロックも見出しも無い散文を前提にしている。技術記事に
そのまま当てれば、記号の率は書きぶりではなく題材で決まる。

### 粗い括りに丸めない

[規範の層を分ける](010-strategy.md#規範の層を分ける)を、数え方の側で実行する。

| 括り方 | 何が起きるか |
| --- | --- |
| 読点の密度 | 意味・長さ・構造で決まる分（誰もが打つ）が大半を占める |
| <strong>接続詞の直後の読点</strong> | <strong>語彙素ごとに打つ・打たないが分かれる。ここに人が出る</strong> |

先行研究の「読点の打ち方」も、細かく見れば読点の直前の文字、直後の文字、打つ間隔と
分かれている。<strong>ここが数え方でいちばん効く判断である。</strong>

### 解析は UniDic の短単位に合わせる

<strong>辞書を選ぶことは、品詞の体系を選ぶことである。</strong> 記録すれば済む話ではない——
どの語が接続詞かが辞書で変わり、[接続詞直後の読点](metrics/接続詞直後の読点.md)の
次元が消える。

<strong>外の表を語彙素で引く指標があるからである。</strong>

| 引く指標 | 引く先 |
| --- | --- |
| [語の文体値](metrics/語の文体値.md) | [馬場の表](../references/baba-2022.md)。BCCWJ の<strong>短単位・語彙素</strong>で作られている |
| [接続詞直後の読点](metrics/接続詞直後の読点.md) | [岩崎](../references/japanese-attribution-others.md)が挙げた語彙素。BCCWJ コアデータ |

<strong>別の体系で解析すれば、鍵が合わない。</strong> 語彙素の切り方が違えば引けない語が出る——
しかも <strong>0 件として静かに落ちる</strong>。

<strong>ほかの指標は辞書を選ばない。</strong> 文字 bigram も品詞 bigram も、タグが付けば足りる
（[金 2014](../references/jin-2014.md)は MeCab を使っている）。<strong>だが 1 つの解析結果を
全部で使う以上、引ける側に合わせる。</strong>

### 品詞は第 1 層で始める

<strong>[金 2014](../references/jin-2014.md)が第 1 層のタグの bigram を使っており、その構成が
日本語で確かめられているからである。</strong> 理由はそれだけで、細分類が悪いという根拠は無い。

> [!WARNING]
> <strong>むしろ逆を示す報告がある。</strong>[金 2013](../references/jin-2013.md)はタグの取り方を
> 4 通り比べ、作文 11 人と日記 6 人では <strong>第 2 層（C）が最良</strong>だった——98.91%、91.75%。
> （文学作品では別の型が最良で、層の優劣は素材で入れ替わる。）
>
> <strong>第 1 層で始めるのは暫定である。</strong> 骨格が通ったら第 2 層と比べる。bigram にすると
> 次元が跳ねるので、[語彙の固定](200-extract.md#語彙は先に決めて固定する)と合わせて測る。

<strong>辞書と版は[指紋](200-extract.md#何で測ったかを指紋にする)に入る。</strong> 体系を選んだうえで、
なお版で値が動くからである。

### 決定的に計算できること

同じ文章から同じ値が出る（[決定](010-strategy.md#数える側に-llm-を置かない)）。

<strong>これは検査ではなく設計の制約である。</strong> 満たさない数え方は、実験して落とすのではなく、
最初から書かない。

### 定義に落とす

1 行目が見出しとしての名前、<strong>空行を挟んだ次の行が札</strong>である。札は種類によって形が違う。

```
指示 / 読点の打ち方 / 記号 / 両側 / 割合。       ← 指示できる指標
指示 / なし / 語 / 上限 / 日本語 1,000 字あたり。 ← 系統を名指しできない（層 3）
照合 / 表記。                                    ← 系統
人らしさ / 上限。                                ← 人らしさ
```

| 位置 | 意味 | どの種別が持つか |
| --- | --- | --- |
| 1 | <strong>種別。</strong>`指示` / `照合` / `人らしさ` | 全部 |
| 2 | <strong>系統。</strong> 系統の名前、または `なし` | <strong>`指示`</strong> |
| 3 | <strong>分類。</strong> 記号 / 表記 / 語 / 品詞 / 構造 / 長さ / 埋め込み | `指示` `照合` |
| 4 | 向き。`上限` `下限` `両側` | `指示` `人らしさ` |
| 5 | 単位 | `指示` |

<strong>持たない位置は詰める。</strong> だから `人らしさ` の札は 2 つになる（`人らしさ / 上限。`）。
位置ではなく <strong>種別が形を決める</strong>ので、読む側は種別を見てから残りを解釈する。

<strong>層は札に持たせない</strong>（[層は系統の属性である](#層は系統の属性である指標は系統から引く)）。

持つ項目も種類で違う。<strong>どれか 1 つでも欠けているものは、まだ指標ではない。</strong>

| | 指示 | 照合 | 人らしさ |
| --- | --- | --- | --- |
| 意味 | 要る | 要る | 要る |
| <strong>出どころ</strong> | <strong>要る</strong> | <strong>要る</strong> | <strong>要る</strong> |
| 数え方 | 要る | 要る | 要る |
| 次元 | — | <strong>要る</strong> | <strong>要る</strong> |
| 除外 | [既定でよい](#除外の既定)。<strong>割合の指標は必須</strong> | [既定でよい](#除外の既定) | [既定でよい](#除外の既定) |
| <strong>直し方</strong> | <strong>要る</strong> | <strong>書かない</strong> | <strong>要る</strong> |

<strong>出どころを必ず書く。</strong> 出どころのあるものと思いつきを見分けられなくなれば、
[指標を発明しない](010-strategy.md#指標を発明しない)という前提が崩れる。指示できる指標
の出どころは、<strong>どの系統の、どの切り口か</strong>の形になる。

<strong>直し方は向きの数だけ書く。</strong>`両側` なら上と下の両方。片方しか無ければ、直す側は指摘を
消すために削る方へ向かう。<strong>片方しか書けないなら、それは `両側` ではない。</strong>

<strong>意味と数え方は別に書く。</strong> 名前だけでは数え方が決まらない。「見出しの密度」と書いて
あっても、深さを区別したか、タイトルを数えたかは分からない。決め方ひとつで値は倍も
変わる。

### 除外の既定

<strong>分母が小さいと値が暴れる。</strong> 段落が 3 つしかない文書で段落長のばらつきを測っても、
書きぶりではなく偶然を測ることになる。

<strong>だが同じことを 50 ファイルに書き写さない。</strong> 単位ごとの既定をここで 1 度だけ決める。

| その指標の分母 | 既定の下限 |
| --- | --- |
| 日本語の文字 | 1,000 |
| 文 | 20 |
| 段落 | 5 |
| 節 | 3 |
| node（見出し・箇条書き・表など） | 3 |
| 項目 | 5 |

<strong>下回った文書では、その指標を測らない。</strong> 0 を返さない——0 は「使わなかった」という
値であり、「測っていない」とは別である（[評価](200-extract.md#下限は使った割合で見る)）。

定義ファイルが `除外` を書くのは、<strong>既定と違うときだけ</strong>である。書いていなければ既定が
効く。<strong>既定と同じ値を書き写さない</strong>——書き写せば、既定を導き直したときにそこだけ古い
値が残る。

### 分母がその現象自身のときは、必ず書く

<strong>既定の表で決まらないものがある。</strong>「感嘆符のうち半角の割合」「接続詞の直後に読点を打つ
割合」のように、<strong>分母がその現象の出現回数そのもの</strong>である指標である。

文書がどれだけ長くても、感嘆符が 2 つしか無ければ半角率は 0 か 0.5 か 1 にしかならない。
<strong>日本語 1,000 字という下限は、この暴れを止めない。</strong>

<strong>割合の指標は `除外` を必ず書く。</strong> 分母となる出現回数の下限を、指標ごとに置く。書いて
いなければ、その指標はまだ定義されていない。

<strong>1,000 字を除いて、すべて暫定値である</strong>（[戦略](010-strategy.md#それでも骨格を先に通す)）。
1,000 字は先行研究が揃って採っている長さ（[財津・金](../references/zaitsu-2018.md),
[尤度比](../references/fusing-lr-2026.md), [金 2013](../references/jin-2013.md)）から取った
が、<strong>残りに出どころは無い。</strong> 骨格が通ったら、値が暴れ始める点を測って導き直す。

<strong>[文書の形](020-document.md#数える単位)が定める単位は、すべてあちらが決める。</strong> 地の文、
日本語の文字、文、段落、節、項目、見出しの深さ。<strong>指標ごとに決め直さない。</strong> 数え方の節
で「節は深さ 2 の見出しで区切る」のように書き直せば、同じ名前が指標によって違うものを
指すことになり、[文書の形](020-document.md)を置いた意味が消える。

## 集合は広く持つ。絞るのはあとである

<strong>この集合から指標を落とさない。</strong> 誰にどれが効くかは、ここでは決まらない。

<strong>費用が非対称だからである。</strong> 入れる費用は測る手間が少し増えるだけだが、外す損失は、
その指標が決め手になる書き手を永久に取りこぼすことである。<strong>外すには理由が要り、入れる
には要らない。</strong>

### 目の前の書き手で効かないことは、落とす理由にならない

ある書き手の幅が、基準の幅のちょうど内側に収まることはある。<strong>分離していない。</strong>

このとき外してはいけない。分離しなかったのは指標に力が無いからではなく、<strong>この書き手が
その点で基準と似ていた</strong>からである。同じ手法で 5 人になりすまさせると成功率が 0.11 から
0.77 まで開き、どの手法が最良かも人によって入れ替わる
（[Masks and Mimicry](../references/masks-mimicry-2025.md)）。

### 1 つの場面で効かないことも、落とす理由にならない

絵文字は技術記事ではどの書き手も 0 が並ぶ。だがチャットでは書き手を強く分ける。

<strong>ある場面で死んでいることは、その場面で使わない理由にはなるが、集合から外す理由には
ならない。</strong>

### 単独で弱いことも、落とす理由にならない

[決定](010-strategy.md#単独で弱いことは落とす理由にならない)のとおり、判別力の順位で
指標を落とさない。日本語の文学作品 10 人で文節パターンは単独 F1 0.704 の最下位だったが、
最良の組み合わせには必ず入っていた
（[統合アンサンブル](../references/japanese-attribution-recent.md)）。

### 落としてよいのは、重複しているとき

名前が違うだけで同じものを測っている指標は、片方を外す。<strong>出どころが違うだけで、数え方
が同じになった</strong>ときに起きる。

残す方を選ぶ基準は、定義が単純な方、除外の少ない方、意味を 1 文で言える方である。

## 集合が変わるとき

<strong>集合は固定ではない。だが変わる理由は 2 つしかない。</strong>

| 理由 | どうする |
| --- | --- |
| <strong>先行研究が増えた</strong> | 出どころを付けて足す |
| <strong>本人が「違う」と言い、数値は通ると言った</strong> | 本人の指摘から足す |

2 つ目が、この道具で唯一の内向きの入口である
（[検め](300-revise.md#本人が違うと感じたら)）。本人が挙げるのは表層の異物——特定の記号、
特定の語、飾りの多さ——であり、<strong>そのまま指標にできることが多い。</strong> 出どころには
「本人の指摘」と書く。

<strong>逆は入口にならない。</strong> 本人が受け入れたことは、集合が足りている証拠にならない
（[決定](010-strategy.md#本人の読みは判定ではなく候補として使う)）。

### 思いつきでは足さない

<strong>出どころの無い指標を入れない。</strong> 入れれば、確かめられていない指標が確かめられた指標
と同じ顔で並ぶ。そして集合が広いほど <strong>偶然効いて見える指標が増える</strong>。30 の指標を 7 本
の文書で測れば、いくつかはまぐれで揃う。

思いついたものは、まず <strong>先行研究に同じものがないかを探す</strong>。無ければ入れない。

## 場面で成立しないことがある

<strong>この集合が、どの場面でも成立するとは限らない。</strong>

| 場面 | 素材 | 到達点 |
| --- | --- | --- |
| 技術記事 | [ブログ 1,000 字、2,287 人](../references/fusing-lr-2026.md) | <strong>EER 9.3%</strong>（埋め込み 2 系統を含む） |
| 日記 | [500 字、6 人](../references/jin-2014.md) | F1 98.4 |
| <strong>チャット</strong> | [レビュー 60 字、100 人](../references/japanese-attribution-recent.md) | <strong>88%</strong> |

<strong>落ちる理由は 2 つあり、別々である。</strong>

| | |
| --- | --- |
| <strong>短くなる</strong> | 短い非形式文では<strong>定型文・情報不足・話題語彙</strong>が邪魔をする |
| <strong>候補が増える</strong> | 同じ 60 字でも、100 人で 88%、<strong>1,000 人で 51%</strong> |

2 つ目は長さの問題ではない。混同すると、字数を増やせば解けるという誤った見込みを持つ。

<strong>成立しない場面が見つかったときに落とすのは、指標ではなく場面である。</strong>
[検め](300-revise.md#当てにならないときは言う)が「判定できない」を返す。

そして技術記事については、<strong>コードブロックや見出しを含む文書での検証は誰もやっていない</strong>
（[まだ残っている穴](../references/japanese-attribution-others.md#まだ残っている穴)）。
<strong>ここは我々が確かめるしかない。</strong> 確かめるまでは、成立を前提にしない。

## 実装に組みこむ

集合は先行研究が増えれば増える。<strong>1 つ足すのに何か所も直す必要があれば、そこで止まる。</strong>

### 定義は 1 指標 1 ファイル

指標の定義は仕様である。実装が何を計算すべきかを決めるものだからである。
[metrics/](metrics/)に 1 指標 1 ファイルで置く。

1 つにまとめない。指標を足し引きするたびに同じファイルを編集することになる。

### 名前は 1 度しか書かない

<strong>同じ指標の名前が 2 か所にあってはいけない。</strong> 測った値の側に名前があって幅の側に無け
れば、その指標は <strong>黙って発火しなくなる</strong>。エラーにならず、動き続けて、結果だけが変わる。

<strong>落ちてくれるなら気付けるが、落ちないので気付けない。</strong> 実装が返す名前と定義にある名前
が一致していることは機械で確かめ、どちらか一方にしか無い名前があれば落ちるようにする。

### 使う側は一覧を持たない

指標を使うところ——指示を作る、外れを出す、値を保存する、中身を覗く——は、指標の一覧を
自分で書かない。定義を回す。

自分で書けば、足した指標が一部にしか現れない。現れていないことにも気付かない。

### 数え方はまとめてよい

定義が 1 か所であることと、実装が指標ごとに割れていることは別である。1 度の走査でまとめ
て数えられるものを分けても、走査が増えるだけで得るものが無い。

### 測るのを安くする

[ループ](010-strategy.md#使うときはループになる)は 1 周ごとに測り直す。測るのが高ければ
周回数が減り、そのまま品質が落ちる。3 つを直接使えるようにする。

- 1 本を測る
- 2 本を比べる
- コーパス全体の分布を出す

### 測った値は置かない

ある書き手を測った値は、その書き手のものであって、この道具の仕様ではない。置き場所は
[評価](200-extract.md#3-つに分けて持つ)が作る成果物の中であり、リポジトリの文書ではない。

同じ理由で、どの場面で効いた・効かなかったという判定も、定義のファイルに書かない。
<strong>コーパスと場面が変われば変わる。</strong> 書き留めた状態は必ず古くなり、古い状態は無いより
悪い。
