# 指標を決める

曖昧な書きぶりを、定量評価できる指標の集合として
定義する。

<strong>指標は借りる。</strong> 何が書き手を分けるかは、日本語の書き手識別で 30 年かけて確かめられて
いる（[先行研究](../references/)）。<strong>kakiburi が決めるのは、それを kakiburi の文書モデル
の上でどう数えるかだけである。</strong>

自前で候補を思いつき、実験し、採否を決める——という手続きは持たない。<strong>やっても、既に
確かめられていることを確かめ直すことにしかならない。</strong>

## 何を借りるか

日本語のブログ・作文・日記・文学作品で、繰り返し採られている顔ぶれがある。

| 特徴 | 出どころ |
| --- | --- |
| <strong>文字 bigram</strong> | [金 2014](../references/jin-2014.md), [尤度比](../references/fusing-lr-2026.md), [柳・金](../references/yanagi-jin-2022.md) |
| <strong>機能語</strong>（助詞・助動詞・接続詞・副詞・感動詞） | [財津・金](../references/zaitsu-2018.md), [水上ほか](../references/mizukami-2014.md), [Writeprints](../references/writeprints-liwc.md) |
| <strong>品詞 bigram</strong> | [金 2014](../references/jin-2014.md), [財津・金](../references/zaitsu-2018.md) |
| <strong>読点の打ち方</strong> | <strong>日本語の主要な 4 本すべてに入っている</strong> |
| <strong>文字種</strong> | [尤度比](../references/fusing-lr-2026.md) |
| 文節パターン | [金 2013](../references/jin-2013.md), [柳・金 2023](../references/yanagi-jin-2023.md) |
| 文末表現 | [有馬ら](../references/arima-2018.md) |
| 語の文体値 | [馬場](../references/baba-2022.md) |
| 表記の選択 | [Wegmann](../references/wegmann-2022.md), [文書の形](020-document.md#揃えても残るもの表記の選択) |
| 文法形式の因子 | [中俣](../references/nakamata-multidimensional.md), [Neurobiber](../references/neurobiber-2025.md) |

上の 5 つは <strong>日本語ブログ 2,287 人で Cllr 0.325、EER 9.3%</strong> を出した組み合わせである
（[尤度比](../references/fusing-lr-2026.md)）。<strong>技術記事とほぼ同じ長さと素材で較正されて
いる。</strong>

### 通るための 2 条件の両方を覆う

| 覆うもの | どういう指標か |
| --- | --- |
| その人らしい | 上の表 |
| <strong>人が書いたものに見える</strong> | <strong>繰り返し、エントロピー、Type-Token 比、圧縮後の大きさ</strong> |

2 つ目を忘れやすい。だが GPT 系の生成文が人と判定される割合はほぼ 0% で、<strong>文体が
どれだけ寄っても通らない</strong>（[Catch Me](../references/catch-me-2025.md),
[軸](000-axis.md#通るには-2-つ要る)）。同じ集合の中に置き、同じ機械で測る。

### 借りないと決めたもの

先行研究が <strong>効かないと報告している</strong>ものは入れない。

| | なぜ |
| --- | --- |
| 文の長さ、単語の長さ、漢字の使用率 | <strong>普通の人が書いた現代文では弱い</strong>と名指し（[金 2014](../references/jin-2014.md)） |
| 文字 n-gram の n が 3 以上 | 内容とジャンルの雑音を拾う（[金 2014](../references/jin-2014.md)） |
| 係り受け距離の分布 | 著者の特徴が現れない（[浅石](../references/asaishi-2017.md)） |

<strong>語彙の豊富さ（Type-Token 比）は 2 条件で扱いが割れる。</strong> 著者識別の特徴としては
上と同じ理由で採らない（[金 2014](../references/jin-2014.md)）。だが <strong>人らしさの指標
としては採る</strong>——なりすまし文は Type-Token 比が高い、という報告がある
（[Zeng & Nini](../references/zeng-nini-2026.md)）。<strong>同じ量が、片方では弱く、もう片方
では効く。</strong> 出どころを見れば取り違えない。

## 指標には 2 種類ある

<strong>借りた集合を並べると、形の違う 2 つが混ざる。</strong> これを分けないと、どちらの側でも
使えないものができる。

| | <strong>系統</strong> | <strong>指示できる指標</strong> |
| --- | --- | --- |
| 形 | 数百次元の頻度ベクトル | 1 つのスカラー |
| 例 | 文字 bigram、品詞 bigram、機能語の頻度 | 三点リーダの密度、接続詞直後の読点 |
| 比べ方 | ベクトル間の距離 | 幅に入っているか |
| <strong>直し方</strong> | <strong>書けない</strong>（「342 次元目を増やせ」は指示にならない） | 書ける |
| 使い道 | <strong>[検める](300-revise.md)。目盛りと組み合わせ判定</strong> | <strong>[指摘する](300-revise.md)。3〜4 本を選んで渡す</strong> |

<strong>系統は指摘に出てこない。指示できる指標は判定にも使う。</strong>

### 指示できる指標は、系統の細い切り口である

<strong>2 つは別物ではない。</strong>「文末が『かもしれない』で終わる割合」は、文末表現という系統の
1 次元を取り出したものである。「文頭が『とはいえ』である割合」は機能語の 1 次元である。

<strong>だから出どころは系統に遡れる。</strong> 遡れないものは、借りたものではない
（[思いつきでは足さない](#思いつきでは足さない)）。

そして切り口の細かさは、[規範の層を分ける](#規範の層を分ける)の要求そのものである。
系統のまま渡せば規範に薄まり、細く切れば人が出る。

## 数え方は kakiburi が決める

借りられるのは <strong>何を見るか</strong> までである。<strong>どう数えるかは、kakiburi の文書モデルに
合わせて決め直す。</strong>

論文の「文字 bigram」は、コードブロックも見出しも無い散文を前提にしている。技術記事に
そのまま当てれば、記号の率は書きぶりではなく題材で決まる。

### 規範の層を分ける

1 つの現象の中に、<strong>誰もがやること</strong>と <strong>人によって違うこと</strong>が混ざっている
（[軸](000-axis.md#規範の層がある)）。<strong>粗く括ると規範に薄められる。</strong>

| 括り方 | 何が起きるか |
| --- | --- |
| 読点の密度 | 意味・長さ・構造で決まる分（誰もが打つ）が大半を占める |
| <strong>接続詞の直後の読点</strong> | <strong>語彙素ごとに打つ・打たないが分かれる。ここに人が出る</strong> |

<strong>ここが数え方でいちばん効く判断である。</strong> 先行研究の「読点の打ち方」も、細かく見れば
読点の直前の文字、直後の文字、打つ間隔と分かれている。<strong>粗い方に丸めない。</strong>

### 定義に落とす

ファイルの 1 行目は名前、2 行目は <strong>札</strong> である。札は種類によって形が違う。

```
指示 / 記号 / 両側 / 日本語 1,000 字あたり。     ← 指示できる指標
照合 / 表記。                                    ← 系統
```

| 位置 | 意味 |
| --- | --- |
| 1 | <strong>種別</strong>。`指示` か `照合` |
| 2 | <strong>分類</strong>。記号 / 表記 / 語 / 品詞 / 構造 / 長さ / 人らしさ |
| 3 | 向き（指示のみ）。`上限` `下限` `両側` |
| 4 | 単位（指示のみ） |

持つ項目も種類で違う。<strong>どれか 1 つでも欠けているものは、まだ指標ではない。</strong>

| | 指示 | 照合 |
| --- | --- | --- |
| 意味 | 要る | 要る |
| <strong>出どころ</strong> | <strong>要る</strong> | <strong>要る</strong> |
| 数え方 | 要る | 要る |
| 次元 | — | <strong>要る</strong> |
| 除外 | 要る | 要る |
| <strong>直し方</strong> | <strong>要る</strong> | <strong>書かない</strong> |

<strong>出どころを必ず書く。</strong> 借りたものと思いつきを見分けられなくなると、この戦術の前提が
崩れる。出どころの無い指標は、入れる前に出どころを探す。指示できる指標の出どころは、
<strong>どの系統の、どの切り口か</strong> の形になる。

<strong>直し方は向きの数だけ書く。</strong>`両側` なら上と下の両方。片方しか無ければ、
[検め](300-revise.md#外れを出す)が警告する失敗——指摘を消そうとする側が削る方へ向かう——
が、定義の側から保証されてしまう。<strong>片方しか書けないなら、それは `両側` ではない。</strong>

「地の文」「日本語の文字」「文」「段落」の意味は
[文書の形](020-document.md) が決める。指標ごとに決め直さない。

<strong>意味と数え方は別に書く。</strong> 名前だけでは数え方が決まらない。「見出しの密度」と
書いてあっても、深さを区別したか、タイトルを数えたかは分からない。決め方ひとつで値は
倍も変わる。

<strong>除外を持つ。</strong> 分母が小さいと値が暴れる。段落が 3 つしかない文書で段落長のばらつき
を測っても、書きぶりではなく偶然を測ることになる。

### 決定的に計算できること

同じ文章から同じ値が出る（[軸](000-axis.md)の性質 5、
[戦略](010-strategy.md#数える側に-llm-を置かない)）。

<strong>これは検査ではなく設計の制約である。</strong> 満たさない数え方は、実験して落とすのではなく、
最初から書かない。

## 集合は広く持つ。絞るのはあとである

<strong>借りた集合から指標を落とさない。</strong> 誰にどれが効くかは、ここでは決まらない。

### 目の前の書き手で効かないことは、落とす理由にならない

ある書き手の幅が、基準の幅のちょうど内側に収まることはある。読点の密度が本人 25、
基準 15 から 35、というような形である。<strong>分離していない。</strong>

このとき外してはいけない。分離しなかったのは、その指標に力が無いからではなく、
<strong>この書き手がその点で基準と似ていた</strong> からである。何が特徴になるかは人によって違う
（[軸](000-axis.md#何が特徴になるかも人による)）。

効くかどうかは書き手ごとに決まる（[評価](200-extract.md#どの指標が効くかを決める)）。

### 1 つの場面で効かないことも、落とす理由にならない

絵文字は技術記事ではどの書き手も 0 が並ぶ。だがチャットでは書き手を強く分ける。

<strong>ある場面で死んでいることは、その場面で使わない理由にはなるが、集合から外す理由には
ならない。</strong>

### 単独で弱いことも、落とす理由にならない

<strong>判別力の順位で指標を落としてはいけない。</strong>

日本語の文学作品 10 人の実験で、文節パターンは <strong>単独では F1 0.704 で最下位</strong>だった。
それでも <strong>最良の組み合わせには必ず入っている</strong>
（[統合アンサンブル](../references/japanese-attribution-recent.md)）。

逆のことも起きる。日本語ブログ 2,287 人の実験では、単独で中位だった機能語 unigram が
<strong>最良の組み合わせから落ちた</strong>（[尤度比](../references/fusing-lr-2026.md)）。

<strong>効くのは組み合わせであって、単独の順位ではない。</strong> これは
[特徴は頻度で選ぶ](../references/stamatatos-2009.md)——判別力で選抜するのは話題分類の
作法である——という総説の指摘と、別の理由から同じところを指している。

### 落としてよいのは、重複しているとき

名前が違うだけで同じものを測っている指標は、片方を外す。<strong>借りた先が違うだけで、
数え方が同じになった</strong>ときに起きる。

残す方を選ぶ基準は、定義が単純な方、除外の少ない方、意味を 1 文で言える方である。

それ以外では外さない。入れる費用は測る手間が少し増えるだけだが、外す損失は、その指標
が決め手になる書き手を永久に取りこぼすことである。<strong>費用が非対称なので、外すには理由が
要り、入れるには要らない。</strong>

## 集合が変わるとき

<strong>集合は固定ではない。だが変わる理由は 2 つしかない。</strong>

| 理由 | どうする |
| --- | --- |
| <strong>先行研究が増えた</strong> | 出どころを付けて足す |
| <strong>本人が「違う」と言い、数値は通ると言った</strong> | 本人の指摘から足す |

2 つ目が、この道具で唯一の内向きの入口である。数値が通ると言い、本人が違うと言うなら、
<strong>足りないのは指標である</strong>（[検め](300-revise.md#本人が違うと感じたら)）。

<strong>逆は入口にならない。</strong> 本人が受け入れたことは、集合が足りている証拠にならない
（[戦略](010-strategy.md#本人の読みは判定ではなく候補として使う)）。

本人が挙げるのは表層の異物——特定の記号、特定の語、飾りの多さ——である。<strong>そのまま
指標にできることが多い。</strong> 出どころには「本人の指摘」と書く。

### 思いつきでは足さない

<strong>出どころの無い指標を入れない。</strong> 入れれば、確かめられていない指標が確かめられた指標
と同じ顔で並ぶ。そして集合が広いほど、<strong>偶然効いて見える指標が増える</strong>。30 の指標を
7 本の文書で測れば、いくつかはまぐれで揃う。

思いついたものは、まず <strong>先行研究に同じものがないかを探す</strong>。無ければ入れない。

## 場面で成立しないことがある

<strong>借りた集合が、どの場面でも成立するとは限らない。</strong>

| 場面 | 素材 | 到達点 |
| --- | --- | --- |
| 技術記事 | [ブログ 1,000 字、2,287 人](../references/fusing-lr-2026.md) | <strong>EER 9.3%</strong> |
| 日記 | [500 字、6 人](../references/jin-2014.md) | F1 98.4 |
| <strong>チャット</strong> | [レビュー 60 字、100 人](../references/japanese-attribution-recent.md) | <strong>88%</strong>（1,000 人で 51%） |

短い非形式文では <strong>定型文・情報不足・話題語彙</strong> の 3 つが邪魔をする。

<strong>成立しない場面が見つかったときに落とすのは、指標ではなく場面である。</strong>
[検め](300-revise.md#当てにならないときは言う)が「判定できない」を返す。

そして技術記事については、<strong>コードブロックや見出しを含む文書での検証は誰もやっていない</strong>
（[まだ残っている穴](../references/japanese-attribution-others.md#まだ残っている穴)）。
<strong>ここは我々が確かめるしかない。</strong> 確かめるまでは、成立を前提にしない。

## 実装に組みこむ

集合は先行研究が増えれば増える。<strong>1 つ足すのに何か所も直す必要があれば、そこで止まる。</strong>

### 定義は 1 指標 1 ファイル

指標の定義は仕様である。実装が何を計算すべきかを決めるものだからである。
[metrics/](metrics/) に 1 指標 1 ファイルで置く。

1 つにまとめない。指標を足し引きするたびに同じファイルを編集することになる。

### 実装も 1 指標 1 エントリ

[定義の項目](#定義に落とす)を、すべて 1 つのエントリに入れる。足すのはエントリを 1 つ
増やすこと、外すのは 1 つ消すことで終わる。

### 名前は 1 度しか書かない

同じ指標の名前が 2 か所にあってはいけない。測った値の側に名前があって幅の側に無ければ、
その指標は <strong>黙って発火しなくなる</strong>。エラーにならない。動き続けて、結果だけが変わる。
落ちてくれるなら気付けるが、落ちないので気付けない。

### 使う側は一覧を持たない

指標を使うところ——指示を作る、外れを出す、値を保存する、中身を覗く——は、指標の一覧を
自分で書かない。定義を回す。

自分で書くと、足した指標が一部にしか現れない。現れていないことにも気付かない。

### 数え方はまとめてよい

定義が 1 か所であることと、実装が指標ごとに割れていることは別である。1 度の走査でまとめ
て数えられるものを分けても、走査が増えるだけで得るものが無い。

ただし、実装が返す名前と定義にある名前が一致していることは機械で確かめる。どちらか一方
にしか無い名前があれば落ちるようにする。

### 測るのを安くする

[使うループ](010-strategy.md#使うときはループになる)は、1 周ごとに測り直す。測るのが
高ければ、周回数が減り、そのまま品質が落ちる。

3 つを、直接使えるようにする。

- 1 本を測る
- 2 本を比べる
- コーパス全体の分布を出す

### 測った値は置かない

ある書き手を測った値は、その書き手のものであって、この道具の仕様ではない。置き場所は
[評価](200-extract.md) が作る成果物の中であり（[評価](200-extract.md)）、リポジトリの文書ではない。

同じ理由で、どの場面で効いた・効かなかったという判定も、定義のファイルに書かない。
<strong>コーパスと場面が変われば変わる。</strong> 書き留めた状態は必ず古くなり、古い状態は無いより
悪い。
