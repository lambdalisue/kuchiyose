# 評価して、その人の値と目盛りにする

本人が書いたものを指標で評価し、外に出せる
値に変える。<strong>同じ材料から、値を読むための目盛りも作る。</strong>

## 場面ごとに分ける

集めた文章は場面ごとに分けて評価する。混ぜたものは、どの場面のものでもない
中間になる。

<strong>場面の寄与は人の寄与と同じ大きさである。</strong> クロスエントロピーで測ると、同じ人でも
役割が変われば +0.77、違う人でも役割が同じなら +0.85
（[水上ほか](../references/mizukami-2014.md)）。混ぜると、<strong>測っているものの半分が場面に
なる。</strong>

場面は人が指定する。相手も立ち位置も目的も文章の外にあるので、文章から当てに
いけば外す。

## 基準を置く

値だけでは、それが特徴なのか普通なのかが分からない。比べる相手を置く。

置くのは LLM が既定で書いたものである。代筆で直したいのがそれだからである。

基準は同じ場面で、できるだけ同じ題材のものを使う。題材が揃っていないと、題材の
差が本人らしさとして出る（[指標](100-metrics.md)）。

<strong>基準を作らせる依頼文に、書き方を漏らさない。</strong> 本文の書き出しをそのまま依頼文に
使うと、書き出しの癖が手掛かりとして漏れ、基準値が <strong>28 ポイント</strong>膨らんだ例がある
（[Sawant](../references/authorship-gap-2026.md)）。依頼文は「何について書くか」の中立な
要約にする。

### 基準はモデルの版まで記録する

<strong>基準は使う LLM ごとに違う。しかも版ごとに違う。</strong> 日本語では、同一系列の版の違い
だけで <strong>93.6%</strong> 識別できる（[林・相澤](../references/japanese-llm-style.md)）。

モデル名だけでは足りない。<strong>版と推論設定まで記録する。</strong> 記録が無い基準で作った値は、
次に測ったときに比べられない。

## 単位は 1 文書

指標は文書ごとに測る。全部を連結して 1 度に測ると、分布が消えて 1 点になる。

1 文書では指標が意味を持たないほど短いものは、何本かをまとめて 1 単位にする。

## 値は幅で持つ

1 点にしない。同じ人でも文書ごとに揺れるので、平均だけを持つと、その人が現に
書いている書き方まで外れと判定される。

書きぶりは幅である。実際に振れた範囲を持つ。

## 目盛りを作る

指標ごとの幅は、その指標が外れたかを言う。だが <strong>全体として通ったか</strong> は言わない。
全体の判定には、<strong>どこからが本人でどこからが他人か</strong> の目盛りが要る
（[戦略](010-strategy.md#目盛りを作る)）。

同じ材料から作れる。

| | 何と何を比べるか | 何本要るか |
| --- | --- | --- |
| <strong>天井</strong> | 本人の文章どうし | 本人の文書を総当たり |
| <strong>床</strong> | 本人の文章と、基準（LLM の既定出力） | 本人 × 基準 |

<strong>天井は「本人の揺れ」である。</strong> 同じ人が書いたもの同士でも完全には一致しない。
そこまで来れば十分だという上限になる。

<strong>床は「何もしていない状態」である。</strong> ここを超えなければ、LLM に素で書かせたのと
変わらない。

2 つの分布の重なり具合から、<strong>判定できない帯</strong>が決まる（[検め](300-revise.md#全体の判定は-3-値で返す)）。

### 他人が手に入るなら、床をもう 1 つ置く

LLM に対する床は「良くなったか」を言う。<strong>「本人のものとして通るか」は言わない。</strong>

他人の文章に対する床があれば、そちらが言える（[財津・金](../references/zaitsu-2018.md)
の無関係テキスト）。手に入るなら足す。

<strong>ただし無くても成立する設計にする。</strong> 複数の書き手のコーパスが集まるかは確かめて
いない。確かめていない前提の上に必須の仕組みを建てない。

### 目盛りも値である

天井と床は、指標の集合と基準と素材から導かれる派生物である。<strong>保存はするが、原本では
ない。</strong> 指標が入れ替われば作り直す（[作り直せるようにする](#作り直せるようにする)）。

## どの指標が効くかを決める

指標の集合は誰にでも当てる。<strong>だが際立つ指標は人によって違う。</strong> 同じ手法で 5 人に
なりすまさせると成功率が 0.11 から 0.77 まで開く
（[Masks and Mimicry](../references/masks-mimicry-2025.md)）。

<strong>ここで決まるのは選択であって、採否ではない。</strong> 集合から落ちる指標は無い
（[指標](100-metrics.md#集合は広く持つ絞るのはあとである)）。効かないと判定しても、
その書き手のこの場面で前に出さないというだけである。

効くかどうかは 3 つで見る。

| | 何を見るか | いつ分かるか |
| --- | --- | --- |
| 1 | その人の幅が狭い（一貫している） | ここで |
| 2 | 基準から離れている（その人に固有である） | ここで |
| 3 | <strong>指摘して動く</strong> | <strong>直させてみて初めて</strong> |

3 つ目は[軸](000-axis.md)からではなく、直す側の事情から来る。<strong>制御できるスタイルと
制御困難なスタイルがあり、その違いはモデルの種類に依存しない</strong>
（[高橋ら](../references/japanese-llm-style.md)）。動かない指標を指摘しても、
限られた枠を潰すだけである。

3 つ目はここでは分からない。<strong>直させて測った結果を、ここに返す</strong>
（[検め](300-revise.md#直したら測り直す)）。返ってくるまでは 1 と 2 だけで決め、
動くかどうかは未知として扱う。

<strong>動かないと分かっても、集合からは外さない。</strong> 判定には効く。落ちるのは
指摘に選ぶときだけである。

### 離れているかの判定

素材は少なく、統計的な検定に足りる件数は集まらない。範囲の交わり方で見る。

| 形 | 判定 |
| --- | --- |
| 交わらない | 離れている |
| 一方が他方を完全に含む | 離れていない。含む側は「その値も取りうる」としか言っていない |
| 端が重なる | 重なりの幅を、その人の幅と比べる。半分を超えるなら離れていない |

### 見る前に標本の範囲を確かめる

その人側と基準側が、同じ範囲を覆っているかを先に確かめる。覆っていなければ、離れ
ていても重なっても、どちらの結果も信じられない。

たとえば長い文書だけを書いた人と、短い文書ばかりの基準を比べれば、長さと連動する
指標はすべて離れて見える。それは書きぶりの差ではない。

数を増やすより先に、範囲を見る。

### 狭いだけで信じない

文書が少なければ、たまたま狭い指標が出る。30 の指標を 7 本で測れば、いくつかは
偶然揃う。

幅の狭さは、素材が増えても狭いままかで確かめる。確かめられないうちは、効くと断定
せずに、素材が足りないことを添える。

### 決まったことは値と一緒に保存する

[検め](300-revise.md)は、効く指標を前に出して指摘にし、その外れを重く見る。効かない
指標まで同じ重さで並べると、いちばん言うべきことが埋もれる。

効かないと判定した指標も、判定ごと残す。素材が増えたときに、判定が変わったのか
値が変わったのかを見分けられる。

### 下限は「使った割合」で見る

下端を「最小値を下回る」で判定してはいけない。一度でも使わなかった文書があれば
最小値は 0 になり、それを下回ることはないので、下限の判定が永久に効かなくなる。

代わりに、その指標が現れた文書の割合を持つ。ほぼ毎回使うものが 1 度も出てこ
なければ、それは外れである。

## 入力を揃える

同じ内容でも、書式が違えば値が変わる。集めた文章は 1 つの形に揃えてから測る。

<strong>手順は [正規化](030-normalize.md) が決める。</strong> ここでは、評価に固有の判断だけを
決める。

正規化で消える特徴は測れない。それでよい。入力の形式が混ざっている以上、
消える特徴は、書き手のものか入力形式のものか区別がつかない。

### 定型を落とす

<strong>場面ごとに、誰が書いても同じになる部分がある。</strong> 落とさないと、書き手どうしの類似が
押し上げられ、差が埋もれる。

日本語の短いレビューで、これが実際に効いている。「発送が早かった」「梱包が丁寧」の
ような定型が <strong>著者間の言語的類似を上げ、文体の識別力を下げる</strong>と報告されている
（[日本語レビュー](../references/japanese-attribution-recent.md)）。

| 場面 | 落とす候補 |
| --- | --- |
| 技術記事 | 見出しの定型、生成された目次、他人の文章の引用 |
| チャット | 挨拶、相槌、定型の返信 |
| メール | 署名、宛名、結びの定型 |

<strong>何を落とすかは場面ごとに人が決める。</strong> 場面の一部であって、文章から当てにいくもの
ではない。決めたことは[作り直せないもの](#3-つに分けて持つ)として保存する。

### 落とすのは中身であって、node ではない

<strong>2 つを混同しない。</strong>

| | 何をするか |
| --- | --- |
| <strong>中身を落とす</strong> | その文字列を[地の文](020-document.md#地の文)から外す。語や記号の指標に効く |
| <strong>node は残す</strong> | 構造の指標は node を数え続ける |

<strong>コードブロックの中身は、既に[地の文](020-document.md#地の文)の定義で外れている。</strong>
ここで重ねて落とさない。[コードブロック](metrics/コードブロック.md)は node を数えるので、
落とすと全書き手で 0 が並び、[条件 4](100-metrics.md#集合は広く持つ絞るのはあとである) で
死ぬ。

引用も同じで、<strong>落とすのは引用された他人の文章であって、引用という node ではない。</strong>
どれだけ引用を挟むかは書き手の選択である。

## 作り直せるようにする

集合は増える。先行研究が増えたときと、本人の指摘から足すときである
（[指標](100-metrics.md#集合が変わるとき)）。<strong>増えるたびに過去の文章を測り直せなければ、
古い値と新しい値が混ざる。</strong>

揃えたあとの文章を残す。値は派生物として扱い、いつでも捨てて作り直せるように
する。

### 3 つに分けて持つ

| | 作り直せるか |
| --- | --- |
| 揃えたあとの本文 | できない。元のファイルは手元に残っていない |
| 人が決めたこと（場面、基準の置き方、除外） | できない |
| 値 | できる。本文と設定から何度でも |

作り直せないものだけを原本として扱う。値は捨ててよいものとして置く。捨てにくい
場所に置くと、測り直しをためらうようになる。

### 何で測ったかを指紋にする

指標の集合と設定から指紋を作り、値と一緒に保存する。次に測るとき指紋が変わって
いれば、保存してある値を捨てて測り直す。

指紋は指標の定義そのものから導く（[指標](100-metrics.md)）。一部だけを混ぜると、
混ぜ忘れた側の指標を足しても指紋が変わらず、古い値が黙って使われる。ここは
[名前を 1 度しか書かない](100-metrics.md#名前は-1-度しか書かない)のと同じ種類の
事故で、やはりエラーにならない。
