# 日本語 × LLM × 文体

日本語の LLM 生成文について、直接に効く 2 本。

## 林 美佐・相澤 彰子 (2026) LLM による日本語生成におけるモデル固有表現パターンの分析

言語処理学会 第 32 回年次大会. 東京大学 / 国立情報学研究所.
<https://www.anlp.jp/proceedings/annual_meeting/2026/pdf_dir/B9-17.pdf>

<strong>本文を読んだ。基準の記録単位を決める根拠になる。</strong>

同一の日本語プロンプトに対する各 LLM の応答から、<strong>生成元モデルを当てられるか</strong>を調べて
いる。

### 結果——日本語でもモデルは識別できる

| 課題 | 精度 |
| --- | --- |
| 商用 API モデル 3 クラス | <strong>98.2%</strong> |
| オープンパラメータモデル 6 クラス | 93.0% |
| <strong>同一系列のバージョン差</strong>（gpt-5.1 / gpt-4o / o3 / gpt-5.2） | <strong>93.6%</strong> |
| モデルサイズ違い（Llama） | 96.9% |
| モデルサイズ違い（Qwen） | 88.0% |

<strong>バージョンが違うだけで 93.6% 識別できる。</strong>

### 表層にも出る

埋め込みだけでなく、頻出フレーズの抽出でもモデル差が出た。

| モデル | 特徴的な表現 |
| --- | --- |
| ChatGPT | 丁寧な依頼表現を含む導入 |
| Gemini | 結論提示、番号付き構造 |
| LLM-jp 系 | 「ステップバイステップで説明します。」のような手順的な導入 |

抽出の式も明快である。対象モデルでの出現応答数と、それ以外での出現応答数の比に、
n-gram の長さで重みを付ける。

```
score = (freq_class + α) / (freq_other + α) × 2^n
```

<strong>基準との差から特徴的な表現を機械的に拾う方法である。</strong> 頻度比に n-gram の長さで重みを
付けるだけで、学習が要らない。

### 何が言えるか

<strong>「LLM の出力」を 1 つの塊として扱えない。</strong> バージョン差だけで 93.6% 識別できる以上、
版が変われば分布が変わる。[Przystalski](przystalski-2025.md) が英語で示したことが、
日本語でより細かい粒度で確認された。

## 高橋 良允ほか (2025) LLM における内部表現を用いた日本語スタイル制御メカニズムの分析

言語処理学会 第 31 回年次大会. 東北大学 / 楽天.
<https://www.anlp.jp/proceedings/annual_meeting/2025/pdf_dir/P2-6.pdf>

<strong>要旨と結論を読んだ。</strong>

日本語の口調（方言、語尾など）を対象に、モデル内部からスタイルベクトルを抽出して制御
できるかを検証している。

### 出発点が同じ問題意識

> 従来の<strong>プロンプトによる工夫では制御に限界があり</strong>、モデルの再学習は計算コストが高い

<strong>日本語側でも、プロンプトによる文体制御の限界が前提になっている。</strong>
[Bhandarkar](bhandarkar-2024.md) と [Catch Me](catch-me-2025.md) が英語で示したことと同じ。

### 結論——制御できるスタイルと、できないスタイルがある

> モデルの種類に依存せず、<strong>スタイルベクトルによって制御可能なスタイルと制御困難な
> スタイルが存在する</strong>ことが明らかになった

そして両者は、部分空間とノルムの分布分析で <strong>定量的に区別できる</strong>としている。

### 何が言えるか

<strong>文体の要素には、動かせるものと動かせないものがある。</strong> そしてその違いはモデルの種類
に依存しない。

[Bhandarkar](bhandarkar-2024.md) が挙げた 3 つ目の原因——「一部の LLM は指示された言語的
特徴を生成時に取り込む能力を欠く」——が、日本語側から裏付けられた形である。

<strong>動くかどうかは事後に測れる。</strong> 指示して書かせ、その量が動いたかを見ればよい。
