# 検めを 2 周する。指摘どおりに直すと数値は動くか

> [!WARNING]
> <strong>この実験の素材も、仕様が断るものだった</strong>（[300 と同じ](300-baseline-scene.md)。
> [詳細](500-directive-loop.md#長さの防護柵が発動した)）。
>
> <strong>結論——照合値は 1 つの切り口に鈍い——は、それでも立つ。</strong> 目盛りの位置が
> 当てにならないことと、目盛りの分解能が足りないことは別の話である。
>
> <strong>そして軸が在るのは照合値ではない。</strong>[指示できる指標の側では通った](500-directive-loop.md)。

[前の実験](300-baseline-scene.md)で目盛りができた。<strong>残るのは、直したら寄るかである。</strong>

道具は [tools/spike-calibrate.pl](../../tools/spike-calibrate.pl) の `--check`。
<strong>語彙・z 得点・較正・重みはすべて固定したまま</strong>、新しい文をそこへ投影する
（[語彙は先に決めて固定する](../spec/200-extract.md#語彙は先に決めて固定する)）。

## 指摘は実測から作った

本人と基準の読点の打ち方を数えた。

| | 1,000 字あたりの読点 | 直前の最頻文字 |
| --- | --- | --- |
| 本人 | 23.9 | <strong>で</strong>(19%)、は は 6% |
| 基準 | 28.6 | <strong>は</strong>(22%)、で は 4% |

<strong>2 つ名指しできる。</strong> 読点を減らす。「は」のあとで切るのをやめる。

## 素材

新しい題材（シェルの設定ファイルの整理）で、基準の書きぶりの記事を 1 本書いた。
<strong>コーパスに入れていない。</strong> `.spike/check/` に置いてある（追跡していない）。

```
perl tools/spike-calibrate.pl '<本人の記事>/*.md' '.spike/baseline/*.md' --commas
perl tools/spike-calibrate.pl '<本人の記事>/*.md' '.spike/baseline/*.md' --check '.spike/check/*.md'
```

改稿は<strong>機械的に 1 規則だけ</strong>当てた——`は、` → `は`。
読点 40 個 → 29 個、直前の「は」は 0% になった。<strong>読点以外の文字は 1 つも変えていない</strong>
（文字ごとに突き合わせて確認した）。

## 経路は通った

| | 照合値 | 位置 |
| --- | --- | --- |
| 床の上端 | −2.055 | |
| 天井の下端 | −1.508 | |
| <strong>改稿前</strong> | <strong>−2.545</strong> | 床の側 |
| <strong>改稿後</strong> | <strong>−2.536</strong> | 床の側 |

<strong>未知の文が正しく床の側に落ちた。</strong> 目盛りは固定したまま新しい文を測れる。

## だが寄らなかった

<strong>+0.009 である。</strong> 床から天井までの隔たり約 1.04 に対して <strong>0.9%</strong>。

どこで消えたかを割った。

| 系統 | 距離 改稿前 → 後 | 尤度比 改稿前 → 後 | 重み |
| --- | --- | --- | --- |
| 文字 bigram | 1.1287 → 1.1255 | −0.950 → −0.949 | 0.098 |
| <strong>読点前</strong> | <strong>1.0845 → 1.0660</strong>（−1.7%） | <strong>−0.956 → −0.949</strong> | <strong>0.060</strong> |
| 読点後 | 1.0624 → 1.0419（−1.9%） | −0.913 → −0.908 | 0.022 |
| 文字種 | 1.7797 → 1.7765 | −1.937 → −1.933 | 1.497 |

<strong>指標は動いた。</strong> 距離は 1.7% 縮んでいる。<strong>2 度縮んで消えた。</strong>

| どこで | 何倍になるか |
| --- | --- |
| 較正の傾き | 距離 0.0185 → 尤度比 0.007（約 0.4 倍） |
| 合算の重み | ×0.060 |

## 薄まる理由

<strong>読点前は 50 次元、読点は 40 個しかない。</strong> ほとんどの次元は 0 のままで、
z 得点に直すとどの文書でも同じ負の値になる。<strong>その定数がベクトルの長さを支配し、
実際に動いた 1 次元を薄める。</strong>

仕様は[「50 程度」を暫定値とし指紋に含める](../spec/metrics/読点の打ち方.md#次元)と書いている。
<strong>暫定であることは正しい。</strong> だが[除外の下限](../spec/metrics/読点の打ち方.md#除外)は
読点 10 個であり、<strong>50 次元の分布にはまるで足りない。</strong>

## 仕様に返したもの

[直したら測り直す](../spec/300-revise.md#直したら測り直す)が 2 つを混ぜていた——
「名指しした指標が動かない」と「照合値が動かない」。

<strong>前者だけが[条件 3](../spec/200-extract.md#どの指標が効くかを決める)である。</strong>
混ぜれば、<strong>正しく通じた指摘を「動かない」として落とす</strong>ことになる。この実験の指摘は
実測から作り、機械的に当て、指標は実際に動いた。それでも照合値は動かない。

分けて書き、照合値が鈍いことの実測値を添えた。

## 何が言えないか

<strong>これは 1 本の記事、1 つの指摘、1 周である。</strong> 仕様は[検めを 2 周](../spec/300-revise.md#直したら測り直す)
と言っており、2 周目——`stuck` を立てたあとの挙動——は動かしていない。

<strong>下限をいくつにすべきかは、この実験では決まらない。</strong> 単位を長くするのか、次元を減らす
のか、両方なのか——どれも 1 本の記事では確かめられない。

<strong>指示できる指標の側は試していない。</strong>「接続詞直後の読点」のような 1 つの切り口は、
指摘で直接動くはずである。<strong>照合値が鈍いことは、そちらが鈍いことを意味しない。</strong>
