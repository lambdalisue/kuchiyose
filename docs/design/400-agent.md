# LLM の道具の起動

[代筆する](../spec/400-write.md)が決めたプロンプトを、使う人の LLM の道具に渡して起動する
仕組みを決める。kuchiyose は LLM の API を呼ばない。起動するのは、使う人が手元に入れて
ある道具（`claude`、`codex`、または自前のコマンド）である。この文書で「道具」と書けば、
この LLM の道具を指す。

## 起動は 2 通り

| 起動 | 使うところ | 入出力 |
| --- | --- | --- |
| 対話の画面で始める | `write` の前半（内容を詰めて書く） | 端末につなぐ。使う人が道具と話す |
| 対話なしで最後まで走らせる | `build` のペルソナ作り、表現を寄せる周回 | 標準入力は `/dev/null`。標準出力と標準エラーは kuchiyose が受けて、失敗したときに見せる |

プロンプトの中身は道具によって変えない。「`kuchiyose katashiro persona --check …` を実行する」の
ような指示は、コマンドを実行できる道具ならどれでも同じように読める。道具ごとに変えると、
同じ形代と要約から違うプロンプトができ、[決定的に作る](../spec/400-write.md#決定的に作る)が
崩れる。

プロンプトの中で kuchiyose を名指すときは、今動いている実行ファイルの絶対経路を書く。
道具の側の `PATH` に kuchiyose があるとは限らないからである。

## 道具ごとに違うこと

道具ごとの違いを、起動の仕方の組（以下、道具の定義）として持つ。違うのは次の点だけである。

| 違い | 何を決めるか |
| --- | --- |
| 対話の画面で始める起動 | 最初のプロンプトの渡し方 |
| 対話なしで最後まで走らせる起動 | 走らせ方と、終わったことの知り方（終了コード） |
| 許す操作の絞り方 | [権限は必要な分だけ](#権限は必要な分だけ)をどう書くか |

`claude` と `codex` の定義は同梱する。引数は Claude Code 2.1.281 と codex-cli 0.146.0 の
`--help`（`codex exec --help` を含む）で確かめた。許す経路とコマンドの規則
（`Read(//<経路>)`、`Edit(//<経路>)`、`Bash(<コマンド>:*)`）は、Claude Code の権限の規則の
書式で書く。

| | claude | codex |
| --- | --- | --- |
| 対話の画面で始める | `claude <プロンプト>` | `codex <プロンプト>` |
| 対話なしで走らせる | `claude -p <プロンプト> --permission-mode dontAsk --tools … --allowedTools …` | `codex exec --sandbox workspace-write --skip-git-repo-check --cd <作業の場所> <プロンプト>` |
| 終わったことの知り方 | 終了コード | 終了コード |
| 許す操作の絞り方 | `--tools` で使える道具を並べ、`--allowedTools` で許す経路とコマンドを名指し、`--permission-mode dontAsk` で名指していないものを訊かずに断る | サンドボックスの段階で決める。`workspace-write` は作業の場所の中にだけ書ける。書ける経路と実行できるものは細かく名指せない |

起動ごとに渡す引数は次のとおりである。経路は絶対経路で、Claude Code の規則では先頭を
`//` にして絶対経路を指す。`--allowedTools` は値を幾つでも取るので、最後に置く。
確かめるコマンドの規則は、プロンプトに書いたコマンドの文字列そのままで、前置きで許す
`:*` を付けない。付ければ、ほかの形代への取り込みや `--remove`、後ろに足したシェルの
続きまで通る。

| 起動 | claude | codex |
| --- | --- | --- |
| ペルソナ作り | `--add-dir <素材>` `--tools Read,Glob,Grep,Write,Edit,Bash` `--allowedTools "Read(//<素材>/**)" "Edit(//<下書きの経路>)" "Bash(<確かめるコマンド>)"` | 作業の場所は[専用のディレクトリ](#ペルソナ作りは専用のディレクトリで走らせる) |
| 表現を寄せる周回 | `--tools Read,Write,Edit` `--allowedTools "Read(//<今の版>)" "Edit(//<その周の版>)"` | 作業の場所は作業用のフォルダ |

絞りきれないところは既知の差として残す。黙って広げない。

| 道具 | 絞れないこと |
| --- | --- |
| claude | 使う人の設定ファイルにある許可の規則は、渡した規則に足される。そこで広く許していれば、その分は広がる。`--tools` で渡していない道具は使えないので、周回で何かを実行することは無い |
| codex | 作業の場所の中なら、どのファイルにも書ける。ペルソナ作りでは専用のディレクトリ、周回では作業用のフォルダの中である。読むほうは絞れず、素材のフォルダの外も読める。`--add-dir` は書ける場所を足す引数で、読むだけの場所を足す引数は無いので、素材のフォルダは足さない。実行できるコマンドは名指せない |

## 権限は必要な分だけ

対話なしで起動するときは、許す操作を必要な分だけに絞る。途中で許可を訊かれても答える人が
いないので、訊かずに済む範囲をあらかじめ決めて渡すことになる。その範囲を広く取れば、
プロンプトを外れた道具が素材や草稿を書き換えても止まらない。

| 起動 | 読む | 書く | 実行する |
| --- | --- | --- | --- |
| ペルソナ作り | 素材のフォルダ | 専用のディレクトリの中の下書きの経路だけ | プロンプトに書いた `kuchiyose katashiro persona --check …` だけ |
| 表現を寄せる周回 | 今の版 | その周の版の経路だけ | 無し |

対話の画面で始める起動では、あらかじめ許すものを足さない。使う人が画面の前にいるので、
道具の側の確かめ（許可を訊く画面）がそのまま働く。草稿を書くことだけは、保存先の経路を
プロンプトで名指す。

### ペルソナ作りは専用のディレクトリで走らせる

ペルソナ作りの道具は、形代のあるディレクトリでは走らせない。そこには形代そのものや、
本人が直したペルソナ、ほかの形代がある。claude は作業の場所を読め、codex は作業の場所に
書ける。素材の記事にプロンプトを外させる文が紛れていれば、それらを読み書きされる。

| 段 | すること |
| --- | --- |
| 1 | `<形代の名前>.kuchiyose/` の下に、推し量れない名前の空のディレクトリを、自分だけが入れる権限（`0700`）で新しく作る |
| 2 | そのディレクトリを作業の場所にして道具を起動し、下書きをその中に書かせる。素材のフォルダは、claude には読むだけの場所として渡す。codex は読むほうを絞れないので渡さない（[絞れないこと](#道具ごとに違うこと)） |
| 3 | 道具には `katashiro persona --check` だけを打たせる。形代を取らず、何も書かないコマンドなので、道具に形代を書き換える道を渡さない |
| 4 | 道具が終わったら、下書きがふつうのファイルであることを確かめ、形代の隣の `<形代の名前>.persona.md` に置く。既にあれば上書きしない |
| 5 | ディレクトリを片づけ、kuchiyose が `katashiro persona` と同じ確かめ方で形代に取り込む |

下書きが symlink なら取り込まない。指した先のファイルの中身が、形代に入ることになる
からである。置けなかったときは、下書きを失わないようディレクトリを残す。

周回で道具に `review` を実行させないのは、検めるのが kuchiyose だからである
（[周回は kuchiyose が回す](../spec/400-write.md#周回は-kuchiyose-が回す)）。道具が自分で
検めて直し続ければ、kuchiyose が採った版と道具が見た版がずれる。

## プロンプトの渡し方

同梱の道具には、プロンプトを引数で渡す。同時に、作業用のフォルダにファイルとして書く。
ファイルは、何を渡したかをあとから読むためと、自前の道具に渡すためにある。

| 起動 | ファイル |
| --- | --- |
| ペルソナ作り | `<形代の名前>.kuchiyose/persona-<推し量れない名前>.prompt.md`（形代の隣。前からあるファイルを追わないよう、毎回新しく作る） |
| 代筆 | `<草稿の名前>.kuchiyose/write.prompt.md`（草稿の隣） |
| 表現を寄せる周回 | `<ファイルの名前>.kuchiyose/round-<n>.prompt.md` |

引数 1 つの長さには OS の上限がある（Linux は 128 KiB）。プロンプトが 100,000 バイトを
超えたら、引数には「次のファイルを読んで、その指示に従う」という短い文とファイルの経路だけを
渡し、中身はファイルで渡す。

## 端末をつなぎ直す

要約を標準入力から読んだあとに対話の画面を起動するときは、道具の標準入力を端末
（`/dev/tty`）につなぎ直す。標準入力は要約を読み切った時点で終わっているので、そのまま
渡せば道具は入力の終わりを受けて閉じる。

標準出力と標準エラーも、端末でなければ端末につなぐ。`:w !kuchiyose write` のように
エディタから流したとき、標準出力はエディタに戻っている。そこへ対話の画面を描けば、
画面がエディタのバッファに入る。

端末が無ければ（`/dev/tty` が開けない）、対話の画面は起動できない。起動せずに `64` で
断り、`--print` を使うよう言う。

## 自前の道具を使う

同梱していない道具は、起動のしかたをひな形で書く。

```sh
KUCHIYOSE_AGENT_CMD='my-llm --prompt-file {prompt_file}'
```

| 置き場 | 意味 |
| --- | --- |
| `{prompt_file}` | プロンプトを書いたファイルの絶対経路。必須 |
| `{mode}` | `interactive`（対話の画面）か `batch`（対話なし） |

ひな形は `/bin/sh -c` で走らせ、置き場はシェルの単引用符で囲んだ値に置き換える。1 つの
ひな形で 2 通りの起動を賄う。道具が起動ごとに違う引数を要るなら、`{mode}` を受ける
小さなスクリプトを挟む。

`{prompt_file}` を必須にするのは、プロンプトの長さが引数の上限に当たらないようにする
ためである。ひな形に `{prompt_file}` が無ければ、起動せずに `64` で断る。

自前の道具では、kuchiyose は許す操作を絞れない。絞るならひな形の側に書く。

## どの道具を使うか

次の順に見て、最初に決まったものを使う。

| 順 | どこ |
| --- | --- |
| 1 | `--agent claude\|codex\|custom` |
| 2 | 環境変数 `KUCHIYOSE_AGENT` |
| 3 | [設定ファイル](200-command.md#設定ファイル)の `agent` |
| 4 | `KUCHIYOSE_AGENT_CMD`（または設定ファイルの `agent_cmd`）があれば `custom` |
| 5 | `PATH` に `claude` があれば `claude`、無くて `codex` があれば `codex` |

5 まで来てどれも無ければ、`69`（環境の側の理由）で断り、`--agent` と `--print` を案内する。
5 で決まったときは、どの道具を使ったかを標準エラーに 1 行出す。初めて使う人に設定を
書かせないためで、黙って選べばどの道具が起動したかが分からなくなる。

`custom` を選んでひな形が無ければ、`64` で断る。

## 失敗の扱い

| 起きたこと | どうするか |
| --- | --- |
| 道具が見つからない | 起動しない。`69` で終わる |
| 対話なしの起動が 0 以外で終わった | その周を失敗とし、周回を止める。道具の標準エラーの末尾を見せる |
| 書くはずの経路に何も書かれていない | 同上 |
| ペルソナの下書きがふつうのファイルでない（symlink など） | 取り込まない。`69` で終わる |
| 対話の画面が終わったのに草稿が無い | 周回に入らない。保存先を言って `65` で終わる |
| 対話の画面が 0 以外で終わった | 失敗としない。使う人が止めても 0 以外で終わる道具がある。草稿があるかで決める |

失敗した周を繰り返さない。道具の失敗は環境の側の理由であることが多く、同じ呼び方を繰り返しても
直らない。それまでに採った版は残る（[止めどき](../spec/400-write.md#止めどき)）。

## プロンプトを出すだけにする

`--print` を付けると、道具を起動せずにプロンプトを標準出力に出す。合う道具が無いとき、
コマンドを実行できない道具を使うとき、プロンプトを読んで確かめたいときのためである。

| コマンド | `--print` で出すもの | ほかにすること |
| --- | --- | --- |
| `build` | ペルソナを作るプロンプト | 統計値を作って形代を書く |
| `write` | 代筆のプロンプト | しない。周回にも入らない |
| `polish` | 最初の周の直させるプロンプト | しない |

`build --print` のプロンプトは、下書きの経路に形代の隣の `<形代の名前>.persona.md` を書く。
道具を起動しないので、ペルソナの取り込みは使う人が `katashiro persona` で打つ。
コマンドを実行できない道具を使うときは、`review` も使う人が自分で打つ。
