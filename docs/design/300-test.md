# テストの体系

何を試験するかを決める。

## 何を狙うか

<strong>仕様は「黙って壊れる」と 9 か所で警告している。</strong> どれも共通の形をしている——
<strong>エラーにならず、値が出て、判定が回り、結果だけが違う。</strong>

> 落ちてくれるなら気付けるが、落ちないので気付けない。
> ——[指標](../spec/100-metrics.md#名前は-1-度しか書かない)

<strong>この試験体系の目的は、落ちない失敗を落ちるようにすることである。</strong> 網羅率ではない。

| 仕様が警告した場所 | 落ちなければどうなるか |
| --- | --- |
| [Alert が引用に化ける](../spec/030-normalize.md#黙って壊れる場所がある) | 引用の密度が高く、補足の密度が 0 で並ぶ |
| [名前が 2 か所にある](../spec/100-metrics.md#名前は-1-度しか書かない) | その指標が発火しなくなる |
| [指紋に一部だけ混ぜる](../spec/200-extract.md#何で測ったかを指紋にする) | 古い値が黙って使われる |
| [0 と「測れない」を混ぜる](../spec/030-normalize.md#対応表は取り込み元ごとに持つ) | 補足を使わない人だと判定される |
| [表記を潰す](../spec/030-normalize.md#表記を潰さない) | 測っているのが取り込み元になる |
| [単位を指標ごとに決め直す](../spec/100-metrics.md#定義に落とす) | 同じ名前が別のものを指す |
| <strong>[全角だけで文を切る](../spec/020-document.md#文)</strong> | <strong>文を数えるものすべてが狂う</strong> |
| [較正した標本で目盛りを測る](../spec/200-extract.md#較正に使う-2-つの対集合) | 分離して見えるだけになる |
| [系統が欠けたまま合算する](../spec/200-extract.md#系統が-1-つでも欠けたら照合値を出さない) | 同じ目盛りに載らない値が出る |

<strong>この 9 つには必ず試験を置く。</strong> 以下はその置き方である。

## 決定性

<strong>[数える側に LLM を置かない](../spec/010-strategy.md#数える側に-llm-を置かない)は
好みではなく成立条件である。</strong> 条件は試験できる。

```
同じ入力を 2 度通して、同じ正規形が出る
同じ正規形を 2 度測って、同じ値が出る
```

<strong>性質試験にする。</strong> 生成した入力で繰り返す。並びや反復回数に依存する実装が混ざれば、
ここで落ちる。

<strong>除くクレートは無い。</strong>[基準を作らない](000-architecture.md#基準は作らない)ので、
非決定的なものがどこにも入っていない——<strong>全部が同じ入力から同じ値を返す。</strong>

同じ形で、<strong>`kakiburi-review` が `kakiburi-scale` に依存していないこと</strong>も確かめる
（[理由](000-architecture.md#依存の向き)）。

## 名前が 1 か所であること

<strong>登録簿の名前集合と、実装が返す名前集合が一致する。</strong>

```
片方にしかない名前が 1 つでもあれば落ちる
```

<strong>これは実行時の検査ではなく試験である。</strong> 仕様は「機械で確かめる」としか言っていないが、
実行時に落とすと本番で初めて分かる。<strong>指標を足した人がその場で気付くようにする。</strong>

同じ形で、<strong>指標の定義ファイルと登録簿の一致</strong>も確かめる。定義が `metrics/` にあるのに
登録簿に無ければ、その指標は仕様にあって実装に無い。

## 指紋が全部の入力を覆うこと

<strong>入力を 1 つ変えたら指紋が変わる。</strong> 入力の数だけ試験を書く。

<strong>[仕様の一覧](../spec/200-extract.md#何で測ったかを指紋にする)が正本である。</strong> ここは
そこから写す——増えたら両方を直す。

| 変えるもの |
| --- |
| 指標の定義 |
| <strong>数える単位の定義</strong>（地の文に何が入るか、日本語の文字の範囲と Unicode の版） |
| 固定した語彙 |
| 形態素解析器の辞書と版 |
| 圧縮器と設定 |
| 固定した z 得点の平均と標準偏差 |
| <strong>較正の設定</strong>（L2 の強さ・解法・収束の条件・反復の上限・残差の合否の線） |
| <strong>束の構成と並び</strong> |
| 外部の表の版（語の文体値、文末表現の辞書、Unicode、絵文字の表） |
| 取り込み元の種類・変換の実装と版・対応表 |
| 基準の LLM の版と推論設定 |
| 係り受け解析器の辞書と版（保留中。使うと決めたら要る） |
| 人が決めたこと（<strong>場面</strong>・落とす定型・<strong>基準の題材</strong>・指示して動くか） |
| <strong>場面が増えた</strong> |

<strong>1 行ずつ書く。</strong> まとめて回すと、覆えていない入力が 1 つあっても他が通って緑になる。

### 共通部分と場面ごとの部分が別に動くこと

<strong>[指紋は 2 つに割れる](100-cassette.md#指紋は組み立てを型で守る)。</strong> 割ったことが
効いているかを確かめる。

| 確かめること | 通らなければ |
| --- | --- |
| 場面ごとの材料を変えると、<strong>その場面の欄だけ</strong>が動く | 1 つの場面を `build` するとほかの場面の語彙が消える |
| 場面ごとの材料を変えても、<strong>共通部分は動かない</strong> | 語彙が変わっただけで「辞書が変わった」と言われる |
| <strong>片方にしか無い場面</strong>が違いとして出る | 場面を消したことが差にならない |
| <strong>2 つの場面の中身を入れ替える</strong>と指紋が変わる | 場面の名前が指紋に写っていない |

<strong>最後の 1 行が、名前を落としていないことの試験である。</strong> 材料だけを並べれば、
中身の入れ替えは同じ文字列になる。

<strong>指紋を作る関数が全部の材料を引数に取る</strong>ので、材料が増えれば型が変わって既存の呼び
出しが壊れる。<strong>試験を書き忘れても、コンパイルが止める。</strong>

## 正規化

### 記法から意味への対応

<strong>取り込み元ごとに golden test を置く。</strong> 入力と、期待する node の木を並べる。

<strong>いちばん先に書くのが Alert である。</strong>

```
> [!NOTE] を含む GitHub の Markdown を通すと
  補足の node になる
  引用の node にならない
```

<strong>逆も書く。</strong> 素の Markdown で同じ記法を通したら、<strong>引用になる</strong>——その取り込み元では
補足を書けないので、それが正しい。

### 0 と「測れない」

```
補足を書けない取り込み元の文書では
  補足の密度は 0 ではなく「測れない」になる
```

<strong>値の型で分ける。</strong> 0 と「測れない」が同じ型に入るなら、この試験は書けても実装が
守れない。

### 表記を潰さない

```
全角と半角、〜 と ～、… と …… を含む文書を通して
  正規形にそのまま残っている
```

<strong>整形ツールを挟んだ経路にも同じ試験を置く。</strong> 既製のフォーマッタは頼まなくても揃える。

### 断る

```
対応表に無い記法を含む入力は、断る
日本語以外が主の入力は、断る
壊れた記法は、断る
```

<strong>「一部を落として通る」が無いことを確かめる。</strong> 通ってしまう実装は、この試験でしか
捕まらない。

## 文書の形

<strong>単位そのものを試験する。</strong>[文書の形](../spec/020-document.md#数える単位)は
<strong>測れることの上限</strong>を決めており、ここが違えば上のすべてが違う。<strong>それでいて、間違って
いても値は出る。</strong>

単位ごとに golden test を置く。

| 単位 | 確かめること |
| --- | --- |
| <strong>文</strong> | <strong>半角の `!` `?` でも切る。</strong> 直後の閉じ括弧は同じ文に含める。`…` では切らない。括弧の内側の `。` では切らない |
| 段落 | 箇条書き・番号リスト・引用・コードブロック・表・見出しは段落ではない |
| 節 | 次の同じ深さ以上の見出しまで。見出しより前の本文も 1 節。見出しが無ければ全体で 1 節 |
| 項目 | 箇条書きと番号リストの直接の子。<strong>入れ子の子は数えない</strong> |
| 日本語の文字 | 約物・英数字・空白・記号を分母に入れない |
| 地の文 | コードブロックとインラインコードの中身、代替文字、参照先を含まない。<strong>ひらがな・カタカナ・漢字の無いセルを含まない</strong>（`ー` `々` だけのセルも含まない） |
| <strong>表の並び</strong> | <strong>セル 1 つが 1 本。</strong> 桁揃えの空白が入らない。落としたセルの跡で隣のセルが繋がらない |
| 見出しの深さ | <strong>最も浅い見出しからの相対。</strong> 同じ構成なら取り込み元が違っても同じ深さ |

<strong>文の行を最初に書く。</strong> 半角を落とす実装は、半角で終える書き手の文を黙って連結する
——[表記を潰さない](../spec/030-normalize.md#表記を潰さない)と組み合わさって初めて
壊れるので、正規化の試験だけでは捕まらない。

## 指標

### 単位を再定義していない

<strong>lint として書く。</strong>[文書の形](../spec/020-document.md#数える単位)が持つ単位の名前が、
指標の定義ファイルの数え方の節に <strong>定義として</strong>現れていないことを確かめる。

<strong>完全ではない。</strong> 言い回しを変えれば抜ける。それでも置くのは、止めたい形が具体的だから
である——「節は深さ 2 の見出しで区切る」「入れ子の項目も 1 項目として数える」のように、
<strong>定義ファイルが単位を言い直す</strong>書き方を捕まえる。

### 除外の解決

```
定義に除外が無ければ、単位から既定が引かれる
定義に除外があれば、そちらが使われる
割合の指標に除外が無ければ、落ちる
```

3 つ目が[仕様の要求](../spec/100-metrics.md#分母がその現象自身のときは必ず書く)である。
<strong>登録簿を組み立てる時点で落とす。</strong>

### 層の 2 段引き

```
札が系統を名指ししていれば、その系統の層
札が なし なら 層 3
```

<strong>分類から系統を当てにいかない。</strong> 分類が「表記」だからといって同名の系統の層を継がせ
ると、<strong>系統を名指しできない指標が層 1・2 へ上がる</strong>——
[層が問うのは系統に遡れるかだけ](../spec/100-metrics.md#層は系統の属性である指標は系統から引く)
という規則が、そこで裏返る。

<strong>2 行目が安全側の既定である。</strong> 書き漏らしを層 3 に落とす仕組みそのものである。
<strong>進行の実況が層 3 になることを、実物で確かめる。</strong>

<strong>札そのものが欠けているのは、既定ではなく壊れである。</strong> 登録簿を組み立てる時点で落とす
（[定義に落とす](../spec/100-metrics.md#定義に落とす)）。

## 目盛り

### 帯の規則

<strong>性質試験にする。</strong> 天井と床の分布を生成し、<strong>分離しているときも重なっているときも</strong>、
どの照合値もちょうど 1 つの判定になることを確かめる。

```
どの値も、通る・通らない・判定できない のちょうど 1 つに落ちる
```

<strong>片端だけで切る実装は、分離した瞬間に 2 つ成立して落ちる。</strong> 例で確かめると通って
しまう——分離した分布の例を書けば通り、重なった例を書いても通る。<strong>両方を跨いで初めて
捕まる形なので、性質試験でなければならない。</strong>

### 較正と評価が分離していること

```
天井と床を作った対が、1 つも較正に使われていない
```

<strong>相手集合の割りと、使った対の一覧を覗いて確かめる。</strong> 結果ではなく手続きを試験する——結果だけ見ても、分離
していない実装のほうが良い数字を出すので気付けない。

### 系統が欠けたら出さない

```
1 つでも除外に掛かった文書は、照合値を持たない
検めは判定できないを返す
```

<strong>抜いて合算する実装が通らない</strong>ことを確かめる。

## 判定

### 3 段の全分岐

<strong>[3 段](../spec/300-revise.md#種別を合わせて通るを出す)の分岐を網羅する。</strong> 表がそのまま
試験の一覧になる。

| 人らしさ値 | 照合値 | <strong>前に出す指標</strong> | 返る |
| --- | --- | --- | --- |
| 機械 | — | — | 通らない |
| 判定できない | — | — | 判定できない |
| 人 | 床側 | — | 通らない |
| 人 | 帯の中 | — | 判定できない |
| 人 | 天井側 | 幅の外あり | 判定できない |
| 人 | 天井側 | 全部幅の中 | 通る |
| 測れない | — | — | 判定できない |

<strong>「止めた理由」が返ることも、行ごとに確かめる。</strong>

<strong>3 列目が「指示できる指標」ではないことが要点である。</strong>[前に出す指標](../spec/300-revise.md#種別を合わせて通るを出す)
——効くと判定されたものから層 3 と動かないものを除いた集合——を使う。全部の指示できる
指標で止めると、<strong>言えない理由で「通る」を止める</strong>ことになり、軸に反する。

```
層 3 の指標が幅の外にあっても、判定は止まらない
動かないと判定された指標が幅の外にあっても、判定は止まらない
判定を止めた指標は、必ず指摘にも現れる
```

<strong>3 行目が、判定と指摘が同じ集合から取っていることの試験である。</strong>

### 指摘の順位

```
出てこないことの外れが、幅の外れと同じ尺度で並ぶ
出現割合 1.0 の指標が消えていれば、上位に来る
```

<strong>割合をそのまま並べると上限 1.0 で、幅の外れ（2.5 や 4.0）に永久に勝てない。</strong>
順位が静かに偏るだけなので、値の試験では出ない。

## 作り直せることを試験する

<strong>[3 つに分けて持つ](../spec/200-extract.md#3-つに分けて持つ)が本当かを確かめる。</strong>

```
カセットから derived/ を丸ごと消して build し直すと
  消す前と同じものが出る
```

<strong>これが通らなければ、派生物のどこかに原本が混ざっている。</strong> 気付かないまま運用すると、
測り直した瞬間に人が決めたことが消える。

<strong>実際に消して、実際に build する。</strong> 古い派生物を控えておいて戻す形では、build を 1 度も
呼ばずに通ってしまう——<strong>確かめたいのは作り直せることであって、控えが取れることではない。</strong>

## カセットを壊さないこと

<strong>[書くときの手順](100-cassette.md#書くときは壊さないことを優先する)は、失敗したときに
しか効かない。</strong> 普通に動かしているかぎり緑になるので、<strong>壊して確かめる。</strong>

| 何を起こすか | 何を確かめるか |
| --- | --- |
| <strong>rename の前</strong>で書き込みを落とす | <strong>元のカセットが読める。</strong> 一時ファイルが残っていない |
| <strong>rename の後</strong>で書き込みを落とす | <strong>読めるカセットが 1 つある</strong>（新旧どちらでもよい） |
| entry を 1 つ壊す | <strong>置き換える前に断る</strong>（CRC・JSON・参照） |
| `manifest.json` を 2 つ持つ zip | <strong>壊れているとして断る</strong> |
| `manifest.json` を持たない zip | 同上 |
| 知らない `version` | <strong>知らない版として断る。</strong> 壊れているとは別の理由で返す |
| 既にある `id` を `add` | <strong>断る。</strong> 原本が消えない |
| 別の役で使われている `unit` を `add` | <strong>断る</strong> |
| <strong>同じ役だが別の取り込み元</strong>の `unit` を `add` | <strong>断る</strong> |
| <strong>無い `id` を `replace`</strong> | <strong>断る</strong> |
| <strong>束の一部だけを別の役へ `replace`</strong> | <strong>断る</strong> |
| <strong>`add` / `replace` のあとに `review`</strong> | <strong>判定できないを返す。</strong> 古い派生物を読まない |
| 2 つの書き込みを同時に走らせる | <strong>片方が断られる。</strong> どちらの変更も消えない |
| <strong>既に在るところへ `new`</strong> | <strong>断る。</strong> 中身が変わらない |
| <strong>知らない場面へ `add` / `decide` / `review`</strong> | <strong>断る</strong> |
| <strong>場面の無い `person` を持つカセット</strong> | <strong>壊れているとして断る</strong> |

<strong>`new` の 1 行が、この表でいちばん失うものが大きい。</strong> 取り込みには時間が掛かり、
原本は作り直せない。

<strong>どれも、通らなければ原本が黙って消える種類の失敗である。</strong> 値が変わるまで誰も
気付かない。

## 組み立て層が目盛りを作り直さないこと

<strong>[クレートの境界は組み立て層では効かない](000-architecture.md#守られるのはクレートの中だけである)。</strong>
`kakiburi` は較正にも検めにも依存するので、<strong>型では止まらない。</strong>

```
review の経路を端から端まで走らせると
  較正の関数が 1 度も呼ばれない
```

<strong>入出力だけを見る試験では書けない。</strong> 較正を差し替えられる形で渡し、呼ばれた回数を
数える。<strong>分岐を全部通す</strong>——通る、通らない、判定できない、系統が欠けた、指紋が合わない。

<strong>これが[唯一、型で守られていない境界](000-architecture.md#守られるのはクレートの中だけである)である。</strong>
ほかは依存の向きが持つ。

## 場面を跨いだ素材が照合の側に漏れないこと

<strong>[跨げるのは 1 本だけである](000-architecture.md#場面を跨ぐ道は-1-本に絞る)。</strong>
欄で分けても、関数の中で混ぜてしまえば同じことになる。

```
他人の文書を足しても
  割りも語彙も照合値の帯も照合の較正も、1 ミリも動かない
  人らしさの較正だけが動く
```

<strong>動かないことと動くことの両方を見る。</strong> 前半だけなら「読まれていない」でも通り、
後半だけなら「どこに効いたか」が言えない。

<strong>取り出し口の側も確かめる。</strong> 場面で絞る口から `other` が 1 本も出てこないこと——
どの場面を指しても一致しないので、型と実装の両方で成り立っている。

## 実データが要るもの

<strong>合成データでは書けない試験がある。</strong> 別に置き、常には回さない。

| | 何を確かめるか |
| --- | --- |
| <strong>自分を検査する</strong> | 本人の実際の文章が、生成文より高く出る |
| <strong>天井と床が分離するか</strong> | [いちばん危ない検査](../spec/010-strategy.md#それでも骨格を先に通す) |
| <strong>指摘どおりに直すと動くか</strong> | [検めを 2 周](../spec/300-revise.md#直したら測り直す) |

<strong>3 つとも、通らなければ設計が間違っている</strong>という種類の試験である。実装の誤りを探す
ものではない。<strong>骨格を通したときに 1 度、そのあとは素材が増えたときに回す。</strong>

> [!WARNING]
> <strong>「天井と床が分離するか」を緑にするために閾値を触らない。</strong> 分離しないという事実が
> 出ているなら、それが結果である。

## どう回すか

| いつ | 何を |
| --- | --- |
| 変更のたび | 決定性・名前・指紋・正規化・指標・目盛り・判定・<strong>組み立て層の境界</strong> |
| 骨格を通すとき | 上に加えて、作り直せること・<strong>カセットを壊さないこと</strong> |
| 素材が増えたとき | さらに、実データが要るもの |

<strong>カセットを壊さない試験を毎回回さないのは、故障を注入するぶん遅いからである。</strong>
<strong>保存形式に手を入れたときは、変更のたびの側で回す。</strong>

<strong>速いものと遅いものを混ぜない。</strong>[1 周を安くする](../spec/010-strategy.md#使うときはループになる)
のと同じ理由で、毎回回す試験が遅ければ回さなくなる。

## 書き方

<strong>試験は「何を」を書く。</strong> どうやってはコードが、なぜはコミットが持つ。

<strong>名前は仕様の言葉で付ける。</strong> 実装の言葉で付けると、仕様が変わったときにどの試験を
直すべきかが分からなくなる。

<strong>失敗したときに、仕様のどこに反したかが読めるようにする。</strong> 冒頭の表の 9 行は、どれも
仕様の節に対応している。
