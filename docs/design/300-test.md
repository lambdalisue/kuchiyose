# テストの体系

何を試験するかを決める。

## 何を狙うか

仕様は「黙って壊れる」と何か所も警告している。どれも共通の形をしている。エラーにならず、
値が出て、判定が回り、結果だけが違う。

> 落ちてくれるなら気付けるが、落ちないので気付けない。
> ——[指標](../spec/100-metrics.md#名前は-1-度しか書かない)

<strong>この試験体系の目的は、落ちない失敗を落ちるようにすることである。</strong> 網羅率ではない。

| 仕様が警告した場所 | 落ちなければどうなるか |
| --- | --- |
| [Alert が引用に化ける](../spec/030-normalize.md#黙って壊れる場所がある) | 引用の密度が高く、補足の密度が 0 で並ぶ |
| [名前が 2 か所にある](../spec/100-metrics.md#名前は-1-度しか書かない) | その指標が発火しなくなる |
| [指紋に一部だけ混ぜる](../spec/200-extract.md#何で測ったかを指紋にする) | 古い値が黙って使われる |
| [0 と「測れない」を混ぜる](../spec/030-normalize.md#対応表は取り込み元ごとに持つ) | 補足を使わない人だと判定される |
| [表記を潰す](../spec/030-normalize.md#表記を潰さない) | 測っているのが取り込み元になる |
| [単位を指標ごとに決め直す](../spec/100-metrics.md#定義に落とす) | 同じ名前が別のものを指す |
| <strong>[全角だけで文を切る](../spec/020-document.md#文)</strong> | <strong>文を数えるものすべてが狂う</strong> |
| [較正した標本で目盛りを測る](../spec/200-extract.md#較正に使う-2-つの対集合) | 分離して見えるだけになる |
| [系統が欠けたまま合算する](../spec/200-extract.md#欠けた系統は-1-つまで基準の側へ寄せて埋める) | 同じ目盛りに載らない値が出る |
| [束ねた単位を連結して測る](../spec/200-extract.md#短い文書は束ねる) | 人らしさの窓が文書をまたぎ、別の文書の語が 1 つの窓に入る |
| [無効にした指標が作り直しで戻る](../spec/200-extract.md#素材を正本にする) | 動かない指標が黙って指摘に戻る |
| [ペルソナが測る側に入る](../spec/400-write.md#形代に入れる) | ペルソナを直すたびに判定が動く |
| [悪くなった版を採る](../spec/400-write.md#良くなった版だけを採る) | 周回が進むほど判定が下がり、しかも最後の版が報告される |

この表の行には必ず試験を置く。以下はその置き方である。

## 決定性

<strong>[数える側に LLM を置かない](../spec/010-strategy.md#数える側に-llm-を置かない)は
好みではなく成立条件である。</strong> 条件は試験できる。

```
同じ入力を 2 度通して、同じ正規形が出る
同じ正規形を 2 度測って、同じ値が出る
```

<strong>性質試験にする。</strong> 生成した入力で繰り返す。並びや反復回数に依存する実装が混ざれば、
ここで落ちる。

除くクレートは無い。[基準を作らない](000-architecture.md#基準は作らない)ので、
非決定的なものがどこにも入っていない。全部が同じ入力から同じ値を返す。

```
同じフォルダを 2 度 katashiro build して、同じバイト列の形代が出る
同じ 2 つの形代から 2 度組み立てて、同じ目盛りが出る
```

目盛りは保存しないので、2 行目が「同じ組み合わせで出した判定をいつでも出し直せる」ことの
中身である。

同じ形で、<strong>`kuchiyose-review` が `kuchiyose-scale` に依存していないこと</strong>も確かめる
（[理由](000-architecture.md#依存の向き)）。

## 名前が 1 か所であること

<strong>登録簿の名前集合と、実装が返す名前集合が一致する。</strong>

```
片方にしかない名前が 1 つでもあれば落ちる
```

<strong>これは実行時の検査ではなく試験である。</strong> 仕様は「機械で確かめる」としか言っていないが、
実行時に落とすと本番で初めて分かる。<strong>指標を足した人がその場で気付くようにする。</strong>

同じ形で、<strong>指標の定義ファイルと登録簿の一致</strong>も確かめる。定義が `metrics/` にあるのに
登録簿に無ければ、その指標は仕様にあって実装に無い。

## 指紋が全部の入力を覆うこと

<strong>入力を 1 つ変えたら指紋が変わる。</strong> 入力の数だけ試験を書く。

<strong>[仕様の一覧](../spec/200-extract.md#何で測ったかを指紋にする)が正本である。</strong> ここは
そこから写す——増えたら両方を直す。

| 変えるもの |
| --- |
| 指標の定義 |
| 数える単位の定義（地の文に何が入るか、日本語の文字の範囲と Unicode の版） |
| 形態素解析器の辞書と版 |
| 圧縮器と設定 |
| 窓の大きさ・下限・言い回しの長さの設定、語のまとめ方の線 |
| 外部の表の版（語の文体値、文末表現の辞書、Unicode、絵文字の表） |
| 取り込み元の種類・変換の実装と版・対応表 |
| 係り受け解析器の辞書と版（保留中。使うと決めたら要る） |
| 統計値の中身 |

逆向きも書く。変えても指紋が動いてはいけないものがある。

| 変えても動かないもの | 動けば |
| --- | --- |
| 調整（無効にした対象、一人称と文体の申告） | 調整しただけで比べられなくなる |
| 較正の設定と閾値 | 閾値を 1 つ動かしただけで、人からもらった形代が全部使えなくなる |

1 行ずつ書く。 まとめて回すと、覆えていない入力が 1 つあっても他が通って緑になる。

### 2 つの形代の指紋を照らすこと

組み立てるときに、2 つの形代の指紋が照らされることを確かめる。

| 確かめること | 通らなければ |
| --- | --- |
| 解析器の版だけが違う 2 つの形代を渡すと、組み立てずに断る | 道具の差を書き手の差として測る |
| 中身だけが違う 2 つの形代は、組み立てられる | 別の人の形代を基準に渡せない |
| 作った直後の指紋が今の道具と合う | 1 度も使えない形代が出来上がる |

指紋を作る関数が全部の材料を引数に取るので、材料が増えれば型が変わって既存の呼び出しが
壊れる。試験を書き忘れても、コンパイルが止める。

## 正規化

### 記法から意味への対応

<strong>取り込み元ごとに golden test を置く。</strong> 入力と、期待する node の木を並べる。

<strong>いちばん先に書くのが Alert である。</strong>

```
> [!NOTE] を含む GitHub の Markdown を通すと
  補足の node になる
  引用の node にならない
```

<strong>逆も書く。</strong> 対応表に無い `> [!HINT]` を通したら、<strong>断られる</strong>——引用に化けて
地の文へ流れてはいけない。Markdown の取り込み元は[1 つである](../spec/030-normalize.md#markdown-を方言に分けない)
ので、同じ記法が方言によって引用になることは無い。

### 0 と「測れない」

```
補足を書けない取り込み元の文書では
  補足の密度は 0 ではなく「測れない」になる
```

<strong>値の型で分ける。</strong> 0 と「測れない」が同じ型に入るなら、この試験は書けても実装が
守れない。

### 表記を潰さない

```
全角と半角、〜 と ～、… と …… を含む文書を通して
  正規形にそのまま残っている
```

<strong>整形ツールを挟んだ経路にも同じ試験を置く。</strong> 既製のフォーマッタは頼まなくても揃える。

### 断る

```
対応表に無い記法を含む入力は、断る
日本語以外が主の入力は、断る
壊れた記法は、断る
```

<strong>「一部を落として通る」が無いことを確かめる。</strong> 通ってしまう実装は、この試験でしか
捕まらない。

## 文書の形

<strong>単位そのものを試験する。</strong>[文書の形](../spec/020-document.md#数える単位)は
<strong>測れることの上限</strong>を決めており、ここが違えば上のすべてが違う。<strong>それでいて、間違って
いても値は出る。</strong>

単位ごとに golden test を置く。

| 単位 | 確かめること |
| --- | --- |
| <strong>文</strong> | <strong>半角の `!` `?` でも切る。</strong> 直後の閉じ括弧は同じ文に含める。`…` では切らない。括弧の内側の `。` では切らない |
| 段落 | 箇条書き・番号リスト・引用・コードブロック・表・見出しは段落ではない |
| 節 | 次の同じ深さ以上の見出しまで。見出しより前の本文も 1 節。見出しが無ければ全体で 1 節 |
| 項目 | 箇条書きと番号リストの直接の子。<strong>入れ子の子は数えない</strong> |
| 日本語の文字 | 約物・英数字・空白・記号を分母に入れない |
| 地の文 | コードブロックとインラインコードの中身、代替文字、参照先を含まない。<strong>ひらがな・カタカナ・漢字の無いセルを含まない</strong>（`ー` `ｰ` `々` `ゝ` `ゞ` `ヽ` `ヾ` だけのセルも含まない。合字の `ゟ` `ヿ` は日本語の文字として数える） |
| <strong>表の並び</strong> | <strong>セル 1 つが 1 本。</strong> 桁揃えの空白が入らない。落としたセルの跡で隣のセルが繋がらない |
| 見出しの深さ | <strong>最も浅い見出しからの相対。</strong> 同じ構成なら取り込み元が違っても同じ深さ |

<strong>文の行を最初に書く。</strong> 半角を落とす実装は、半角で終える書き手の文を黙って連結する
——[表記を潰さない](../spec/030-normalize.md#表記を潰さない)と組み合わさって初めて
壊れるので、正規化の試験だけでは捕まらない。

## 指標

### 単位を再定義していない

<strong>lint として書く。</strong>[文書の形](../spec/020-document.md#数える単位)が持つ単位の名前が、
指標の定義ファイルの数え方の節に <strong>定義として</strong>現れていないことを確かめる。

<strong>完全ではない。</strong> 言い回しを変えれば抜ける。それでも置くのは、止めたい形が具体的だから
である——「節は深さ 2 の見出しで区切る」「入れ子の項目も 1 項目として数える」のように、
<strong>定義ファイルが単位を言い直す</strong>書き方を捕まえる。

### 除外の解決

```
定義に除外が無ければ、単位から既定が引かれる
定義に除外があれば、そちらが使われる
割合の指標に除外が無ければ、落ちる
```

3 つ目が[仕様の要求](../spec/100-metrics.md#分母がその現象自身のときは必ず書く)である。
<strong>登録簿を組み立てる時点で落とす。</strong>

### 層の 2 段引き

```
札が系統を名指ししていれば、その系統の層
札が なし なら 層 3
```

<strong>分類から系統を当てにいかない。</strong> 分類が「表記」だからといって同名の系統の層を継がせ
ると、<strong>系統を名指しできない指標が層 1・2 へ上がる</strong>——
[層が問うのは系統に遡れるかだけ](../spec/100-metrics.md#層は系統の属性である指標は系統から引く)
という規則が、そこで裏返る。

<strong>2 行目が安全側の既定である。</strong> 書き漏らしを層 3 に落とす仕組みそのものである。
<strong>進行の実況が層 3 になることを、実物で確かめる。</strong>

<strong>札そのものが欠けているのは、既定ではなく壊れである。</strong> 登録簿を組み立てる時点で落とす
（[定義に落とす](../spec/100-metrics.md#定義に落とす)）。

## 目盛り

### 帯の規則

<strong>性質試験にする。</strong> 天井と床の分布を生成し、<strong>分離しているときも重なっているときも</strong>、
どの照合値もちょうど 1 つの判定になることを確かめる。

```
どの値も、通る・通らない・判定できない のちょうど 1 つに落ちる
```

<strong>片端だけで切る実装は、分離した瞬間に 2 つ成立して落ちる。</strong> 例で確かめると通って
しまう——分離した分布の例を書けば通り、重なった例を書いても通る。<strong>両方を跨いで初めて
捕まる形なので、性質試験でなければならない。</strong>

### 較正と評価が分離していること

```
天井と床を作った対が、1 つも較正に使われていない
```

<strong>相手集合の割りと、使った対の一覧を覗いて確かめる。</strong> 結果ではなく手続きを試験する——結果だけ見ても、分離
していない実装のほうが良い数字を出すので気付けない。

### 系統が欠けたら、抜いて合算しない

```
2 つ以上の系統が除外に掛かった文書は、照合値を持たない
1 つだけ欠けた文書は、基準の側へ寄せた値で埋めた照合値を持ち、埋めた系統を名指す
埋めた照合値が帯の中か床の側なら、判定できないを返す。通らないは返さない
```

抜いて合算する実装が通らないことを確かめる。3 行目は、埋めた値のせいで本人を
「通らない」と言わないことの試験である。

### 統計値から組み立てても同じになる

目盛りの材料は文書ごとの統計値だけである。統計値の経路が正しいことを確かめる。

| 確かめること | 通らなければ |
| --- | --- |
| 1 文書の統計値から組み立てた値と、その文書を直接測った値が一致する | 統計値が測った値を運べていない |
| 束ねた単位の値が、文書ごとの統計値の足し合わせと一致する | 束ね方が数え方とずれる |
| 束ねた単位の人らしさの窓が、文書の境目をまたがない | 別の文書の語が 1 つの窓に入る |
| 形代に書いて読み戻した統計値から組み立てた目盛りが、書く前のものと一致する | 保存した形代で検めた値が、測ったときと違う |
| 素材の本文を読めない状態で、`review` が動く | 検めが本文に頼っている |

### 3 段目の小さな外れ

```
幅の外れが 1/(n−1) 以下の指標は、3 段目を止めず、指摘にも出ない
幅が 0 の指標の外れは、必ずこの許しを越える
単位が 2 本に満たない指標は、許さない
```

### 自己検査は組み立てるたびに走る

```
本人の文書と基準の文書を入れ替えた組み合わせで組み立てると、
  review は判定できないを返し、理由に「本人を基準と見分けられない」が入る
  katashiro diff は見分けられないを返す
```

崩れていない組み合わせでは、自己検査の結果が出力に現れないことも確かめる。

## 判定

### 3 段の全分岐

<strong>[3 段](../spec/300-revise.md#種別を合わせて通るを出す)の分岐を網羅する。</strong> 表がそのまま
試験の一覧になる。

| 検査 | 基準との距離 | 照合値 | 前に出す指標 | 返る |
| --- | --- | --- | --- | --- |
| 線を超えた | — | — | — | 通らない |
| 通った | 基準の側 | — | — | 通らない |
| 通った | 判定できない | — | — | 判定できない |
| 通った | 本人の側 | 床側 | — | 通らない |
| 通った | 本人の側 | 帯の中 | — | 判定できない |
| 通った | 本人の側 | 天井側 | 1 本も無い | 判定できない |
| 通った | 本人の側 | 天井側 | 許す大きさを超えて幅の外あり | 判定できない |
| 通った | 本人の側 | 天井側 | 幅の外だが許す大きさの内 | 通る |
| 通った | 本人の側 | 天井側 | 全部幅の中 | 通る |
| 通った | 本人の側 | 天井側 | あるが、この草稿ではどれも測れない | 通る |
| 通った | 測れない | — | — | 判定できない |
| 通った | 本人の側 | 測れない（2 系統以上欠けた） | — | 判定できない |
| 通った | 本人の側 | 1 系統を埋めて天井側 | 全部幅の中 | 通る |
| 通った | 本人の側 | 1 系統を埋めて床側 | — | 判定できない |
| 通った | 測れない（草稿が短い） | — | — | 判定できない。理由は「短すぎて測れない」 |
| 組み立てられない | — | — | — | 判定できない |

<strong>「止めた理由」が返ることも、行ごとに確かめる。</strong>

4 列目が「指示できる指標」ではないことが要点である。[前に出す指標](../spec/300-revise.md#種別を合わせて通るを出す)、
つまり効くと判定されたものから層 3 と無効にしたものを除いた集合を使う。全部の指示できる
指標で止めると、<strong>言えない理由で「通る」を止める</strong>ことになり、軸に反する。

```
層 3 の指標が幅の外にあっても、判定は止まらない
本人が無効にした指標が幅の外にあっても、判定は止まらない
判定を止めた指標は、必ず指摘にも現れる
```

<strong>3 行目が、判定と指摘が同じ集合から取っていることの試験である。</strong>

### 指摘の順位

```
出てこないことの外れが、幅の外れと同じ尺度で並ぶ
出現割合 1.0 の指標が消えていれば、上位に来る
```

<strong>割合をそのまま並べると上限 1.0 で、幅の外れ（2.5 や 4.0）に永久に勝てない。</strong>
順位が静かに偏るだけなので、値の試験では出ない。

## 作り直せることを試験する

[素材を正本にする](../spec/200-extract.md#素材を正本にする)が本当かを確かめる。

```
調整した形代の stats/ を丸ごと消して katashiro build し直すと
  消す前と同じ統計値が出る
  調整は残る
stats/ の entry が壊れていても
  調整とペルソナは原本として読める
```

これが通らなければ、統計値のどこかに原本が混ざっているか、作り直しが調整を消している。
気付かないまま運用すると、測り直した瞬間に人が決めたことが消える。

実際に消して、実際に `katashiro build` する。古い統計値を控えておいて戻す形では、build を
1 度も呼ばずに通ってしまう。確かめたいのは作り直せることであって、控えが取れることでは
ない。

### 同梱の基準形代

```
baselines/ の文書から katashiro build した形代が、
  実行ファイルに埋め込んだ形代と同じバイト列になる
```

これが通らなければ、同梱の基準がどの文書から作られたかを言えない。`baselines/` を
直したのに埋め込んだほうを作り直し忘れると、ここで落ちる。

## 形代を壊さないこと

<strong>[書くときの手順](100-katashiro.md#書くときは壊さないことを優先する)は、失敗したときに
しか効かない。</strong> 普通に動かしているかぎり緑になるので、<strong>壊して確かめる。</strong>

| 何を起こすか | 何を確かめるか |
| --- | --- |
| <strong>rename の前</strong>で書き込みを落とす | <strong>元の形代が読める。</strong> 一時ファイルが残っていない |
| <strong>rename の後</strong>で書き込みを落とす | <strong>読める形代が 1 つある</strong>（新旧どちらでもよい） |
| entry を 1 つ壊す | <strong>置き換える前に断る</strong>（CRC・JSON・参照） |
| `manifest.json` を 2 つ持つ zip | <strong>壊れているとして断る</strong> |
| `manifest.json` を持たない zip | 同上 |
| 知らない `version` | <strong>知らない版として断る。</strong> 壊れているとは別の理由で返す |
| `tuning.json` が欠けた形代 | 壊れているとして断る。空で埋めない |
| `tuning.json` の `register` の知らない値 | 断る。捨てれば申告が黙って数えた結果に戻る |
| 中身のハッシュが `stats/` と合わない | 壊れているとして断る |
| <strong>場面を名乗らない形代</strong> | <strong>壊れているとして断る</strong> |
| 調整のサブコマンドのあとに `review` | 調整が効いた判定を返す。作り直しを求めない |
| 2 つの書き込みを同時に走らせる | <strong>片方が断られる。</strong> どちらの変更も消えない |
| 形代でないファイルへ `katashiro build` | 断る。消さない |
| 調整の在る形代へ `katashiro build` | 調整が残る。今の登録簿に無い指標の名前だけが知らせて捨てられる |
| 版の違う形代へ `katashiro build` | 断る。調整を引き継げないまま上書きしない |

下の 3 行が、この表でいちばん失うものが大きい。[調整は作り直せない](100-katashiro.md#何を収めるか)
ので、消してしまえば打ち直すしかない。

<strong>どれも、通らなければ原本が黙って消える種類の失敗である。</strong> 値が変わるまで誰も
気付かない。

## 検める草稿が目盛りに入らないこと

[クレートの境界は組み立て層では効かない](000-architecture.md#守られるのはクレートの中だけである)。
`kuchiyose` は組み立てにも検めにも依存するので、型では止まらない。

```
review の経路を端から端まで走らせると
  組み立ての関数がちょうど 1 度呼ばれ、それは草稿を読む前である
  組み立ての関数に渡るのは 2 つの形代の統計値だけである
  草稿を複数渡しても、組み立ては 1 度である
  違う草稿を渡しても、組み立てた目盛りは同じである
```

入出力だけを見る試験では書けない。組み立てを差し替えられる形で渡し、呼ばれた回数と
渡された値を記録する。分岐を全部通す。通る、通らない、判定できない、系統が欠けた、
指紋が合わない、組み立てられない。

これが[唯一、型で守られていない境界](000-architecture.md#守られるのはクレートの中だけである)である。
ほかは依存の向きが持つ。

## 本人の側に基準の文書が入らないこと

[跨げるのは 1 本だけである](000-architecture.md#場面を跨ぐ道は-1-本に絞る)。
欄で分けても、関数の中で混ぜてしまえば同じことになる。

```
基準の形代を別のものに替えても
  相手集合と測る分（本人の側の割り）は動かない
  本人の幅と出現割合は動かない
本人の形代を別のものに替えても
  基準の文書の選ばれ方は、文体と題材が同じなら動かない
```

動かないことと、動くべきものが動くことの両方を見る。基準を替えれば床と較正は動く。
前半だけなら「読まれていない」でも通り、後半だけなら「どこに効いたか」が言えない。

## 書かせる部分

LLM の出来は試験しない。試験するのは、道具が決めることが決めたとおりになっているかだけで
ある（[ペルソナが効いたかは本人が読んで決める](../spec/400-write.md#ペルソナが効いたかは本人が読んで決める)）。

```
同じ形代・基準・要約・保存先からは
  同じバイト列の代筆のプロンプトが出る
ペルソナを足しても外しても
  組み立てた目盛りと判定は変わらない
無効にした型・基準の型・基準の語は
  代筆のプロンプトに出ない
見出しが欠けた、または余計な見出しがあるペルソナは
  取り込まれず、名指しされる
記事に無い引用、短すぎる引用、無い単位を指す引用は
  解決しないと名指しされ、ペルソナは取り込まれる
統計値を作り直しても
  ペルソナは残る
ペルソナを下書きする道具は
  形代のあるディレクトリではなく、自分だけが入れる専用のディレクトリで走る
道具が下書きの代わりに symlink を置いても
  指した先は取り込まれない
katashiro persona --check は
  何も書かず、知らせの有無を終了コードで言う
```

2 つ目は、ペルソナが測る側に漏れていないことの試験である。型では
[`kuchiyose-prompt` から測る側への線が無い](000-architecture.md#kuchiyose-prompt)ことで守るが、
組み立て層で渡してしまう経路は型では止まらない。

表現を寄せる周回は、決まった版を決まった順に書く偽の道具で試験する。道具の定義に偽の
コマンドを渡せば、kuchiyose からは本物と区別が付かない。

```
偽の道具が悪くなった版を書くと
  その版は採られず、前の版が残る
良くなった版を書くと
  採られ、次の周はその版から直させる
良し悪しが同じ版を書くと
  採られない
測れない版（短すぎる、取り込めない）を書くと
  ほかの比べ方を見ずに捨てられる
通る版を書くと
  そこで止まる
何も書かないか 0 以外で終わると
  そこで止まり、それまでに採った版が残り、69 で終わる
上限の周回数に達すると
  止まる。捨てた周も数える
どの周でも
  目盛りの組み立ては周回の最初の 1 度だけである
元のファイルは
  上書きされない
```

[良くなった版だけを採る](../spec/400-write.md#良くなった版だけを採る)の比べ方は、
`kuchiyose-review` の中で、順ごとに差が付く組を作って全部の行を通す。

端末のつなぎ直しは、標準入力を閉じた状態で `write` を起動し、偽の道具に渡った標準入力が
端末であることを確かめる。端末の無い環境では `64` で断ることを確かめる。

## 実データが要るもの

<strong>合成データでは書けない試験がある。</strong> 別に置き、常には回さない。

| | 何を確かめるか |
| --- | --- |
| 自分を検査する | 本人の実際の文章が、[対ごとに見て](../spec/300-revise.md#端では見ない)生成文より高く出る |
| 書き手が変わっても本人を誤らない | LLM にペルソナを指定して作らせた書き手（敬体と常体を混ぜ、1 人あたり 20 本前後）で同じ 4 分割の検証を回し、本人を「通らない」と言わない |
| <strong>天井と床が分離するか</strong> | [いちばん危ない検査](../spec/010-strategy.md#それでも骨格を先に通す) |
| <strong>指摘どおりに直すと動くか</strong> | [検めを 2 周](../spec/300-revise.md#直したら測り直す) |

<strong>3 つとも、通らなければ設計が間違っている</strong>という種類の試験である。実装の誤りを探す
ものではない。<strong>骨格を通したときに 1 度、そのあとは素材が増えたときに回す。</strong>

> [!WARNING]
> <strong>「天井と床が分離するか」を緑にするために閾値を触らない。</strong> 分離しないという事実が
> 出ているなら、それが結果である。

## どう回すか

| いつ | 何を |
| --- | --- |
| 変更のたび | 決定性・名前・指紋・正規化・指標・目盛り・判定・組み立て層の境界・書かせる部分 |
| 骨格を通すとき | 上に加えて、作り直せること・同梱の基準形代・形代を壊さないこと |
| 素材が増えたとき | さらに、実データが要るもの |

<strong>形代を壊さない試験を毎回回さないのは、故障を注入するぶん遅いからである。</strong>
<strong>保存形式に手を入れたときは、変更のたびの側で回す。</strong>

<strong>速いものと遅いものを混ぜない。</strong>[1 周を安くする](../spec/010-strategy.md#使うときはループになる)
のと同じ理由で、毎回回す試験が遅ければ回さなくなる。

## 書き方

<strong>試験は「何を」を書く。</strong> どうやってはコードが、なぜはコミットが持つ。

<strong>名前は仕様の言葉で付ける。</strong> 実装の言葉で付けると、仕様が変わったときにどの試験を
直すべきかが分からなくなる。

失敗したときに、仕様のどこに反したかが読めるようにする。冒頭の表の行は、どれも仕様の
節に対応している。
