# 推論基盤を GPU から CPU へ移した話

機械学習モデルの推論基盤を GPU 環境から CPU 環境へ移行するプロジェクトに携わる機会がありました。当初は「推論に GPU は必須」という前提から出発したのですが、実際に手を動かしてみると、要件次第では CPU でも十分実用に耐えることが分かってきました。この記事では、その移行の過程で得た知見をまとめます。

## 移行を検討した背景

もともとのシステムは、学習済みのモデルを GPU インスタンス上でホストし、リアルタイムに近い形で推論リクエストを処理していました。サービスの成長に伴ってリクエスト数が増え、GPU インスタンスの台数も比例して増やす必要が出てきました。ここで問題になったのがコストです。GPU インスタンスは CPU インスタンスに比べて時間単価が数倍高く、しかも常時起動しておく必要があるワークロードだったため、月々の費用が無視できない規模になっていました。

一方で、対象となっていたモデルはそれほど大きくなく、バッチサイズも小さいまま運用されていました。GPU の並列演算能力をフルに活かせているかというと疑問があり、単に「速いから」という理由で GPU を選んでいた側面が大きいことに気づきました。そこで、レイテンシ要件を満たせる範囲で CPU 化できないかを検証することになりました。

## ONNX への変換

移行の第一歩は、モデルをフレームワーク依存の形式から ONNX 形式へ変換することでした。学習時のフレームワークが持つ独自の実行系のままでは、推論時の最適化余地が限られてしまいます。ONNX に変換することで、推論専用のランタイムに処理を任せられるようになり、CPU 向けの最適化を受けやすくなります。

変換自体は既存のエクスポート機能を使えば大きな手間ではありませんでしたが、実際に苦労したのは変換後の数値的な一致を確認する作業でした。演算子によっては変換前後で挙動が微妙に異なることがあり、出力の分布がずれていないかを個別に検証する必要がありました。特に正規化処理や条件分岐を含む層は要注意で、変換ツールが対応している演算子のバージョンを事前に確認しておくと手戻りが減ります。

ONNX 形式に統一しておくメリットは、実行環境を柔軟に選べる点にもあります。GPU 実行プロバイダと CPU 実行プロバイダを設定だけで切り替えられるため、今後また GPU に戻す判断をする場合にも、モデル自体を作り直す必要がありません。

## 量子化によるレイテンシ改善

CPU 上での推論速度を確保するうえで効果が大きかったのが量子化です。重みと活性化を 32 ビット浮動小数点から 8 ビット整数へ変換することで、演算量とメモリ帯域の使用量を大きく削減できます。CPU は GPU に比べて並列演算のスループットで劣る分、量子化によって演算そのものを軽くすることが特に効いてきます。

量子化には静的な手法と動的な手法があり、今回はキャリブレーション用のデータセットを用意できる状況だったため、静的量子化を選びました。動的量子化に比べて事前準備の手間はかかりますが、推論時に毎回スケールを計算する必要がない分、レイテンシの面で有利です。

量子化後は精度の劣化を必ず確認する必要があります。今回のケースでは、出力スコアの分布を量子化前後で比較し、実運用上の判定結果に影響が出ない範囲に収まっていることを確認してから本番投入しました。精度が許容範囲を超えて劣化する層があれば、その層だけ量子化の対象から外すという選択肢もあります。全体を一律に量子化するのではなく、影響の大きい層を見極めて部分的に適用する判断も重要でした。

## レイテンシとスループットの両立

CPU 移行で最も気を配ったのが、レイテンシとスループットのバランスです。GPU では大きなバッチをまとめて処理することで単位時間あたりの処理量を稼ぐ設計が一般的でしたが、CPU ではコア数やキャッシュ構造の特性上、同じ発想がそのまま通用しません。バッチサイズを大きくしすぎると、かえって一件あたりのレイテンシが伸びてしまう場面もありました。

そこで、スレッド数とバッチサイズの組み合わせを何パターンか試し、実際のリクエストパターンに近い条件で計測を行いました。物理コア数を超えてスレッドを割り当てても効果が頭打ちになる、あるいは逆に競合で遅くなることも観測されたため、コア数に対してスレッド数を過不足なく合わせる調整が必要でした。また、複数のリクエストを同時に処理する構成では、プロセス単位で推論セッションを分離するか、スレッド単位で共有するかによっても挙動が変わり、この点は環境ごとに実測しないと最適な設定が見えてきませんでした。

最終的には、レイテンシの目標値を満たしつつスループットを最大化できる設定を見つけることができ、量子化と実行時の設定調整を組み合わせることで、GPU 環境に匹敵する体感速度を CPU 上で実現できました。

## コスト面での効果

移行の主目的だったコストについては、狙い通りの効果が得られました。GPU インスタンスを CPU インスタンスに置き換えたことで、インスタンス単価そのものが下がったのに加え、CPU インスタンスは種類や台数の調整がしやすく、負荷に応じたスケーリングの選択肢も広がりました。GPU インスタンスは在庫や割り当ての制約で柔軟なスケーリングがしにくい場面があったのですが、CPU 環境に移してからはオートスケールの設定がシンプルになり、運用の手間も減りました。

もちろん、すべてのワークロードが CPU で置き換えられるわけではありません。バッチサイズが大きく、並列演算の恩恵を強く受けるようなモデルであれば、GPU の優位性は依然として大きいはずです。今回のケースでは、モデルの規模とリクエストパターンがたまたま CPU 向けの最適化と相性が良かったという面もあります。

## まとめ

推論基盤の GPU から CPU への移行は、単純な置き換えではなく、モデル形式の変換、量子化による軽量化、実行時パラメータの調整という複数の工程を積み重ねて初めて成立するものでした。ONNX への変換によって実行環境の選択肢を広げ、量子化でレイテンシを改善し、スレッド数やバッチサイズの調整でスループットを確保する。この一連の作業を経て、コストを大きく下げながら実用上問題のない推論性能を CPU 上で実現できました。GPU が唯一の選択肢だと決めつける前に、モデルの規模とリクエストパターンを見直してみる価値は十分にあると感じています。
