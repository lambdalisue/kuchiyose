クロスプラットフォームをやめた

Flutter で書いていたアプリを、iOS と Android のネイティブ実装に切り替えた。多くの現場ではまだクロスプラットフォームが合理的な選択だと思うが、少なくともこのアプリではそうではなかった、という記録を残しておく。

## 何を諦めたか

Flutter を選んだ動機は単純で、1 つのコードベースで両方の OS に出せることだった。実際、最初の数ヶ月はその恩恵をそのまま受け取れた。画面数が少ないうちは、ロジックも UI も一度書けば両方で動く。チームの人数も少なかったので、プラットフォームごとにコードを分ける余裕もなかった。

問題が表面化したのは、アプリが「それなりに普通のアプリ」から「その OS らしいアプリ」を求められる段階に入ってからだった。具体的には次のようなところで、Flutter のレンダリングエンジンが自前で描画する UI と、OS 標準の UI との間に埋めがたい差が出てきた。

- スクロールの物理特性や慣性、バウンスの挙動
- テキスト選択やコンテキストメニューの振る舞い
- キーボード表示時のレイアウト調整
- システムのアクセシビリティ設定への追従
- OS のアップデートで変わる標準コンポーネントの見た目

これらは個別に見れば小さな差だが、日常的にそのアプリを触るユーザーにとっては「なんとなく違和感がある」という形で積み重なっていく。ネイティブアプリに慣れたユーザーほど、この違和感に敏感だった。

## プラグインという緩衝材の限界

Flutter が OS 固有の機能にアクセスする方法はプラグイン経由になる。カメラ、通知、生体認証、共有シートといった機能は、Flutter 側のコードから見ると統一された API に見えるが、実体は iOS と Android それぞれのネイティブコードを呼び出すブリッジになっている。

このブリッジ層が、体感として最もコストのかかる部分だった。プラグインは OS のメジャーアップデートのたびに追従が必要で、更新が止まっているプラグインに当たると、フォークして自分たちで直すか、該当機能だけネイティブのプラットフォームチャンネルを自前で書くことになる。後者を選ぶ場面が増えるにつれて、「Flutter で書いているのに、実装の多くがネイティブコード」という状態に近づいていった。

さらに、プラグインが抽象化する API は最大公約数的にならざるを得ない。iOS と Android で権限モデルや UI ガイドラインが異なる機能ほど、プラグインの共通インターフェースはどちらの OS にとっても少しずつ不自然になる。結果として、プラグインのオプションをかいくぐるための条件分岐が Dart 側にも増え、コードベースは「共通化されているように見えて、実質は 2 つの実装を 1 つのファイルに同居させている」状態になっていた。

## 体験の差はユーザーにも見えていた

社内では「1 つのコードベースで両方に出せる」ことが効率の指標として重視されがちだが、ユーザーはコードベースの数を見ているわけではない。見ているのは、いつも使っている OS の標準的な振る舞いと、このアプリの振る舞いが一致しているかどうかだけだ。

レビューやサポートへの問い合わせを見返すと、機能不足を指摘する声よりも、「このアプリだけ変な動きをする」という違和感を指摘する声のほうが継続的に出ていた。個々の指摘は小さくても、プラットフォームごとの標準体験からのズレが積み重なった結果として現れているように見えた。これはクロスプラットフォーム層をいくら薄くしても、レンダリングエンジンそのものを OS 標準に置き換えない限り解消しにくい種類の問題だった。

## ネイティブに移行して変わったこと

iOS は Swift と UIKit・SwiftUI、Android は Kotlin と Jetpack Compose という構成に切り替えた。コードは重複する部分が増えたし、機能追加のたびに 2 回実装する手間も増えた。開発速度という単純な指標だけ見れば後退している。

一方で、スクロールやキーボード周りの違和感を報告する声はほぼ消えた。OS のアップデートにも、標準コンポーネントを使っている分だけ追従が早くなった。プラグインのメンテナンス状況に開発スケジュールが左右されることもなくなり、機能追加の見積もりが立てやすくなった。

コードの共有によって浮く工数と、体験の差によって失われる信頼とを、同じ天秤に乗せて比較する必要があった。今回のアプリの規模とユーザー層では、後者のコストのほうが見えにくく、じわじわと効いてくる種類のものだったというのが実感に近い。クロスプラットフォームが不利だったという一般論ではなく、体験の均質さがユーザー満足度に直結するアプリだったからこそ出た結論として書き残しておく。
