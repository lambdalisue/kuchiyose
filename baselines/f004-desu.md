# 画像配信を最適化した話

サイトの表示速度を見直す機会があり、画像配信まわりを一通り整理しました。テキストや JavaScript のチューニングはある程度やり尽くしていたのですが、実際に計測してみるとページ全体の転送量の大半を画像が占めていて、ここに手を入れるだけで体感速度が大きく変わることが分かりました。

## 現状把握から始める

最初にやったのは、どのページのどの画像が重いのかを洗い出すことです。闇雲に圧縮ツールを導入する前に、実際のアクセス解析とパフォーマンス計測ツールでボトルネックを特定しました。特に注目したのは LCP（Largest Contentful Paint）です。多くのページでファーストビューに大きなヒーロー画像を置いていたため、この画像の読み込み完了がそのままページ全体の体感速度を決めていました。LCP が遅い原因は主に三つで、画像のファイルサイズが大きいこと、画像の読み込み開始が遅いこと、そして配信元のサーバーが遠いことでした。この三つに対応する形で施策を組み立てていきました。

## 画像フォーマットの見直し

まず着手したのはフォーマットの変更です。これまで JPEG と PNG をそのまま配信していましたが、WebP に切り替えるだけで同じ見た目でファイルサイズを大きく削減できました。さらに対応ブラウザが増えてきた AVIF も採用し、より高い圧縮率を狙いました。ただし AVIF は非対応の環境も残っているため、picture 要素を使って AVIF、WebP、従来のフォーマットの順に候補を並べ、ブラウザが対応している形式を自動的に選んでもらう構成にしました。エンコード時間は AVIF の方が長くかかりますが、配信は静的ファイルなのでビルド時に変換しておけば実行時の負荷は増えません。

## 解像度ごとの出し分け

フォーマットと同じくらい効果が大きかったのが、画面サイズに応じた解像度の出し分けです。srcset と sizes 属性を使い、スマートフォン向けには小さい画像を、大きなディスプレイ向けには高解像度の画像を用意して、ブラウザが自分の表示条件に合わせて最適なものを選択できるようにしました。これまでは一律に大きな画像を配信していたため、モバイル環境では明らかに過剰な転送が発生していたことが分かりました。特に一覧ページのサムネイルのように点数が多い画像で効果が大きく、ページ全体の転送量が目に見えて減りました。

## 遅延読み込みとの兼ね合い

画面外の画像には遅延読み込みを適用し、初期表示に不要な読み込みを後回しにしました。ここで注意したのは、LCP の対象になり得るファーストビューの画像には遅延読み込みを適用しないことです。遅延読み込みは表示速度を改善する施策ですが、最も重要な画像にまで適用すると逆に LCP を悪化させてしまいます。ページごとにどの画像が最初に表示される主要な画像なのかを判断し、それ以外の画像だけに遅延読み込みを設定するという使い分けを徹底しました。

## CDN による配信の見直し

最後に配信経路そのものも見直しました。画像をオリジンサーバーから直接配信するのではなく、CDN 経由で配信するように変更し、利用者に近い拠点から画像を届けられるようにしました。CDN 側でフォーマット変換やリサイズをリクエストに応じて行える設定も活用し、アップロード時に複数サイズを作り込まなくても、必要なサイズと形式をその場で生成して配信できるようにしています。キャッシュが効くようになったことで二回目以降のアクセスも高速化され、サーバー側の負荷も下がりました。

## 振り返って

これらの施策を組み合わせた結果、主要ページの LCP は大きく改善し、体感速度も明らかに向上しました。個々の施策はどれも目新しいものではありませんが、フォーマット、解像度、読み込みタイミング、配信経路という異なるレイヤーの最適化を一つずつ積み重ねたことで、相乗効果が生まれたのだと思います。今後は動画コンテンツについても同じ考え方で配信を見直していきたいと考えています。
