# kuchiyose

kuchiyose は、書き手の記事から数えた統計値とペルソナ（形代）を使って、LLM に書かせる
ためのプロンプトを作り、書かれた文章が本人の書き方からどこでずれているかを数える CLI で
ある。kuchiyose 自身は LLM を呼ばない。書くのはあなた（Claude）で、kuchiyose は
プロンプトと検めを受け持つ。

詳しい使い方は <https://github.com/lambdalisue/kuchiyose/blob/main/docs/guide.md> にある。
分からないことは `kuchiyose <コマンド> --help` で確かめる。

## 始める前に

1. `kuchiyose --version` で入っているかを確かめる。無ければ `cargo install kuchiyose` を
   案内する（または GitHub Releases の実行ファイル）。勝手に入れない。
2. 形代が要る。`write`・`polish`・`review` は、`--katashiro` が無ければ既定の形代を使う。
   「既定の形代が無い」と言われたら、下の「形代を作る」に進む。

## やりたいことごとの手順

### 形代を作る

本人の記事（`.md` / `.markdown` / `.html` / `.htm`）を 1 つのフォルダに集めてもらう。
目安は 10 本以上、1 本あたり地の文で 1,000 字以上。技術記事と議事録のように書き方が違う
文章はフォルダを分ける。

```sh
kuchiyose build <フォルダ>
```

統計値を測り、LLM の道具（`claude` など）を対話なしで起動してペルソナを下書きさせ、既定の
形代にする。ペルソナの下書きは形代の隣の `<名前>.persona.md` に書かれる。本人に読んで
直してもらい、`kuchiyose katashiro persona <形代> <名前>.persona.md` で取り込み直す。
ペルソナは本人のものなので、あなたが勝手に書き換えない。

### 代筆する

`kuchiyose write` は道具を対話の画面で起動するため、Bash からは使えない。代わりに
`--print` でプロンプトだけを受け取り、あなたがそれに従って書く。

1. 何を書きたいか（題材、読み手、伝えたいこと、入れたい例）を本人から聞き、要約にする。
2. プロンプトを受け取る。保存先は既に在ってはならない。

   ```sh
   kuchiyose write --print -o <草稿.md> <<'EOF'
   <要約>
   EOF
   ```

3. プロンプトの指示（ペルソナ、文体の事実、内容の詰め方、保存先）に従い、本人と対話して
   内容を詰めてから草稿を保存する。プロンプトの指示は、このスキルの一般的な書き方より
   優先する。
4. 保存したら、下の「表現を寄せる」に進む。

### 表現を寄せる

```sh
kuchiyose polish <草稿.md>
```

kuchiyose が周回を回す。検めて、指摘された表現だけを道具に対話なしで直させ、良くなった版
だけを採り、通るか 4 周で止まる。元のファイルは上書きせず、最後に採った版を
`<名前>.polished.md` に、各周の版を `<名前>.kuchiyose/` に残す。数分かかることがあるので、
Bash のタイムアウトを長めに取るか、バックグラウンドで走らせる。

道具を起動できないとき（終了コード 69）や、本人があなたに直させたいときは、あなたが周回を
回す。

1. `kuchiyose polish <版> --print -o <次の版>` で直させるプロンプトを受け取り、それに従って
   指摘された表現だけを直し、次の版として保存する。内容は変えない。
2. `kuchiyose review <前の版> <次の版>` で並べ、良くなったかを見る。良くなっていなければ
   前の版に戻る。
3. 通るか、4 周で止める。元のファイルは上書きしない。

### 検めるだけ

```sh
kuchiyose review <草稿.md>            # 判定と指摘
kuchiyose review <版1.md> <版2.md>    # 1 本 1 行で並べ、近づいているかを見る
```

## 結果の読み方

判定は終了コードに出る。Bash が非 0 を失敗として扱っても、それは判定である。

| 終了コード | 判定 | 意味 |
| --- | --- | --- |
| 0 | 通る | 本人の書き方の範囲に入っている |
| 1 | 通らない | 基準（素の LLM）の側に落ちている |
| 2 | 判定できない | 短すぎる、素材が足りない、どちらとも言えない。失敗ではない |
| 64 以上 | — | 判定の前に止まった。エラーの文言に理由と次にすることがある |

- 出力の「ここから下は判定に使っていない」より上が判定を止めた理由とその直し方、下は参考の
  知らせである。知らせを直すかは本人が決める。
- 草稿は地の文で 1,000 字以上ないと測れない。
- 数字が揃っても内容までは測れない。最後の版と元の草稿の差分は本人に読んでもらう。

## 守ること

- AI が書いたことを隠すための道具ではない。検出器をすり抜ける目的では使わない。
- 本人の記事の本文やペルソナは私的な内容である。頼まれない限り外に出さない。形代を人に
  渡すときは `kuchiyose katashiro persona <形代> --remove` でペルソナを外せることを伝える。
- 形代の調整（`katashiro mute` など）やペルソナの取り込みは、本人に確かめてから行う。
